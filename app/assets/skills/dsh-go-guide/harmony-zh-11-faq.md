# 常见问题

## 发不出消息，或一直没有回复

先看对话列表底部的主机状态。

- **本机**：打开引擎页查看状态和**日志**。没装运行环境、引擎已停止、启动失败是不同情况，按页面提示处理。启动失败时，失败卡片里可以查看日志、导出诊断包。
- **远程主机**：远程主机页会按原因给出修复按钮，如**重新连接**、**重新登录**、**重新信任**。
- 模型没配好时，**选择模型**里会提示填写 API Key 或添加渠道。

重置和卸载会删除本机数据，排查时不必先用它们。

<!-- nav: commonSettings,phoneEngineDiagnostics -->
`设置 › 诊断` · [打开](dshgo://open/diagnostics)

反馈问题时，在这里导出诊断包，包含版本、设备、有限的引擎日志和已捕获的错误；不是全部系统日志或完整崩溃历史。App 会尝试移除 Key 和令牌，但分享前仍需自己检查。

想让 AI 直接帮你查：点 **让 AI 看诊断**，App 会把一份有限快照写给本机引擎，然后问 AI「看下诊断」——内置的 `dsh-go-support` 技能会按症状排查并给出可以直接粘贴的 issue 草稿。

## 切到后台后引擎被关掉，或收不到通知

<!-- nav: commonSettings,phoneEngineKeepAlive -->
`设置 › 后台运行` · [打开](dshgo://open/background)

离开屏幕后，系统很快会挂起应用：正在跑的对话可能还能跑一小会儿，多久由系统决定，之后跟着应用暂停，回到应用后会尽量接着跑。有的版本可以申请长时任务，让对话留在后台继续跑，通知栏会有一条提示；系统不批准或中途收回时同样会暂停。这一页写明这个版本是哪一种。

要一直跑，把应用留在屏幕上，或放到已连接的远程主机上跑。鸿蒙版没有关闭电池优化、锁定最近任务这类设置。

提醒要应用在运行才发得出，应用被挂起期间没有提醒；通知还要在 App 的**通知**里开启对应提醒，并在系统设置里允许 DSH Go 通知。本机的定时任务也只在应用运行时触发，应用被挂起时到点不会运行。

## 引擎反复启动失败

连续几次没有正常退出时，引擎不会自己启动，等你选。原因不明时可能是系统回收了应用或应用被关掉，也可能是引擎出了错。失败卡片上可以：

- **恢复配置**：回到上次正常运行时的插件和设置。引擎连续运行满两分钟才算一次正常；没有这样的记录，或配置没变时，不会出现这个按钮。只恢复配置，不回退引擎版本，也不动对话和定时任务。
- **进入安全模式**：用随包的默认配置启动，不加载你装的插件，对话都在。修好后点**恢复正常模式**。安全模式期间改的网页版设置不会保留。
- **重试**：按现在的配置再启动一次。

这次打开 App 已经启动过引擎时，恢复配置、进入和退出安全模式都要重新打开 App，确认框会写明。失败卡片里还可以查看日志、导出诊断包。重置和卸载会删除本机数据，排查时不必先用它们。

## App 能对话，headless 命令却报 MISSING_CREDENTIAL

`dsh --profile headless` 启动独立的一次性任务。默认配置不启用交互式凭据存储、授权和 DeepSeek 账号服务，因此不会自动使用 App 里保存的 API Key 或账号登录。App 能对话，不代表这条命令已经配好凭据。

默认的 DeepSeek 官方 API 路线需要 `DEEPSEEK_API_KEY`。在启动命令的进程环境中提供它，或在启动目录的 `.env`、`$DSH_HOME/.env` 中按 `DEEPSEEK_API_KEY=...` 的格式配置自己的 API Key。读取优先级依次为进程环境、启动目录的 `.env`、`$DSH_HOME/.env`；导出的空变量也会挡住 `.env` 回退，改用文件配置时先取消该空变量。不要把真实 Key 放进对话、问题反馈或提交到代码仓库。

如果 App 用的是 DeepSeek 账号登录，它和官方 API Key 是不同的凭据；账号登录令牌不能填进 `DEEPSEEK_API_KEY`。可以继续在 App 中使用账号，或为 headless 单独配置 API Key。

只叠加 App 的登录补丁不会启用 headless 默认关闭的服务。自定义 profile 或远程主机采用不同配置时，以那台主机的实际配置为准。

## 系统操作用不了

系统操作页顶部会写明现在的状态：

- **已开启，等本机引擎启动**：启动本机引擎。
- **已开启，回到 DSH Go 才能用**：系统不让后台应用做这些，回到 DSH Go。
- **已开启，暂时连不上，正在重试**：等一会儿。
- **这个版本用不了**：这个版本不支持系统操作。
- **当前连的是远程主机**：切回**本机**。

AI 说不支持：看屏幕、点按其他应用、读剪贴板、按名字找应用、短信都做不到。闹钟和计时器要这个版本开通了系统提醒。见 [系统操作](04-phone-control.md)。

## AI 说 gh、python3 或 pip 用不了

<!-- nav: commonSettings,linuxTitle -->
`设置 › Linux 环境`

这些命令在鸿蒙本机引擎上要靠 Linux 环境运行，见 [本机引擎与远程主机](03-engine-hosts.md#linux-环境)。看这一页的状态：

- **未开启**：打开**开启 Linux**。第一次要等准备完成，再让 AI 重试；准备期间这些命令仍会失败，不会排队等它。
- 页面写着本机引擎没在运行：先启动本机引擎。
- 页面要求完全退出并重新打开 App：照做后再开启。
- 写着原来的 Linux 数据没法继续用（常见于 App 更新之后）：点同一页的**重新安装 Linux**，再打开**开启 Linux**。Linux 里装过的东西会被删除，见 [本机引擎与远程主机](03-engine-hosts.md#linux-环境)。
- **出错了**，或写着没能开启加一段代码：反馈问题时把这段代码和诊断包一起附上。
- AI 说 Linux 忙：Linux 一次只跑一条命令，插件常驻的 Python 服务会一直占着它，期间别的命令等一会儿就报忙。关掉那个插件或稍后再试。
- 下载慢或连不上：在同一页的**网络代理**里设代理。

连着远程主机时，这些命令在那台主机上运行，和这里的开关无关。

## 宠物不见了

- 对话里看不到：宠物页选了**不显示**时，重新选一只；还在「藏起来 1 小时」里时，点**立即显示**。
- App 外看不到：鸿蒙版没有 App 外显示，宠物只在 App 里。

见 [宠物](06-pets.md)。

## 插件装好了，界面里看不到

先确认插件已启用，需要时重启引擎。插件的原生界面需要主机带有 dsh-go 桥接：本机引擎自带，远程主机一般没有。插件详情里也可能关掉了某个显示位置。没有原生界面的插件面板会出现在「全部功能」的插件分组里，在 App 内打开或以「网页版」入口打开。见 [插件](08-plugins.md)。
