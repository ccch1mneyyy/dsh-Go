# 管家（Router）

> 2026-11-08 起草，方向稿。owner 的设想：dsh-Go 变成一个 router，接入各种 IM 和 GitHub，替用户整理消息、汇报，把任务派给本地或云端电脑上的 worker；以后再接米家这类智能设备，用户只和这一个入口打交道。参照 DeepSeek Harness 团队 2026-10-31 的 Super-agent 设计稿和开源原型。接口细节等 §10 的 A0 调研之后再定。

## 0. 结论

- **不从零写 router。** 官方原型 `deepseek-ai/dsh-superagent-prototype`（MIT）本身就是一个 DSH bundle：router、worker 两个预设，和我们的桥接用同一套 `cordis.patch.yml`。dsh-Go 照 DS Bot 的做法（[dsbot.md](dsbot.md)）给它做原生客户端，再补上原型没有的手机一侧。
- **dsh-Go 有三个身份。** 管家的脸（用户只和它说话）；一台设备节点（读通知、手机操控、点米家 App）；装 worker 的主机之一（本机引擎）。
- **Router 推荐放在常开的机器上**（电脑、NAS、云机）。没有这种机器的人放手机本机引擎，代价是耗电。
- **外来消息怎么处理由用户选。** 别人发来的消息、邮件、issue 是直接派活，还是先变成「建议」进收件箱等用户点，用原型的接收模式（`off` / `observe` / `auto`）让用户定。安全相关的都是选项，不替用户加限制（§7）。
- **米家走 Home Assistant**：小米官方的 Xiaomi Home 集成加 HA 自带的 MCP Server，对引擎来说就是一组工具。没有 HA 时退到手机操控去点米家 App。
- **名字。** 界面叫「管家」，代码叫 `router`。它不是一种模式，而是垫在所有模式下面的一层（模式见 [roleplay.md](roleplay.md) §1）。

## 1. Super-agent 是什么

资料是设计稿的英译（中文原文还没对过）和原型的 README、docs 002 / 006 / 007。A0 调研要对着原文和代码核实。

| 部分 | 做什么 | 不做什么 |
|---|---|---|
| Router | 一个常驻会话，是全局的「顺序点、协调点和记忆」。只和人说话、派活。可以用较轻的模型 | 不执行代码，甚至可以没有 Bash 工具 |
| Worker | 一个任务一个，上下文隔离，有全套执行工具，通常用最强的模型；内部可以再开子代理 | 不直接和人说话，结论报给 Router |
| Watchdog | 按定时消息驱动的独立会话：处理接口错误、状态恢复失败，判断 worker 有没有在推进或跑偏；维护者可以通过它改提示词和触发规则 | — |
| 触发 | 群消息、邮件、日历提醒、代码评审意见、CI 结果都算触发 | 不是每条都送给模型 |
| 两道筛 | 第一道是代码：看来源、群范围、用户和机器人白名单，每个来源可设「只回应明确请求 / 当作候选 / 直接忽略」。第二道是模型：按写在提示词里的策略判断候选 | — |
| 找人 | 只在需要做决定或验收结果时通知；IM 回复不超过 100 字 | — |

**他们自己的模拟测试**（约 300 条消息、20 个工作请求，编码用耗时工具模拟，每组 5 次）：Super-agent 完成时间 p50 / p95 为 12.4 / 15.7 分钟；单会话加子代理工具是 20.4 / 29.5 分钟。缓存读取 token 多 2–4 倍。中性提示词下，单会话 agent 五次都没有主动派过活。Router 攒批：到达速度从每分钟约 1 条升到约 40 条时，平均每批从 1.0 条升到 2.8 条，每个决定摊到的推理时间从 6.4 秒降到 1.6 秒。

**原型实际做了什么：**

- TypeScript，要 Node 22.19+ 或 24+、git 2.32+、Python 3.8+、tmux、`gh` 2.48+，飞书要 `lark-cli`。装进单独的 `superagent` profile，钉在 `@deepseek-ai/dsh@0.2.1-rc.3`。
- 预设 `dsh-superagent-router`、`dsh-superagent-worker`。
- 来源：GitHub（Issue、PR、评论、默认分支 CI，各有一个默认关的 `observe*` 开关）和可选的飞书。
- 准入：每条消息分成明确请求、推断的候选、不接三档；有按范围的准入表、机器人名单，接收模式 `off` / `observe`（默认）/ `auto`。
- 接下一个候选时，原子地建 Ticket、Mandate（授权范围）、Assignment、Subscription 并回执；每个 Ticket 一个执行会话、一个目录（示例用 `git worktree`）。`waitsForPerson` 状态在有人回话前暂停自动工作。订阅线程里的消息只给上下文，不给新权限；人说停就撤回授权。
- 存储：一个 `orchestrator.sqlite`，目录锁；还没有删旧记录的逻辑。
- 面板：本机 `127.0.0.1` 的网页，只列需要人处理的事。
- 两个预设都以操作者的系统用户、`danger-full-access` 运行，文档自己说目录分开不是沙箱，建议用单独的系统账号。
- **没有的：** Watchdog 会话（只有每小时跑一次 `status`，退出码 1 时重启）、多机器、手机端、worker 之间通信。README 说代码和内部版本、和设计稿都有差别。

设计稿自己列的未解决问题：Router 分片、worker 之间通信、长期记忆、让用户看见工作进展、上下文边界、安全（云端循环被攻破就能碰到所有连着的设备；凭据要能用、但不进 agent 的上下文）。

## 2. 分工

```
手机 dsh-Go                       常开主机                               worker 和设备
├ 管家的脸 ⇄───────────────── Router 会话（轻模型，只沟通派活）
├ 通知读取（第一道筛）────────→ 第二道筛（攒批）←─ 官方接口连接器
├ 手机操控（手机上的 worker）←┐ 任务账本（授权范围、预算）──────────→ 本机 worktree / 别的电脑 / 云机
└ 米家 App（没有 HA 时）       └ Watchdog                               Home Assistant
```

原型缺的正好是 dsh-Go 已经有一半的东西：多主机和 Remote 扫码配对（#765、#766）、手机操控（13 个工具，确认规则已定）、通知（`chat_alerts`）、给 DSH 插件做原生客户端的做法（DS Bot）。

## 3. Router 放在哪

| | 常开的电脑 / NAS / 云机（推荐） | 手机本机引擎 |
|---|---|---|
| 一直在线 | 是，能收 GitHub、飞书的推送 | 前台服务保活已在真机验证，但关机、没网就停 |
| 读手机通知 | 经手机节点转过来（§4.2） | 直接 |
| 代价 | 要有一台机器 | 耗电和内存；第二道筛要攒更大的批 |
| 原型能不能跑 | Linux、macOS 可以；Windows 要 WSL（原型要 tmux） | 要在 PRoot 里装 Node 22、git、tmux、gh，A0 验证 |

一个用户只有一个 Router（设计稿的「全局顺序点」）。主机切换器里标出哪台主机跑着管家；装了两个时让用户选一个为主，另一个停用。

## 4. 消息怎么进来

### 4.1 来源

| 路子 | 能拿到 | 能不能回 | 做法 |
|---|---|---|---|
| 主机侧官方接口：GitHub、飞书、Telegram、邮件（IMAP）、企业微信机器人、QQ 官方机器人、钉钉 | 完整消息和历史 | 能，以机器人或用户授权的身份 | 首选。做在主机上，原型已有 GitHub 和飞书 |
| 手机读通知（`NotificationListenerService`） | 任何 App 通知里的文字，微信、QQ 也行；`MessagingStyle` 能给出最近几条；没有历史，折叠的「[3条]」拿不全；用户关了「通知显示消息详情」就什么都没有 | 只有通知带 `RemoteInput` 回复动作的 App 能回，多数国内 IM 没有 | 读哪些 App 用户自己勾（§4.2） |
| 手机操控读屏 | 能翻聊天记录 | 能，确认方式按手机操控的设置 | 慢；微信对自动化敏感。默认按吩咐用，常驻读屏做成选项 |
| 个人微信协议外挂（wechaty 一类） | 完整 | 能 | 有封号风险；不在第一批，做不做由 owner 定 |

### 4.2 第一道筛：在手机上

通知读取是新权限，App 现在没有。读哪些、怎么筛都由用户选：

- **读哪些 App**：用户自己勾。每个 App 三档，和设计稿一致：只听点名（私聊、@我、提到我设定的关键词）/ 当作候选 / 忽略。可以再按会话名细分（「家人群」候选，「广告群」忽略）。
- **可选的过滤**：不送验证码（「验证码」「校验码」「code」「OTP」附近的 4–8 位数字）、不送银行和支付类 App 的通知、不送图片和头像。Android 15 起系统本身就对第三方读通知的 App 隐藏验证码内容，这个开关管的是老系统。
- **攒批**：每隔几分钟或攒够若干条送一次；没连上 Router 时在手机上排队，有上限，超过就丢最旧的并记一笔。
- 通知读取的开关、每个 App 的档位、最近送出了什么，都在一页里能看到。

### 4.3 第二道筛：在 Router 上

模型按策略提示词逐批判断，每条给一个去向：忽略 / 记进汇总 / 建议一个任务 / 需要你看。策略是自然语言，用户可以在管家页改（「老板的消息都算需要我看」）。

### 4.4 汇总和回复

- **汇总**：定时（默认早 8 点、晚 9 点，可改）和随问（「今天群里有什么和我有关的」）。定时用 DSH 现成的自动化任务。
- **回复别人**：用户让管家回时，主机侧来源以机器人身份发；手机侧用通知的回复动作，没有就走手机操控。发之前要不要确认、能不能自动回，都是选项（手机操控本来就有「每次都询问 / 本任务免确认 / 始终免确认」三档）。

## 5. 派活

**任务**（对应原型的 Ticket）：目标、来源（用户的哪句话，或哪条建议被采纳）、授权范围、状态、worker 会话。

**授权范围**（Mandate）：哪台主机、哪个工作区、用哪个预设和哪些工具、能不能联网、能不能动手机、预算（token、时长）、截止时间。每一项用户都能留空表示不限；worker 想扩大范围时是先问还是直接扩，也由用户选。

**状态**：排队 / 进行中 / 等你（提问、审批）/ 待验收 / 完成 / 失败 / 撤回。

- **Worker 是普通 DSH 会话**，用 worker 预设开在选定的主机上。用户在 dsh-Go 里点开就是普通对话页，审批、提问、改动卡都复用。
- **选主机**：Router 维护主机清单——在线没有、系统、有哪些工作区和仓库、有没有 GPU、能不能操控手机。v1 只派到 Router 所在的主机（原型现成的 worktree），v2 再派到别处。
- **跨机器**：现在只有手机能连上各台主机（SSH、Remote 中继、局域网）。Router 在电脑 A、要派活给电脑 B，有三条路，A0 比较：(a) Router 也用 Remote 协议当客户端去连 B，用扫码配对给它一个设备身份；(b) 经手机转发——手机一睡就断，不推荐；(c) 每台机器跑一个小守护进程主动连 Router（设计稿说的 BYOM 设备守护进程）。倾向 (a) 或 (c)。
- **手机任务**：要用手机的活（操控 App、读屏）派给手机本机引擎上的 worker，沿用手机操控的设置。
- **Worker 之间不直接说话**，v1 都经 Router。

## 6. 米家和智能设备

- **首选 Home Assistant。** 用户在 NAS、电脑或树莓派上跑 HA，装小米官方的 Xiaomi Home 集成，再开 HA 的 MCP Server。引擎已经能经 `@deepseek-ai/dsh-mcp-client` 接 MCP（手机工具就是这么接的）；HA 官方的 MCP Server 走 HTTP（SSE），社区版还有 Streamable HTTP；`dsh-mcp-client` 能不能直接连、要不要套一层转 stdio 的代理，A0 验证。Xiaomi Home 集成会把小米账号信息明文存在 HA 的配置里，安装引导要写明。好处：几乎所有品牌都能管；HA 的长期令牌只在主机配置里，不进模型上下文。
- **没有 HA**：手机操控去点米家 App。慢，但不用配置。
- **要不要确认，用户按设备选。** 设置页按类型分好组，方便一次设一类：

| 类型 | 例子 |
|---|---|
| 只读 | 温湿度、门窗状态、电量 |
| 日常 | 灯、插座、窗帘、空调温度、扫地机 |
| 门锁、燃气和加热 | 门锁、燃气阀、烤箱、热水器 |

  每一类、每个设备都可以设「直接做 / 先问我」，定时任务和外来消息触发时可以单独设。默认都是直接做。

## 7. 安全选项

设计稿自己把安全列为没解决的问题：一个能读所有消息、能指挥所有电脑和家电的管家，可能被一条消息骗。App 不替用户加限制，下面这些都在管家设置里一页摆出来，用户自己选：

| 选项 | 防的是什么 |
|---|---|
| 外来消息的接收模式（`off` / `observe` / `auto`，原型默认 `observe`） | 别人的消息、邮件、issue 直接让管家动手。用户也可以立长期规则（「CI 挂了就开个 worker 看看」） |
| 授权范围的到期时间 | 很久以前的任务还拿着权限 |
| 发送、支付、删除前确认 | 管家替用户对外发东西、花钱、删东西。沿用手机操控的三档 |
| 设备确认（§6） | 门锁、燃气这类被误开 |
| 每日 token 预算 | Super-agent 的 token 是单会话的 2–4 倍；超了就停下等用户 |
| worker 放进单独的系统账号或容器 | 原型以操作者账号 `danger-full-access` 运行；A0 看能不能做，安装引导里给出选项 |

不算限制、照做的两件：

- **「全部停下」和「管家做过的事」**：手机上一个键停掉所有任务；做过的事一页列出，每条带来源和授权范围。
- **凭据放在主机配置里**：GitHub、飞书、HA 的令牌在主机配置或连接器里，模型只看到工具。这只是放的位置，不影响能做什么。

## 8. 界面（主线做）

- **管家页**：最上面是今天的汇总卡；然后是「待你处理」（审批、回答、验收，一张卡一件事）；再下面是进行中的任务条（主机标识、状态、用时、花费）；最底下输入条（语音、附件）。
- **任务详情**：来源、授权范围、时间线、打开 worker 对话、停下、验收。
- **通知**：只发需要用户的事和定时汇总；按任务分组，别处处理了就撤回（复用现有通知）。
- **入口**：生活模式的首页就是管家页；工作模式在抽屉顶部常驻一行「管家」；伙伴模式由她当脸（§9）。分享进来、桌面快捷方式、快速设置磁贴、语音都能直达管家。

## 9. 和已有东西的关系

- **DS Bot**：主 Bot「Chief」有点像 Router，但它是人格加团队聊天，没有任务隔离和授权范围。保持原样；以后 Chief 可以当管家的一张脸。
- **伙伴**：可以当管家的脸。事实由 Router 结构化给出、卡片原样显示，她只负责那一句话的口吻；现在「『整理照片』那边跑完啦」加「去看看」胶囊就是这个形状。酒馆角色默认只聊天，用户可以让某个角色走完整模式接上管家（[roleplay.md](roleplay.md) §7）。
- **手机操控线**（phone1、phone2）：工具、确认、多任务并发上限都复用。
- **Remote 扫码配对**（#766）：跨机器派活的设备身份可以从这里长出来。
- **自动化任务**：定时汇总、长期规则的定时部分用它。

## 10. 阶段

| 阶段 | 内容 | 后端（Pro） | 界面（主线） |
|---|---|---|---|
| A0 | 调研 | 原型能不能在 0.2.2-rc.1 上跑、能不能在手机 PRoot 里跑；它的接口（面板背后的 HTTP）够不够做原生客户端；和 DS Bot 重叠多少；跟上游还是维护分支；跨机器三条路的比较；HA MCP 怎么接；国内 IM 官方接口哪些能用 | — |
| A1 | 单机管家 | 原型的客户端协议、安装和更新（照 DS Bot 的「安装 / 更新」） | 管家页、待你处理、任务条、任务详情、汇总、通知 |
| A2 | 手机节点 | 通知读取和第一道筛、手机任务派回手机 | 逐个 App 授权页、「最近送出了什么」 |
| A3 | 多机器 | 主机清单、跨机器派活、设备身份 | 任务里的主机标识、选主机 |
| A4 | 智能设备 | HA MCP 接入、米家 App 退路 | 设备卡片、按设备的确认选项 |

## 11. 待定

- 原型的接口稳不稳定，上游收不收我们的补丁（手机来源、移动端接口）。跟上游还是维护自己的分支，A0 之后定。
- 引擎版本：原型钉 0.2.1-rc.3，我们是 0.2.2-rc.1。
- 费用：Router 默认用 `deepseek-flash`，worker 用强模型；每日预算的默认值。
- 飞书之外，企业微信机器人、QQ 官方机器人、钉钉对个人用户开不开放、要不要企业资质。
