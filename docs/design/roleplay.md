# 酒馆

> 2026-11-08 起草，2026-11-09 扩成完整方案。owner 定的：正则和 HTML 要兼容；不审查，卡由用户自己提供；出于安全考虑的措施都做成默认关的开关；在兼容的基础上，用 agent 做一个更有趣、更好看、互动更丰富的酒馆。
>
> 这一份是总纲，细节分三册：[兼容](roleplay-compat.md)、[agent 玩法](roleplay-agent.md)、[界面](roleplay-ui.md)，另有一份[优化排期](roleplay-roadmap.md)。伙伴小屋见 [companion.md](companion.md) 和 [companion-daily.md](companion-daily.md)，管家见 [router.md](router.md)。

## 0. 结论

- **两层。** 兼容层照 SillyTavern（下称 ST）跑：角色卡、世界书、预设、正则、酒馆助手脚本拿来就能用，结果和 ST 逐项对拍。增强层是我们自己的：状态、导演、记忆、组件、群像、做卡助手，按对话开关，老卡也能用上。
- **不另起卡格式。** 新能力写进卡的 `extensions.dshgo`。导出回 ST 照样能玩，增强的部分退化成普通文字。
- **事实归规则层，文字归模型。** 数值、背包、骰子、谁知道什么、真相是什么，由 App 里的确定性代码管；模型负责把故事讲好。酒馆最常见的几个毛病——状态栏被写坏、骰子乱编、角色说漏嘴——都出在让模型同时管这两件事。
- **一回合只等一次模型。** 导演、整理状态、写摘要这些额外的活，都放在你读和打字的时候在后台做，不加等待。
- **整个酒馆在手机上跑。** 不起引擎、不连主机，有 DeepSeek Key 就能玩全部。只有做卡助手要抓网页、批量改文件时，可以借主机。
- **默认和 ST 一样自由。** 不审查内容，卡里的脚本照常跑；保护措施都是默认关的开关（compat §9）。
- **核心是一个纯 Dart 包** `packages/dsh_tavern`，界面接在上面；对话存在 SQLite 里。

## 1. 给谁、解决什么

**给谁**

- 在电脑上玩 ST、想在手机上接着玩的人；现在用 Termux 或远程在手机上跑 ST 的人。
- DSH Go 现在的用户：已经有 DeepSeek Key，觉得伙伴小屋还不够玩。
- 想要「更像游戏」的角色扮演的人：有状态、有目标、有悬念、有结局。

**现在在手机上玩酒馆的毛病，和我们的做法**

| 毛病 | 我们 |
|---|---|
| ST 要自己部署，界面是给电脑做的 | 原生 App，单手竖屏，导入卡就能玩 |
| 状态栏常被模型写坏：漏一行、格式错、数字乱跳 | 状态是真数据，模型调工具改，规则层校验，面板由 App 画（agent §2） |
| 长剧情忘事；摘要、向量库要自己配 | 自动前情提要和记忆书，导演提前把要用的设定挑出来（agent §5） |
| 群聊串台，每个角色都什么都知道 | 群像：每个角色只看到自己在场时发生的事（agent §4） |
| 剧情全靠自己推 | 导演在后台埋伏笔、控节奏、给建议回复（agent §3） |
| 做卡要会正则、HTML、JS | 做卡助手：说想要什么，它来写、来调（agent §9） |
| 前端卡在手机上又卡又挤 | 一块画布装下整段对话，前端块懒加载、滚出屏幕就卸掉（ui §3） |

**同类**（2026-11 调研）：手机上已经有几家在做「兼容 ST 的数据 + 原生界面」——TauriTavern（把 ST 前端搬到 Android / iOS，AGPL-3.0）、Tavo（闭源，iOS）、ChatterUI（AGPL-3.0）；RisuAI 自带记忆和模块，手机网页体验好。没有一家在做导演、状态工具和知识隔离。电脑上最接近我们增强层的是 Talemate（多个 agent 分工、导演、世界状态，AGPL-3.0），但它是给本地大模型和电脑用的。国内的陪伴 App（星野、猫箱等）有养成和收藏，但卡是平台的、不能导入，也被批评模板化和付费点脱离剧情。

## 2. 原则

1. **兼容第一。** 导进来的东西照 ST 的规则跑；拿不准时以 ST 的源码和对拍结果为准，不自己发明。
2. **增强不改卡。** 增强层对老卡也生效；关掉就是原汁原味的 ST。
3. **数据进出无损。** 不认识的字段原样保留、原样导出。
4. **事实归规则层，文字归模型**（§0）。
5. **一回合只等一次模型**（§0）。
6. **花多少看得见。** 每回合用了多少 token、命中多少缓存、大约多少钱，检视页都有；后台的 agent 各自记账。
7. **默认不限制，保护是开关。**
8. **数据在这台手机上**，能整体导出备份；Key 在安全存储里。

## 3. 两层

```
┌─ 增强层（DSH 自己的，按对话开关）──────────────────────────────────┐
│ 状态和规则 · 工具 · 组件 · 导演 · 群像 · 记忆 · 异步剧情 · 做卡助手  │
└──────────────────────────────────────────────────────────────────┘
┌─ 兼容层（照 ST）───────────────────────────────────────────────────┐
│ 角色卡 · 世界书 · 预设和提示词组装 · 宏 · 正则 · 显示流水线          │
│ · 酒馆助手接口 · MVU · 斜杠命令 · 快速回复 · 聊天记录                │
└──────────────────────────────────────────────────────────────────┘
```

同一张卡在三种情况下：

| | 老卡，经典 | 老卡，增强 | DSH 卡（带 `extensions.dshgo`），增强 |
|---|---|---|---|
| 提示词 | 和 ST 一字不差 | ST 那份，加上导演提示和记忆 | 同左，加上卡里的剧本和状态说明 |
| 状态 | 卡自己的（变量、MVU、正则状态栏） | 卡自己的，再加一个自动整理的状态面板 | 卡定义的状态，规则层管 |
| 回合后 | 无 | 整理状态、导演、摘要 | 同左，导演按卡里的剧本走 |
| 导出回 ST | 原样 | 原样（增强层的东西存在对话里，不进卡） | 能玩；状态和组件退化成文字 |

## 4. 架构

```
App（Flutter，主线）
├─ 外壳：首页、角色页、对话页的顶栏和输入条、抽屉、编辑器、设置
├─ 对话画布：一个 WebView，装消息列表、显示流水线、前端块、组件
│           （画布里的逻辑交给 Pro，样式和动效主线做）
├─ 舞台：立绘、Live2D、背景、视觉小说对话框（复用伙伴的舞台）
└─ 接线：Riverpod 状态、画布桥、通知、分享导入

packages/dsh_tavern（纯 Dart，不依赖 Flutter，Pro）
├─ io      卡（PNG / JSON / CHARX）、世界书、预设、正则、ST 聊天记录的读写
├─ store   资料库（文件）、对话库（SQLite）
├─ prompt  预设 → 消息数组（ST PromptManager 的规则）、世界书引擎、宏、提示词侧正则
├─ turn    回合引擎：调模型、流式、标记解析、工具、写回正则、提交状态
├─ state   状态文档、操作、规则、快照；酒馆助手的五种变量
├─ agents  整理者、导演、群像调度、摘要和记忆、异步剧情、做卡助手
├─ llm     DeepSeek（OpenAI 格式）、任意 OpenAI 兼容接口、完整模式（主机会话）
└─ script  酒馆助手接口在 Dart 一侧的实现（画布里的 JS 调过来）
```

- 纯 Dart 的部分都能在电脑上跑测试，用夹具和 ST 对拍。
- 新依赖只有 `sqlite3` 和 `sqlite3_flutter_libs`（MIT）。别的复用 App 已有的：`archive`、`image`、`http`、`yaml`、`crypto`。

## 5. 数据

### 5.1 资料库（文件）

放在 `<应用支持目录>/tavern/`，都存 ST 的原格式，导出就是复制：

| 位置 | 内容 |
|---|---|
| `characters/<id>/` | `card.json`（V3）、卡面、`assets/`、导入时的原文件 |
| `lorebooks/<id>.json` | 独立世界书 |
| `presets/<id>.json` | 对话补全预设 |
| `regex/global.json` | 全局正则 |
| `personas/<id>/` | 用户人设：名字、描述、头像 |
| `quickreplies/<id>.json` | 快速回复组 |

我们自己的东西放在各自的 `extensions.dshgo` 里。

### 5.2 对话（SQLite）

一个库 `tavern.db`：

| 表 | 存什么 |
|---|---|
| `chats` | 角色或群、人设、预设、绑定的世界书、作者注释、增强开关、排版、当前叶子节点、对话变量 |
| `nodes` | 一条消息：父节点、说话人、角色（用户 / 角色 / 旁白 / 系统）、正文、思考、时间、模型和用量、`extra`（ST 的 `extra` 原样，加 `dshgo`） |
| `node_states` | 状态：每个节点一份增量（JSON Patch），每隔 20 个节点存一份全量 |
| `summaries` | 前情提要：覆盖哪段节点、正文、是否手改过 |
| `memories` | 记忆书条目（世界书条目的格式） |
| `agent_runs` | 后台 agent 每次跑了什么、用了多少 token、产出了什么 |
| `nodes_fts` | 全文搜索 |

- **消息树。** 备选回答就是同一个父节点下的兄弟节点，分支也一样。所以「左右滑换一个回答」就是换到兄弟节点；哪一条都能滑、都能从那里分叉，不用像 ST 那样另存一个对话文件。每个节点记着当前走哪个孩子，从根走到当前叶子就是「这条路」。
- **状态跟着节点走。** 换回答、切分支、删消息、重写时，状态自动回到那个节点的样子。酒馆助手「每条消息、每个备选回答各一份变量」正好对得上。
- **和 ST 互通。** ST 的 `.jsonl` 聊天记录双向转换（compat §7）：这条路展开成消息列表，兄弟节点进 `swipes`；导入时反过来。

### 5.3 一段对话能设什么

角色或群、人设、预设（默认跟全局）、绑定的世界书、作者注释、增强开关（经典 / 增强）、群聊发言方式（agent §4）、排版（ui §4）、主模型和帮手模型。

## 6. 一个回合

**经典**（和 ST 一样）：

1. 你发的话过「用户输入」正则；以 `/` 开头的走斜杠命令。
2. 按 ST 的事件名发生成事件，给酒馆助手脚本。
3. 组装提示词：预设、卡、世界书扫描、宏、提示词侧正则。
4. 调模型，流式显示。
5. 收完后过「AI 输出」正则写回，存节点；按 ST 的事件名发「收到消息」，MVU 这类脚本在画布里自己更新变量。

**增强多出来的：**

- 第 3 步多放几样：导演上一轮留下的提示（不给你看）、导演挑好的设定、记忆书命中的条目、状态摘要。
- 第 4 步：正文里的标记（表情、动作、换场景、组件）边流边解析，舞台和画布同步变化。思考关着时，模型可以在回复末尾调工具改状态，App 直接提交，不用把结果再发回去，所以还是一次调用；只有要掷骰时多一次（掷完接着讲）。
- 第 5 步以后，后台并行三件事：
  - **整理者**：思考开着、或者卡没定义状态时，用帮手模型读这一轮的正文，提出状态变化。
  - **导演**：更新剧情笔记，留下一拍的提示、要预取的设定、三个建议回复。
  - **摘要**：快超出预算时，把更早的部分滚动摘要。

  你读完、打字的时候它们一般已经做完了。你抢先发出下一句时，没做完的就用上一轮的结果，不等。

## 7. 模型和花费

- **接口。** DeepSeek 走 OpenAI 格式的 `/beta/chat/completions`，和 ST 的 DeepSeek 源一模一样：同样的地址，同样的后处理（同角色合并、中间的 system 改成 user、名字写进正文），「接着写」同样用前缀续写（最后一条 assistant 消息带 `prefix: true`）。大家的预设都是在 ST 的这条路上调出来的，所以照它做才对得上（compat §3.4）。另外支持任意 OpenAI 兼容接口。伙伴的轻量模式仍走 Anthropic 格式，两边互不影响。
- **两个模型槽。** 主模型讲故事：默认 `deepseek-flash`，可换 `deepseek-v4-pro`。帮手模型给导演、整理者、摘要、群像里的配角用：默认 `deepseek-flash`，关思考。
- **价格**（2026-11 DeepSeek 官网，美元 / 百万 token，高峰时段）：flash 输入命中 0.006、未命中 0.30、输出 1.20；v4-pro 分别是 0.044、1.32、3.96。工作日北京时间 9–12 点、14–18 点是高峰，其余时间半价。
- **估算**：一回合提示词 16k、九成命中缓存、输出 800。

| | 主模型 flash | 主模型 v4-pro |
|---|---|---|
| 经典，一回合 | 约 0.0015 美元（1 分钱左右） | 约 0.006 美元（4 分钱左右） |
| 增强：加导演 | 约 +0.0009 美元 | 同左（帮手默认 flash） |
| 增强：加整理者（需要时） | 约 +0.0008 美元 | 同左 |
| 群像：每多一个开口的配角 | 约 +0.0015 美元 | 同左 |

  经典一百回合约一块钱，增强约两块。前提是缓存命中：命中价是未命中的五十分之一，ST 默认把世界书放在角色设定前面，命中的条目一变，后面全部按未命中算，一回合能贵几十倍。所以检视页会标出打碎缓存的段落，并提供一个「省钱排序」开关（compat §3.5）。

## 8. 和伙伴、管家的关系

- 伙伴和酒馆共用 `dsh_tavern` 的卡、世界书、记忆书。伙伴 = 一个长期角色 + Live2D 小屋的外壳；任何卡都能请进小屋，伙伴也能导出成一张卡。
- 伙伴的亲近度是状态系统的一个特例，规则写在伙伴卡的 `extensions.dshgo.bond` 里。
- [companion-daily.md](companion-daily.md) 的定时通知，酒馆的异步剧情也用（agent §8）。
- 管家不进酒馆：酒馆里的角色默认碰不到你的 IM 和设备。哪个角色想接管家、用主机的工具，由你在角色设置里打开（走完整模式）。

## 9. 阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| R0 | 对拍台：让 ST 连一个只录请求的假接口，录下它发出去的提示词；显示流水线放进 jsdom 跑；一批自制的测试卡、预设、世界书 | 一条命令录出一组夹具 |
| R1 | 底座：读写、资料库、对话库、消息树、预设组装、世界书全量、常用宏、DeepSeek 和 OpenAI 兼容接口；酒馆首页、角色页、对话页（画布先只有 Markdown）、检视页 | 20 组夹具的提示词和 ST 逐字一致 |
| R2 | 美化：正则、显示流水线（移植 ST）、作者注释、人设、视觉小说排版、表情图 | 夹具的显示结果一致；热门真卡肉眼看一致 |
| R3 | 脚本：酒馆助手接口、前端块、嵌入脚本、MVU、斜杠命令子集、快速回复、经典群聊 | 一批常见的前端卡和 MVU 卡能玩 |
| R4 | 增强一：状态和规则、原生状态面板、工具、整理者、组件、骰子 | 换回答、切分支时状态正确回退 |
| R5 | 增强二：导演、建议回复、记忆和摘要、群像、异步剧情 | 悬疑样卡里配角不说漏 |
| R6 | 做卡助手、DSH 卡导出、和伙伴打通（请进小屋、记忆书） | 一张老卡一键升级成 DSH 卡 |

分工照老规矩：界面和动效主线做，`dsh_tavern`、画布逻辑和协议交给 Pro。
