# 酒馆：界面

> 总纲见 [roleplay.md](roleplay.md)。界面和动效归主线。外壳的气质照 [polish-guide.md](polish-guide.md)；画布和舞台里允许卡的主题盖过 App 的配色（§10），外壳始终是 App 自己的样子。

## 0. 结论

- **外壳原生，消息按卡的需要分三级渲染**（2026-11-10 定，见 [roleplay-roadmap.md](roleplay-roadmap.md) §1）：纯文本卡用原生 Markdown；带 HTML 的那几条消息各嵌一个沙箱 WebView（岛屿）；带脚本、要酒馆助手的卡才用下面 §3 的整页画布。顶栏、输入区、抽屉、编辑器始终是 Flutter。
- **三种排版**：气泡、小说、视觉小说，每段对话自己选（§4）。
- **组件分两种**：跟着消息走的（信件、物品、线索、剧中手机消息、插图、小游戏）在画布里；跟着对话走的（建议回复、状态面板、背包、地图、分支树）在外壳里（§5）。
- **消息操作像 ST，但更顺手**：哪一条都能左右滑换回答、从那里分叉；下拉打开分支树，看整段故事走过的岔路（§7）。
- **卡可以换主题**：颜色、字体、背景、气泡样式只作用在画布和舞台（§10）。

## 1. 页面

| 页面 | 是什么 |
|---|---|
| 酒馆首页 | 四个板块：书架、对话、资源库、我的（2026-11-10 定，见 [roleplay-roadmap.md](roleplay-roadmap.md) §4）。书架顶部「继续」：最近的对话，横向卡片，带角色图和最后一句。下面是角色网格（两列、卡面 2:3），能搜、按标签筛、排序 |
| 角色页 | 卡面大图（从网格里的卡片展开过来，`CardOrigin`）、名字、作者、标签；开场白左右滑着挑，挑中就「开始」；这个角色的对话列表；作者说明（常带 HTML，在画布里渲染）；设定详情折叠；编辑、导出、请进小屋 |
| 对话页 | §2 |
| 资料库 | 世界书、预设、正则、人设、快速回复、主题，各一个列表 |
| 编辑器 | 角色、世界书、预设、正则、人设各一个（§9） |
| 检视页 | 这一回合实际发了什么、花了多少（§9） |
| 酒馆设置 | 接口和模型、增强、显示、保护开关（compat §9）、数据（导出、备份） |

**导入**：选文件；系统分享进来（PNG、JSON、CHARX、ST 导出的 zip）；粘贴卡站的链接，App 下载那张卡。导入后直接打开角色页。

**空状态**：一张图 + 「导入第一张卡」+ 一个按钮；下面放一张 App 自带的示范卡（我们自己写的，用来展示增强玩法）。

## 2. 对话页

从下往上四层：

1. **舞台**（画布的底层）：背景、立绘或 Live2D、天气和光影。排版是视觉小说时才有立绘；另外两种排版只有背景（可以关）。
2. **消息**（画布）：消息列表、前端块、跟着消息走的组件。背景透明，透出舞台。
3. **外壳**：顶栏（44，玻璃）、输入区、输入区上方的一排胶囊（建议回复、快速回复、脚本按钮、骰子）。
4. **抽屉和弹层**：状态面板、背包、地图、线索本、剧中手机、分支树、导演笔记、世界书、记忆、检视。

**顶栏**：左边返回；中间角色名（群聊是一排小头像），下面一行小字放卡钉住的一两个状态（「第三天 · 黄昏 · 酒馆」）；右边状态面板按钮和菜单。点角色名打开角色速览（设定、换人设、换排版）。

## 3. 对话画布

> 这一节是渲染的第 2 级（整页画布），只给带脚本、要酒馆助手、样式跨消息的卡用；第 1 级是单条消息的沙箱 WebView（岛屿），先做。分级见 [roleplay-roadmap.md](roleplay-roadmap.md) §1。

- **加载**：照伙伴舞台的做法，App 里起一个只听 `127.0.0.1` 的小服务器，路径带随机令牌（同 `companion_server.dart`）；页面、常用库、卡的资源都从它给。JS channel 叫 `DshTavern`，App 到画布是 `canvas.command(<json>)`。
- **结构**：DOM 照 ST 的消息结构搭（`#chat > .mes[mesid] > .mes_block > .mes_text`），卡里写给 ST 的 CSS 和选择器大多能直接生效（compat §6）。
- **只画看得见的**：长对话只把视口附近的消息放进 DOM，往上翻再补。前端块只在最近若干条里跑（同酒馆助手的「渲染深度」），滚出屏幕的 iframe 卸掉，滚回来再建。
- **流式**：最后一条每 50 毫秒重排一次（显示正则和 Markdown 整条重跑，和 ST 一样）；前端块等这条收完再建，不在流式里反复重建。
- **渲染进程**：App 里所有 WebView 共用一个渲染进程，重的前端卡可能把它撑崩。画布接上 `web_view_guard`：崩了就重载画布、回到原来的位置，提示一句「画面重新加载了」。
- **选字和长按**：画布里长按消息，把位置告诉 Flutter，弹原生的消息菜单（§7）；选字用系统的。
- **深浅色**：App 的颜色以 CSS 变量（`--dsh-*`）传进画布，卡的主题可以盖过（§10）。系统字号经 WebView 的文字缩放跟上。
- **性能目标**：中档手机上，两千条的对话打开到最新一条 < 0.5 秒，滑动 60 帧。

## 4. 排版

| 排版 | 样子 | 适合 |
|---|---|---|
| 气泡 | 头像 + 气泡，你在右、角色在左 | 日常聊天、群聊 |
| 小说 | 全宽正文，说话人是一行小标题，没有气泡，段距大 | 长文、讲究文风的卡 |
| 视觉小说 | 背景 + 立绘 + 底部对话框；点一下出下一句，上滑看记录 | 带立绘、表情图的卡 |

**视觉小说的细节**

- 对话框是玻璃，名字牌用角色的颜色。文字逐字出现，速度可调；有自动播放、跳过、记录（像伙伴小屋那样的 galgame 记录页）。
- 一条回复按段切成几页；前端块和组件单独占一页。
- 立绘按说话人数量站位（一人居中，两人左右，三人左中右），说话的人亮、别人暗一点；换表情交叉淡变 200 毫秒。
- 表情来自正文里的标记（agent §6.1）；没有标记的老卡，按 V3 `assets` 里 `emotion` 资源的名字匹配情绪词兜底。
- 角色有 Live2D 包时用 Live2D（复用伙伴舞台的 `stage.js`，放进画布的舞台层），没有就用表情图，再没有就用卡面。

每段对话自己选排版；默认用卡里写的（`extensions.dshgo.theme.layout`），没写就是气泡。

## 5. 组件

模型怎么放组件见 agent §6。这里只管长什么样。

**跟着消息走**（画布里，Web Components，标签 `<dsh-*>`）

| 组件 | 样子 | 能点吗 | 在 ST 里退化成 |
|---|---|---|---|
| 信件 `<dsh-letter>` | 信纸、署名、日期，展开读全文 | 展开 | 普通引用段 |
| 物品 `<dsh-item>` | 图标、名字、一句描述，「获得」时有个小落袋动画 | 点开看详情 | 一行文字 |
| 线索 `<dsh-clue>` | 便签样式，收进线索本 | 点开 | 一行文字 |
| 剧中手机消息 `<dsh-phone>` | 一段手机聊天界面（头像、气泡、时间） | 点开全屏剧中手机 | 「某某：……」 |
| 插图 `<dsh-image>` | 生成或卡里带的图，点开全屏，可存进相册 | 放大、保存 | 图片链接 |
| 掷骰 `<dsh-roll>` | 骰子滚动后停在点数，写着检定项和成败 | 点开看算式 | 「检定：潜行 14/12 成功」 |
| 提示 `<dsh-notice>` | 一行细字：「好感 +5」「获得：铜钥匙」 | — | 一行文字 |
| 小游戏 `<dsh-game>` | 一个前端块（agent §6.4），玩完把结果交回剧情 | 玩 | 一句「此处有一个小游戏」 |

**跟着对话走**（外壳里，Flutter）

| 组件 | 在哪 |
|---|---|
| 建议回复 | 输入区上方的一排胶囊，点了填进输入框（不直接发），长按直接发 |
| 状态面板 | 底部抽屉（§8） |
| 背包 | 状态面板的一页，格子排列；把物品拖到立绘上 = 「把它给 TA」 |
| 地图 | 全屏；去过的地方亮，点地点 = 「去那里」 |
| 线索本 | 全屏卡片墙；线索之间能连线（连线只是你的笔记，不发给模型） |
| 剧中手机 | 全屏的手机界面：和每个角色的私聊、朋友圈式动态。私聊是同一段对话里的一条支线（agent §6.3） |
| 分支树 | §7 |
| 导演笔记 | 抽屉，默认折叠、标「剧透」（agent §3） |

组件默认的样子跟 App 的玻璃风格走；卡能用 CSS 变量（`--dsh-letter-paper` 这类）和 `::part()` 改，规则在 compat §6。

## 6. 输入区

- 用主对话的 `Composer`（它已经和对话状态解耦，DS Bot、群聊都在用）。左边是当前人设的头像，点了换人设。
- 上方一排胶囊，从左到右：建议回复（导演给的）、快速回复（卡带的或你建的）、脚本按钮（酒馆助手脚本声明的）、骰子。放不下就横向滑。
- 发送键长按：以旁白身份发；只发不让角色回；让某个角色接着说（群聊）。
- 输入框旁的小按钮：**帮我写**（模型替你写你这句，填进输入框）、**接着写**（让最后一条接着往下写）。
- 语音输入用 App 已有的那套。

## 7. 消息操作

- **换回答**：任何一条角色消息都能左右滑，底下小字「2 / 5」。在最后一条上往左滑到头 = 再生成一个。滑一条较早的消息，会切到那条备选所在的分支（后面的内容跟着换），顶部提示「切到了另一条分支」，能撤销。
- **长按菜单**：复制、编辑、朗读、从这里分叉、重新生成、删除（这条 / 这条及以后）、隐藏（不发给模型，同 ST 的 `/hide`）、看这一回合的提示词（检视）。
- **编辑**：弹一个原生的编辑页，不在画布里改；保存后按 ST 的规则跑「编辑时」正则。
- **分支树**：在对话顶部下拉，或从菜单打开。整段对话画成一张流程图：每个岔口一个节点，当前这条路高亮，每条分支末端写着最后一句。点任一节点跳过去；长按能给分支起名、删掉。玩悬疑和多结局的卡时，这张图就是「剧情流程图」。

## 8. 状态面板

- 底部抽屉，内容按卡定义的状态画（agent §2.2 的显示提示）：关系（条）、属性（数字）、背包（格子）、任务（列表）、时间地点（一行）。
- **这一回合变了什么**：变化的值旁边有「+5」这样的小标签，下一回合消失。重要的变化同时在消息底下出一条 `<dsh-notice>`。
- **你可以直接改**：点数值就能改。改动记在当前节点上（标「你改的」），换回答、切分支时一样会回退。
- **没定义状态的老卡**：显示酒馆助手 / MVU 变量的树形视图，能搜、能改。开了整理者的，再加一页「自动整理」（agent §2.4）。
- 顶栏那行小字放卡钉住的状态；没钉的卡不显示。

## 9. 编辑器和检视

- **角色编辑**：V3 的字段分组折叠（基本、设定、开场白、示例、系统提示、世界书、资源、扩展）；`extensions` 里不认识的东西只读显示，原样保存。
- **世界书编辑**：条目列表（开关、关键词、位置、顺序）；条目编辑页把 ST 的字段分成「常用」和「更多」；「测一下」：输入一段话，看哪些条目命中、为什么。
- **预设编辑**：照 ST 的提示词管理器：一列提示词，开关、拖动排序、点开改内容和插入位置；采样参数一页。
- **正则编辑**：列表、开关、作用范围；「试一下」：输入一段文字，看替换前后。
- **检视页**：这一回合发出去的每一段，标着来源（预设的哪一条、哪张卡、哪个世界书条目和命中原因、导演提示、记忆）、各自的 token 数、缓存命中了多少、大约花了多少钱；下面是这一回合后台 agent 各跑了什么。会打碎缓存的段落标黄（compat §3.5）。

## 10. 主题

- **卡的主题**（`extensions.dshgo.theme`）：强调色、正文和名字字体、背景、气泡样式、各角色的名字颜色、默认排版。只作用于画布和舞台；外壳仍用 App 的配色。
- **ST 的主题**：导入 ST 主题 JSON 里和对话有关的部分——正文、斜体、引号的颜色，和自定义 CSS。自定义 CSS 直接加进画布，因为 DOM 照 ST 搭，大多能生效。
- **字体**：卡可以带字体文件或写网络字体；App 自带一款中文衬线体给小说排版用（待定，见 §13）。
- **你说了算**：设置里能关掉卡的主题和自定义 CSS，回到默认样子。

## 11. 动效和触感

都在 polish-guide 的规矩里，经 `AppMotion` 取时长，系统关动画时全停：

- 新消息从输入框升起（主对话已有的 `StreamFadeIn.rise`）；流式正文用匀速出字。
- 视觉小说：逐字出现、立绘交叉淡变、换背景淡变 300 毫秒。
- 掷骰：数字滚动后停住（`RollingCount`），出结果时轻震一下。
- 状态变化的小标签淡入淡出；建议回复的胶囊逐个错开出现（≤ 30 毫秒）。
- 换回答、切分支时轻震一下；分支树里点节点时，画面从那个节点放大过去（灵动档）。

## 12. 无障碍和窄屏

- 画布输出语义化的 HTML，读屏按消息顺序读，每条先读说话人。
- 360dp 宽、系统字号 1.3 下：顶栏状态那行省略、胶囊横向滑、视觉小说的对话框变高。
- 外壳控件都有 `Semantics` 标签；画布里的组件有 `aria-label`。

## 13. 待定

- Live2D 放进画布：伙伴的 `stage.js` 是为单独的页面写的，搬进画布的舞台层要拆一拆。
- 自带中文字体的体积和许可证。
- ST 主题导入只做颜色和自定义 CSS，模糊、布局类的设置不做。
- 剧中手机的私聊做成同一棵消息树上的支线，还是单独的小对话。倾向前者，状态好算。
