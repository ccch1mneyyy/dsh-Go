# 酒馆：agent 玩法

> 总纲见 [roleplay.md](roleplay.md)，界面见 [roleplay-ui.md](roleplay-ui.md)。这一册是增强层：状态、导演、群像、记忆、组件、工具、异步剧情、做卡助手，以及卡里的 `extensions.dshgo` 怎么写。后端（`packages/dsh_tavern`）交给 Pro。

## 0. 结论

- **回合里有三条通道。** 表现类（表情、换场景、组件）写在正文的标记里，边流边生效；改状态、掷骰走工具；导演、整理、摘要放在回合后的后台。主回合永远只等一次模型，掷骰除外。
- **状态是真数据。** 一份 JSON，跟着消息树的节点走；有定义（类型、范围、每回合最多变多少）；四种改法（模型的工具、整理者、兼容脚本、你手改）都经同一道校验。
- **导演不写正文，只管方向。** 它在后台读剧情和状态，给主模型留一条看不见的提示、提前挑好下一回合要用的设定、给你三个建议回复。剧本卡里的真相和结局条件只有导演和规则层知道。
- **群像**让每个角色单独开口，只看到自己在场时发生的事。
- **记忆**不靠向量库：前情提要 + 记忆书（世界书格式）+ 导演挑。
- **做卡助手**在手机上就能跑：写卡、写世界书、把老卡升级成 DSH 卡、写前端并截图自查，每一处改动都给你看 diff。
- **玩法可以单独成包。** 状态定义、规则、组件、骰子、世界书、正则打成一个「玩法包」，能挂在全局、某个角色或某段对话上（§10.2）。跑团规则、剧中手机、恋爱养成都可以是包，老卡挂上就有。
- 所有这些按对话开关；关掉增强就是原样的 ST。

**调研里学到的**（2026-11-09，详见文末参考）：

- 模型维护状态并不可靠：Labyrinth 实验里 GPT-4 当主持人，状态更新的正确率只有四成多；NCP-Bench 里最好的模型也只有 42% 的局撑过 20 回合，失败大多是前后矛盾。所以状态要有规则层兜底、定期对账、你能直接改（§2）。
- 后台 agent 不能挡在你和回复之间：ST 的状态追踪插件先生成状态再生成正文，等待叠加，被抱怨得最多。导演照 Letta「睡眠时计算」的路子在后台跑（§3.3）。
- 导演给要点，不给台词：IBSEN 发现把原句给演员，演员会照抄。Talemate 的导演会替玩家角色做决定，这是要避免的坑（§3.1）。
- 限制角色最有效的办法是限制它知道什么（Inworld 的说法）；没落地的秘密会被角色「提前知道」（Hidden Door 的评测）。所以真相先落地、按在场和知情分发（§3.4、§4）。

## 1. 回合里的三条通道

| 通道 | 管什么 | 什么时候生效 | 多花一次调用吗 | 思考开着时 |
|---|---|---|---|---|
| 正文里的标记 | 表情、动作、换场景、音效、说话人、组件（§6） | 边流边解析，舞台和画布同步变 | 不 | 照常 |
| 工具 | 改状态、掷骰、记一条记忆（§7） | 回复收完时提交；掷骰在中途 | 改状态不；掷骰多一次 | 不给主回合工具，改由整理者做 |
| 回合后的 agent | 整理者、导演、摘要、群像调度、异步剧情 | 后台，你读和打字的时候 | 各自一次，用帮手模型 | 照常 |

为什么思考开着时不给主回合工具：DeepSeek 的文档要求思考模式下带工具时，把之前的思考内容发回去（ST 的做法是给带工具调用的消息补一个空的 `reasoning_content`，这样够不够要实测）。长剧情里这部分要么 token 很大，要么行为没把握。所以思考开着时主回合只写正文，状态交给回合后的整理者（关思考的 flash）；效果一样，只是状态面板晚一两秒更新。

## 2. 状态

### 2.1 状态文档

- 一份 JSON。存在**消息变量**里（酒馆助手的 message 作用域：每条消息、每个备选回答各一份），所以天然跟着节点走：换回答、切分支、删消息时自动回到那个节点的样子（总纲 §5.2）。
- DSH 卡的状态放在 `dshgo` 键下；MVU 卡的 `stat_data` 和酒馆助手的其他变量原样放在旁边，互不干扰。
- 对话级的东西（剧中时间的设置、导演笔记、整理者推断出的状态定义）放在对话变量里，不随节点回退。

### 2.2 定义

卡的 `extensions.dshgo.state.schema` 用 JSON Schema 的一个子集，加几个 `x-dsh` 关键字：

| 写什么 | 例子 | 用来 |
|---|---|---|
| 类型、范围、枚举、默认值 | `"affection": {"type": "integer", "minimum": -100, "maximum": 100, "default": 0}` | 校验、截断 |
| `x-dsh-step` | `5` | 一回合最多变多少，多了截断 |
| `x-dsh-by` | `["model", "rules", "user"]` | 谁能改；只写 `rules` 的模型改不动 |
| `x-dsh-hidden` | `true` | 不给主模型看（真相、暗骰、配角的秘密） |
| `x-dsh-show` | `"bar"`、`"number"`、`"tags"`、`"inventory"`、`"list"`、`"line"` | 状态面板怎么画（ui §8） |
| `description` | 「她对你的好感，0 是陌生人」 | 写进提示词和工具说明，告诉模型这是什么 |

同一份 schema 直接生成 `update_state` 工具的参数定义（DeepSeek 严格模式要求所有字段必填、`additionalProperties: false`，生成时照办），也生成状态面板。

### 2.3 操作

改状态只有一种形式：一串操作，每个是 `{op, path, value, why}`。

- `op`：`set`、`add`（数字加减）、`push`、`remove`、`move`（背包里的东西从一处到另一处）。`path` 是 JSON Pointer。
- 可以带 `from`（模型以为的旧值，学 MVU 的 `_.set(路径, 旧值, 新值)`）。和实际的旧值对不上时照样按规则提交，但记一次「冲突」：冲突多说明模型记错了状态，下一回合的状态那一段会写得更显眼，对账也会提前。
- 每个操作过校验：类型、范围（越界就截断到边界）、`x-dsh-step`、`x-dsh-by`。不过的丢掉，检视页里记下原因。
- 一回合的操作合成一份增量存在节点上。

### 2.4 四种改法

1. **主模型调工具**（思考关着时）：回复末尾调 `update_state`，不需要把结果发回去，App 直接提交（§7.2）。
2. **整理者**（回合后，帮手模型）：读这一回合你说的和角色说的、当前状态、schema，调 `update_state`。用在思考开着时、老卡，以及**对账**：主模型自己调了工具时，整理者默认每 3 回合把这几回合的正文和状态核对一遍，补上漏掉的、纠正对不上的（频率可调，也能关）。
3. **兼容**：MVU 的更新命令、酒馆助手脚本写变量，由它们自己的脚本在画布里处理（compat §5.3）。DSH 状态不去解析它们，但整理者和状态面板能读到它们的结果。
4. **你手改**：状态面板里点数值改（ui §8），记成「你改的」。

**老卡的自动整理**：卡没有 schema 时，整理者第一次运行先根据开场和设定推一份小定义（在场角色和关系、地点、时间、随身物品、正在做的事），存在对话变量里，之后按它维护。你可以在面板里改这份定义、删字段、钉到顶栏。

### 2.5 规则

卡可以写两类规则，都是声明式的 JSON，不跑代码（要跑代码的用酒馆助手脚本）：

- **派生值**：`"mood": {"x-dsh-derive": {"if": [{">": [{"var": "affection"}, 60]}, "亲近", "普通"]}}`。表达式用 JsonLogic 的写法（一种用 JSON 写的表达式，规范公开），在 Dart 里实现一个子集：比较、算术、逻辑、取值。
- **触发**：`{"when": <JsonLogic>, "once": true, "do": [...]}`。动作有：改状态、给主模型插一段提示（下一回合）、出一条 `<dsh-notice>`、给导演发一个事件、解锁结局或成就。每回合提交状态后检查一遍。

伙伴的亲近度规则（每 6 小时最多 +0.01、不因缺席扣分）就是写成这样的一组规则，放在伙伴卡的 `extensions.dshgo.bond` 里。

### 2.6 给模型看什么

- 每回合把状态按模板写成一小段，按深度插进聊天记录（默认深度 1，也就是你最新那句之前，system 角色；发 DeepSeek 时照 ST 的后处理变成 user，compat §3.4；卡能改位置和模板）：「【状态】第三天 黄昏，酒馆二楼。林：好感 35（友好），受伤。你的背包：铜钥匙、火柴×3。」
- `x-dsh-hidden` 的字段永远不进主模型的提示词。
- 状态那一段每回合都变，所以放在靠后的位置，不打碎前面的缓存。

## 3. 导演

### 3.1 做什么、不做什么

做：读剧情和状态，决定下一拍往哪走；给主模型留一条看不见的提示；挑好下一回合要用的世界书条目和记忆；写三个建议回复；管真相、伏笔、结局条件；按剧本推进章节。

不做：不写正文、不替角色说话、不替你决定。导演的提示是建议，主模型怎么写还是它自己的。

- **给要点，不给台词。** `beat` 写「要发生什么、谁在意什么、几个关键词」，不写成句的对白，否则主模型会照抄。
- **不替你行动。** `beat` 和建议回复里不能替你的角色做决定、说话；导演的提示词里写明，App 检查 `beat` 里有没有以你的名字开头的动作句，有就去掉那句。
- **先落地再揭示。** 不是剧本卡也一样：剧情里出现一个没打开的宝箱、一个没说出口的秘密时，导演当场把答案定下来，写进隐藏状态。之后主模型拿到的只是「现在可以揭开的部分」，不会前后对不上，角色也不会提前知道。

### 3.2 输入和输出

- **输入**：卡（含剧本）、前情提要、最近几回合、当前状态（含隐藏字段）、导演自己的笔记、你的人设。前面几样很少变，缓存命中率高。
- **输出**：调一次 `direct` 工具：

| 字段 | 去哪 |
|---|---|
| `notes` | 导演自己的笔记，覆盖上一份（对话变量），你在「导演笔记」里能看，默认折叠标剧透 |
| `beat` | 下一回合插进主模型提示词的一段（深度 1，system）：「下一回合让雨停下来，老板娘提起地下室。别直接说出这条提示。」 |
| `prefetch` | 下一回合强制激活的世界书条目和记忆的 id |
| `suggestions` | 三个建议回复，放在输入区上方（ui §6）。尽量一个做事、一个说话、一个表达感受；有风险的标出来（「可能被发现」），让失败成为真的可能 |
| `events` | 规则层的事件：推进章节、触发结局、安排一条剧中手机消息（§8） |

### 3.3 什么时候跑

- 每回合结束后在后台跑；卡或你可以改成每 N 回合一次。
- 你在它跑完之前就发了下一句：用上一份 `beat` 和 `prefetch`，这一份跑完后照样存下，留给下一回合。
- 进对话时如果离开超过设定的时长，先跑一次（§8）。
- **预先写好开头**（默认关）：导演出了建议回复以后，用帮手模型给每个建议预先写好回复的开头。你点了建议，回复几乎立刻出来。三个建议共用同一段前缀，基本都按缓存价计费，但没被选中的那两份是白花的，所以默认关。

### 3.4 剧本卡

DSH 卡可以带一份剧本（`extensions.dshgo.story`）：

- `outline`：故事大纲，只给导演看。
- `acts`：章节，每章有目标、进入下一章的条件（JsonLogic，看状态），以及最少、最多回合数。没到最少回合不推进；过了最多回合，导演强制推进（学 IBSEN：判断「目标完成了没有」时模型常拿不准，到点就推）。
- `tension`（可选）：一条张力曲线，每章一个目标值。导演按它决定这一拍是松还是紧（学 Façade 的戏剧管理）。
- `secrets`：真相和伏笔，每条写着谁知道、什么条件下可以揭开。
- `endings`：结局，每个有条件和标题；达成时出一个结局页，记进这张卡的成就，同时生成一张**纪念卡**（这段故事的一句话、一张图——开了插图时现画，否则用卡面——和日期），收进相册，也写成一条记忆。收藏从剧情里长出来，不靠抽卡。

**真相不进主模型。** 悬疑卡里「谁是凶手」只在导演和规则层手里；主模型只拿到导演给的提示（「管家今晚很紧张，但不会说为什么」），所以不会说漏。你指认凶手时，规则层按真相判。

**即兴剧本。** 没有剧本的卡也能玩成故事：开始对话时选「来一段故事」，挑一个类型（悬疑、冒险、恋爱、恐怖……），导演用这张卡（或几张卡）当场写一份剧本——大纲、三五章、几个秘密、两三个结局——存进对话变量，之后和剧本卡一样跑。分支树能让你回到岔路口，看另一个结局。

## 4. 群像

### 4.1 发言顺序

- 照 ST 的四种：自然点名（被叫到名字的人说）、轮流、随机池、手动；加一种：**导演点名**（导演的 `events` 里指定下一个说话的人）。
- 每个角色有「话多话少」（ST 的 `talkativeness`）。

### 4.2 三种上下文

| | 共用（经典，和 ST 一样） | 账本 | 各自视角（群像） |
|---|---|---|---|
| 怎么生成 | 一次调用，一次一个角色 | 一次调用，可以几个角色一起说 | 每个开口的人单独一次 |
| 每个角色看到的历史 | 整段对话 | 整段对话，另附一本「谁知道什么」的账本 | 只看自己在场时的节点；不在场时的事只拿到公开的摘要 |
| 秘密 | 都在提示词里，靠模型自觉 | 账本里写明「X 不知道这件事」，靠模型照账本演 | 只进知道的那个人的提示词 |
| 记忆 | 共用 | 共用，账本按人分 | 每人一本记忆书 |
| 花费 | 每回合一次 | 每回合一次 | 每个开口的人一次 |

账本是便宜的折中：多数时候够用；悬疑、宫斗这类秘密就是玩法的卡，用各自视角。对账时（§2.4）整理者顺带检查「有没有人说出了他不该知道的事」，有就在检视页标出来，下一回合的账本里加重提醒。

- **谁在场**：每个节点记着当时在场的角色（状态里的 `scene.cast`，由标记 `[登场:名字]`、`[退场:名字]` 或导演事件维护）。
- **知道什么**：`secrets` 和配角的隐藏字段写着 `knownBy`。

### 4.3 花费和等待

- 一回合默认最多 3 个人开口，一个说完下一个才开始（后面的人要听到前面的人说了什么）；每个人都流式出字，所以第一个字很快就到。
- 主角用主模型，配角默认用帮手模型。

## 5. 记忆

### 5.1 三层

1. **最近原文**：按 token 预算从新往旧取。DeepSeek 有 1M 上下文，但长上下文又慢又贵，默认预算 32k，可调。
2. **前情提要**：超出预算的部分，滚动写成摘要。
3. **记忆书**：一条一条的事实，世界书条目的格式（关键词、常驻、过期）。

### 5.2 前情提要

- 原文快要超出预算时，把最早的一段（默认 20 个节点）写成一段摘要；摘要多了再合并成「章节摘要」。成批做、少做：每重写一次摘要，它后面的缓存就要重建一次。
- **最近 6 个节点永远不摘要**（学 AI Dungeon），所以撤回、换回答、改最近的话都不会碰到摘要。
- 写摘要时顺手给每段打一个重要性（1–5），预算紧时先丢不重要的旧摘要，置顶的不丢。
- **跟着分支走**：摘要挂在它覆盖的那段节点上。切到另一条分支，用的是那条路上的摘要；分叉点之后的摘要要重写，后台补。
- 能手改，改过的标「你改的」，不会被自动覆盖。
- 插在聊天记录前面，用预设里的位置（没有就在角色设定之后）。

### 5.3 记忆书

- 写摘要时、导演跑完时，会提议几条值得记的事（「林怕黑」「你答应过下周带她去看海」），默认要你确认，可以改成自动收。
- 它就是一本世界书：用世界书引擎按关键词命中，置顶的常驻。导出时是一本标准的 ST 世界书。
- **关于故事和关于你分开记。** 酒馆的记忆书只记故事里的事；伙伴的记忆（`CompanionMemory`）记的是你本人。两本不混：故事里你演的骑士受了伤，不能变成「用户受伤了」（Character.AI 的自动记忆就犯过这个错）。伙伴请进酒馆演戏时，只读你本人那本，不往里写；写的都进这段故事的记忆书。
- 伙伴的记忆和记忆书的字段对得上（`keywords`、`pinned`、`expiresAt`），共用同一套世界书引擎来命中。

### 5.4 取用

- 关键词命中（世界书引擎），加上导演的 `prefetch`：导演看着最近的剧情，从记忆和设定的标题列表里挑出下一回合可能用到的。这比向量检索更懂「接下来要发生什么」，而且不需要额外的服务。
- 想用向量检索的，可以在设置里填一个 OpenAI 兼容的 embeddings 接口（DeepSeek 没有 embeddings），开了以后多一路召回。

## 6. 正文里的标记和组件

### 6.1 标记

沿用伙伴现有的写法（`[表情:开心]`、`[动作:点头]`，全角括号和冒号也认，解析在 `companion_reply.dart`），加几种：

| 标记 | 作用 |
|---|---|
| `[表情:名字]` | 换当前说话人的表情（立绘、Live2D、表情图） |
| `[动作:名字]` | Live2D 动作 |
| `[场景:名字]` | 换背景（卡的 `assets` 里的 `background`，按名字找） |
| `[音效:名字]`、`[音乐:名字]` | 播卡里带的音频；音乐循环，直到下一个 `[音乐:]` 或 `[音乐:停]` |
| `[说话人:名字]` | 一条回复里换人说话（旁白式的卡、小说排版） |
| `[登场:名字]`、`[退场:名字]` | 维护在场名单（§4.2） |

- 边流边解析；半个标记先压住，等它完整再处理（伙伴已经这样做）。
- 显示时去掉；存档里保留，导出到 ST 时可选去掉。
- App 在提示词里加一小段说明可用的标记和名字列表（表情、背景、音频都从卡的资源里列），这段对话里不变，所以不打碎缓存。

### 6.2 组件标签

跟着消息走的组件（ui §5）由模型直接写成标签，比如：

```
<dsh-letter from="林" date="三月初七">见字如面……</dsh-letter>
<dsh-item name="铜钥匙" icon="key">锈迹斑斑，齿纹很深。</dsh-item>
```

- App 在提示词里说明这张卡开了哪些组件、各自的写法（同样一段对话里不变）。卡可以关掉某些、加自己的。
- 画布把标签渲染成组件；在 ST 里，未知标签会被清洗掉标签、留下文字，读起来仍然通顺。
- 获得物品这类组件同时可以带状态操作：`<dsh-item ... take>` 等于往背包里 `push` 一件，走 §2.3 的校验。这样即使没用工具，也不会出现「画面里拿到了，背包里没有」。

### 6.3 剧中手机

- 角色发来的手机消息写成 `<dsh-phone from="林">在吗？</dsh-phone>`，消息里显示一小段聊天界面，点开是全屏的剧中手机（ui §5）。
- 你在剧中手机里回的话，是挂在当前节点上的一条**私聊支线**：只有那个角色能看到（群像下其他人看不到）。私聊完回到主线，主线的下一回合会带上私聊的摘要。

### 6.4 小游戏

- 两种来源：卡里带的模板（`extensions.dshgo.minigames`，模型写 `<dsh-game id="lockpick" difficulty="3"/>` 调用），或模型当场写一段 HTML（`<dsh-game>` 里直接放代码，需要卡或你开了「允许即兴小游戏」）。
- 跑在画布的前端块里，和酒馆助手的前端块同样的环境，多一个 `dsh.finish(result)`。
- 玩完，结果作为你下一句话的开头：「【小游戏·开锁】成功，用时 12 秒。」剧情接着讲。
- 即兴小游戏建议用 `deepseek-v4-pro` 写；写坏了（报错、白屏）显示「这个小游戏没跑起来」和一个「跳过」。

### 6.5 插图

- `[插图:一句画面描述]`，或者导演觉得是关键时刻时发一个事件。
- 生成在后台，好了以后以 `<dsh-image>` 插在那条消息下面，同时存进这段对话的相册。
- 接口：设置里填一个生图接口（OpenAI 兼容的 images、硅基流动、通义万相等，和主机的 dsh-media 用同一批服务商）；连着主机时也可以交给主机的 dsh-media。DeepSeek 不出图。
- 默认关，因为要另配接口、另花钱。

## 7. 工具

### 7.1 清单

| 工具 | 谁用 | 要把结果发回去吗 |
|---|---|---|
| `update_state(ops[])` | 主模型、整理者 | 不 |
| `roll(dice, label, target?)` | 主模型 | 要：掷完接着讲 |
| `remember(text, keywords[])` | 主模型、导演、摘要 | 不 |
| `direct(...)` | 导演 | — |
| `summarize(...)` | 摘要 | — |
| 做卡助手那一套 | 做卡助手 | 要（§9） |

主回合的工具就前三个，卡可以关掉。工具定义每段对话里不变，放在请求的固定位置，不影响缓存。

### 7.2 怎么调

- 走 OpenAI 格式的函数调用；DeepSeek 用 `/beta` 开严格模式，参数一定合 schema。
- **不需要结果的工具不回传。** 回复末尾只有 `update_state`、`remember` 时，App 提交后这一回合就结束，不再调模型。下一回合的历史里只放正文，不重放工具调用：工具的效果已经体现在状态那一段里了。这样每回合的消息结构和 ST 一样，缓存也稳。
- **掷骰**：模型中途调 `roll` 时，这一次请求停下，App 掷骰、画出骰子动画，把结果作为工具结果发回去，模型接着讲。两段拼成同一条消息。第二次请求的前缀和第一次一样，几乎全部命中缓存。
- **你自己掷**：输入区的骰子按钮，掷出的结果附在你这句话前面（「【潜行 d20=14】」），不用模型调工具。暗骰由规则层在回合前掷好，写进隐藏状态，只有导演看得到。

### 7.3 手机上的工具循环

App 里现在没有工具调用循环（伙伴的轻量模式只收文字），`dsh_tavern` 自己写一个：

- 流式解析 OpenAI 格式的 `tool_calls` 增量；
- 一次回复里的多个工具调用按顺序执行；
- 每个工具调用、校验结果、耗时都记进 `agent_runs`，检视页能看；
- 一回合最多 4 次往返，超了就停下，把已有的正文存下。

## 8. 异步剧情

- **剧中时间**：每段对话选「不走」（默认，剧情时间只随剧情推进）或「跟着现实走」。
- **离开以后**：跟着现实走、且离开超过设定的时长（默认 8 小时）时，回来时导演先写一段「你不在的时候」，作为一条旁白接在对话最后；不喜欢可以左右滑换一个，或者删掉。
- **角色主动找你**（默认关）：导演可以在 `events` 里安排一条剧中手机消息，到点用 App 的通知发出来（和 [companion-daily.md](companion-daily.md) 的定时通知共用一套定时和频道，酒馆有自己的通知类别，能在系统设置里单独关）。点开回到这段对话，消息已经在剧中手机里。每条消息是一次帮手模型调用。
  - 你正在这段对话里时不发通知，消息直接出现在剧中手机里，不打断正在演的那一幕。
  - 可选：免打扰时段（默认跟系统的勿扰）、每天最多几条、每日花费上限，都和伙伴那边共用。

## 9. 做卡助手

在手机上跑，用的是同一个工具循环，不需要主机：

| 工具 | 做什么 |
|---|---|
| `card_read` / `card_write` | 读写卡的字段；写的时候给 diff |
| `lore_*` | 世界书条目的增删改查 |
| `regex_*` | 正则的增删改，`regex_test` 用样例文字试 |
| `preset_read` | 读当前预设 |
| `prompt_preview` | 用这张卡组一次提示词，看实际发出去什么 |
| `render_preview` | 让画布渲染一条样例消息，返回截图（flash 能看图；v4-pro 不能，看图时自动换 flash） |
| `simulate` | 用帮手模型和这张卡对几回合，看开场、状态、世界书命中是否正常 |
| `lint` | 体检：从没命中过的条目、编译不过的正则、会打碎缓存的位置、缺开场白、schema 和状态栏对不上 |

**能做的事**

- 从一段描述生成一张卡；从粘贴的小说、设定集生成世界书。
- **老卡升级成 DSH 卡**：MVU 的初始变量 → `state.schema`；正则状态栏 → 原生状态面板 + 组件；从开场和设定里抽出剧本的骨架。升级后的卡另存一份，原卡不动。
- 写前端（状态栏、美化），渲染截图自己检查，再给你看。
- 翻译卡（带世界书和正则里的文字）、给卡体检。

**每一处改动都给你看**：像代码审查一样逐条显示 diff，可以全收、挑着收、全退；卡有版本历史，随时回到之前的样子。

连着主机时，做卡助手可以借主机的网页工具去抓设定百科；不连主机时只用你给它的文字。DeepSeek 自己的搜索和抓取接口（另计费）能不能直接用，待定。

## 10. 卡的扩展和玩法包

### 10.1 `extensions.dshgo`（v1）

```json
{
  "v": 1,
  "state":   { "schema": {}, "init": {}, "rules": [], "summary": "模板", "pin": ["/time", "/place"] },
  "story":   { "outline": "", "acts": [], "secrets": [], "endings": [] },
  "cast":    [ { "id": "", "name": "", "card": {}, "voice": {}, "sprites": "", "color": "" } ],
  "director":{ "enabled": true, "every": 1, "style": "" },
  "components": { "enabled": ["letter", "item", "clue", "phone", "roll", "notice"], "custom": [], "css": "" },
  "dice":    { "system": "d20", "skills": {} },
  "minigames": [ { "id": "", "title": "", "html": "", "params": {} } ],
  "theme":   { "accent": "", "fonts": {}, "background": "", "layout": "bubble", "names": {} },
  "async":   { "clock": "story", "messages": false },
  "live2d":  {}, "voice": {}, "bond": {}
}
```

- 每一块都可以省；省了就用默认，或者这项功能对这张卡不开。
- `cast` 让一张卡带一群角色（群像卡、剧本卡）；每个角色的 `card` 是一份完整的 V3 `data`。
- `live2d`、`voice`、`bond` 是伙伴原有的（总纲 §8）。
- 在 ST 里这一整块被忽略。导出时可选「同时生成 ST 能用的状态栏」：按 schema 写一条 MVU 风格的初始变量世界书条目和一条状态栏正则，装了 MVU 和酒馆助手的 ST 也能看到状态（R6 再做）。

### 10.2 玩法包

学 RisuAI 的模块：把一套玩法从卡里拿出来，单独成包，挂到哪张卡上都能用。

- **是什么**：一份独立的 `extensions.dshgo`（可以只有其中几块），加上可选的世界书、正则、快速回复和资源，打成一个 zip（`.dshpack`，根目录 `pack.json`）。
- **挂在哪**：全局、某个角色、某段对话。几层一起生效时，状态定义按路径合并（同一路径，对话 > 角色 > 全局 > 卡自带）；规则、组件、骰子技能取并集；世界书和正则按 ST 的来源顺序加进去。
- **例子**：跑团（属性、技能、检定、骰子、战斗回合）、剧中手机、恋爱养成（好感、阶段、纪念日）、悬疑（线索本、指认判定）、生存（饱食、体力、昼夜）。
- App 自带几个；做卡助手能写；也能导入别人做的。
- 导出卡时可以选「把挂着的玩法包并进卡里」，变成一张自带全套的 DSH 卡。

## 12. 出错时

- 工具参数不合 schema、或者操作被规则拒掉：丢掉这个操作，检视页记原因，正文照常显示。
- 模型该调工具没调：开着「每回合核对」时整理者会补上；没开就算了。
- 导演、整理者、摘要超时或报错：这一回合不用它的结果，检视页标红，不打扰你。连续失败三次，顶栏出一个小提示。
- 小游戏、插图失败：显示一句原因和「跳过」。
- **复读**：模型反复用同样的句式、同样的情节时，App 在本机比较新回复和最近几条的重合度（不调模型）。超过阈值时，下一回合在末尾加一句「避免重复前几回合的句式和情节」，导演也会收到提醒去换个方向。默认开，可关。
