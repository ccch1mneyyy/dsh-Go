# 设置的信息架构

> 2026-10-27 · 基于 main `49ccf36`（0.9.5）。这一轮只做研究和设计，不改代码。配合 [page-design.md](page-design.md)（页面骨架）、[polish-guide.md](polish-guide.md)（对称、文案、术语）和另一个代理的风险提醒与「问 AI」方案（`docs/design/risk-notices-and-ask-ai.md`，提交 `9bc4b30`，还没合入 main）一起看。

**结论**：设置难找，主要不是因为藏得深。从对话页数起，首页上的一行是 3 下，大多数设置 4 到 5 下就能改到。真正的问题有三个。第一，同一件事散在好几处，名字还不一样：「让 AI 别问我」有 5 个入口、4 种叫法。第二，「设置」和「全部功能」互相嵌套：全部功能 38 张卡里有 16 张打开的其实是设置页，而权限、Agent 预设只能从全部功能进去。第三，首页按技术模块分组：「引擎与扩展」一组塞了 9 行，「通用设置」里其实是网页版的选项。

新方案做四件事：

- **按意图重组首页**：分成 AI、能力、外观、通用、主机、帮助与关于六组，每行右侧显示当前值。
- **就近设置**：当前对话的权限和计划模式放进输入区的 ＋，手机操控的确认方式也在那里。权限放宽时，输入框上方常驻一枚提示胶囊。
- **设置搜索**：中英文、同义词和旧名字都能搜到，点结果跳到那一行并高亮。搜不到时给出「问 AI」。行和索引取自同一个常量，测试保证两者对得上。
- **划清分工**：设置管「以后怎么样」，全部功能管「现在去做」。

实现分 7 步，可以逐步合入。先做索引和搜索，不动页面结构就能先解决「找不到」；再重组首页，最后做对话里的就近设置。

## 1. 现状盘点

**计数规则**：从对话页（手机竖屏）起算，点一下或长按一下都算 1 下；打字不算；确认框算 1 下。设置首页本身是 2 下（≡ › ⚙，在抽屉底部的身份栏）。宽屏（≥840dp）导轨上的 ⚙ 只要 1 下。网页模式下从网页版的 App 标志 › **App 设置** 进入。

**频率**：高 = 每周会碰；中 = 首周必碰，或每月碰一次；低 = 一次性设置或排障时才碰。

**影响面**：
- App：本机全局，存在 SharedPreferences 或安全存储。
- 本机引擎：只影响本机引擎，常常要重启才生效。
- 当前主机：写在当前主机的引擎里，连远程主机时改的就是远程那台。
- 当前对话。
- 系统：跳到 Android 系统设置去改。

文件路径都相对 `app/lib/`，行号以 main `49ccf36` 为准。

## 2. 问题

### 2.1 主要问题（按严重程度）

**P1 · 同一件事散在多处，名字还不一样。** 「让 AI 别每步都问我」有 5 个入口、4 种叫法，状态分别存在 4 个地方（SharedPreferences、引擎、内存、原生侧）：

| 入口 | 叫法 | 下 | 改的是 |
|---|---|---|---|
| 设置 › 对话 | 自动执行命令 | 3 + 确认 | `auto_approve_commands`（本机新对话） |
| 设置 › 全部功能 › 权限 | 完全权限 / 自动审查 | 5 + 确认 | `permission.defaultPreset`，或当前对话；本机上选「完全权限」改的其实还是上一行的开关 |
| 审批卡 | 本对话都允许 | 1，只在有审批时 | 内存，重启后失效 |
| 输入框 | `/permission` | 打字 | 当前对话 |
| 设置 › 手机操控 › 确认方式 | 始终免确认 | 5 + 确认 | 手机上的点按，另一套机制 |

问题还不止这些：
- 使用说明里**没提**「全部功能 › 权限」。
- 完全权限的对话在界面上**没有任何标记**，只有「本对话都允许」有一枚胶囊。

**P2 · 「设置」和「全部功能」互相嵌套。**
- 全部功能的 38 张卡里，16 张打开的是设置页。「Agent 与模型」一组 7 张全是设置。
- 设置首页又放了一行「全部功能」，于是出现「设置 › 全部功能 › 子代理设置」和「设置 › 引擎设置 › 子代理」两条路到同一页，名字还不同。
- 从设置这一侧看，权限、Agent 预设、远程主机三项只能先进全部功能才找得到。

**P3 · 按技术模块分组，名字对不上用户的说法。**
- 「引擎与扩展」一组 9 行，再加插件注入的行，里面同时有引擎、模型、插件、分享、网页版、功能目录和安全模式。
- 「引擎」和「引擎设置」挨着：前者是本机的运行环境，后者是当前主机（可能是远程主机）的参数。
- 「通用设置」里装的是网页版的显示和发送选项，外加一个隐私开关（上传对话日志）。
- 首页组名叫「外观」，组里一行叫「主题」，主题页的第一节又叫「外观」。宠物在主题页最底下。
- 「完成后收起过程」（原生）和「工作步骤收起时机」（网页版）听起来像同一件事。
- 用户心里想的是「换模型」，入口却叫「模型渠道」。

**P4 · 常用的藏得深，少用的放得浅。**
- 首页第一组没有标题，放的是界面、语言、性能，这三项一年也动不了几次。
- 后台保活要 4 下，藏在「引擎」里。国产机用户第一周就会碰到它，它在常见问题里排第二（`docs/guide/zh/11-faq.md:18`）。
- 远程主机在首页没有行。
- 联网搜索的 Key 要 6 下。
- 关闭上传对话日志要 5 下，而且藏在「通用设置」里。
- 最深的是命令执行 › 更多里的字段，7 下。

**P5 · 对话里看不到、也改不了「这个对话」的设置。**
- 当前对话的权限只能打 `/permission`，或者绕道全部功能。
- 计划模式只能打 `/plan`。
- 语音识别出错时，提示里不给去设置的路。

**P6 · 没有搜索。** 设置和全部功能加起来超过 100 个可调项，却没有一个能搜的地方。

**P7 · 风险项和普通项混在一起。**
- 首页「对话」组的第二行就是「自动执行命令」，和「可视化回复」放在同一级。
- 「以安全模式启动」会重启引擎、中断进行中的回复，却是首页上的一行普通入口。
- 「访问手机文件」也在首页，开关它同样会重启引擎。

**P8 · 开发者选项没有专门的位置。** 正在开发的「直接启动本机引擎」放进了诊断页。可诊断页是给所有人排障用的。

## 4. 新方案

### 4.1 七条规则

1. **设置管以后，对话管现在。** 默认值在设置里，当前对话的值在对话里改。模型是例外：引擎本来就把上次选的模型当新对话的默认，模型页只是把这一点放到明面上（§6 D7）。
2. **一项设置只有一个家，入口可以有多个，但名字必须相同。**
   - 每一项只有一个固定的位置。
   - 别处可以放入口，但要用同一个名字、打开同一页，并高亮那一行。
   - 不复制控件。确实需要就地改的，用同一个控件，绑同一个 provider。
3. **按意图分组，用用户的说法。** 组名回答「我想……」：AI 怎么工作、能做什么、长什么样、手机上怎么表现、连哪台机器、出了问题找谁。
4. **首页每一行都有值。** 子页入口右侧显示当前值或摘要，不点进去也知道状态。
5. **首页不放任何放宽保护或删除数据的控件。** 放宽保护、删除、重置都放在对应页里，走风险提醒（`confirmRisk`）。删除和重置放在页底的危险区。
6. **找不到就搜，搜不到就问。** 搜索覆盖设置和功能，中英文都行，认同义词和旧名字。没有结果时给出「问 AI」。
7. **低频项收进对应页的「高级」，开发者项要先解锁。** 首页不出现技术名词：子代理、Agent 循环、命令执行都收进「引擎参数」。

### 4.5 设置搜索

#### 范围
- 所有设置行，包括子页里的行和弹层的入口行。
- 所有设置页。
- 全部功能的每张卡，单独成「功能」一组。
- 引擎下发的插件命名空间及其字段名。这部分是动态的，标「当前主机」。

#### 入口
- 首页顶部的搜索胶囊。
- 长按抽屉里的 ⚙。
- 全部功能底部的「全部设置」（§4.6）。

#### 匹配
- 标题、同义词、所在路径，中英文**同时**匹配，与界面语言无关。中文界面下搜「dark」也能找到「深色」。
- 先做归一化：转小写、全角转半角、去掉空格。
- 匹配方式是子串匹配，不做分词。
- 同义词里放进旧名字。比如「完全权限」的同义词有「自动执行命令」，「模型」的同义词有「模型渠道」，「后台运行」的同义词有「保活」。改版后老用户按记忆里的名字也能搜到。

| 同义词包含 | 40 |
| 路径包含 | 20 |

#### 索引怎么维护才不会和页面脱节

做法和 Android 一样：**行的标题和索引出自同一个常量，再用测试双向核对**。

```dart
// lib/ui/settings/index/settings_index.dart（草图）
enum SettingsPageId { hub, models, permission, personalization, phone, webSearch, plugins,
  theme, pets, interface, notifications, voice, performance, background, privacy,
  engine, remote, engineParams, diagnostics, about, developer, account, /* … */ }

class SettingsPageSpec {
  final SettingsPageId id;
  final SettingsPageId? parent;            // 面包屑，也决定从哪里能到达
  final String Function(L10n) title;
  final Widget Function(String? sessionId) build;
  final Set<String> linkIds;               // dshgo://open/<id>，包括旧 id
}

class SettingSpot {
  final String id;                         // 'permission.default'，全局唯一、稳定
  final SettingsPageId page;
  final String Function(L10n) title;       // 行本身的标题也从这里取
  final String Function(L10n)? keywords;   // search_{zh,en}.arb，逗号分隔
  final bool Function(Ref)? available;     // 本机 / 手机操控开着 / 引擎有这个命名空间
  final Freq freq;                         // 高 / 中 / 低
  final String? link;                      // 可以当 dshgo://open/<link> 打开的行
}
```

- 行组件新增 `spot:` 参数：`SettingsTile`、`SettingsSwitchTile`、`SettingsSegmentTile` 各加一个，例如 `SettingsSwitchTile.spot(Spots.phoneFiles, value: …, onChanged: …)`。有了它，行的 Key 就是 `SpotKey(id)`，标题从 spot 取，不再单独传。
- 同义词放进新的 ARB 分片 `l10n/parts/search_{zh,en}.arb`（键名例如 `searchKwPermission`），由 `tool/l10n_merge.py` 合入。和界面文字一起翻译、一起审。
- 插件命名空间这类动态项，由一个 provider 读取 `engineSettingsProvider` 后追加，不进静态表。

**三道测试**：
1. **页面和索引对得上**（`test/settings/index/index_sync_test.dart`）。把每个 `SettingsPageId` 的页面在两种状态下各 pump 一次：「全都可见」（本机运行、手机操控已开、引擎 fixture 齐全、已登录）和「最少」（远程主机、全关）。然后断言：
   - 页面里每个设置行都带 spot。没有 spot 的行必须写进白名单，比如单选列表里的选项归它的父项。
   - 这一页每个 `available` 为真的 spot 恰好出现一次。
   - 中英两种语言下，渲染出来的标题都等于 spot 的标题。
   新加一行却忘了登记，或者删了一行却没删索引，这道测试都会失败。
2. **索引自身成立**（`spots_test.dart`）：
   - id 唯一；
   - 每个页面沿 `parent` 都能走回首页，没有孤儿页；
   - 每个可搜索的 spot 中英文同义词都不为空；
   - `page_links.dart` 里所有旧 id 都能解析，`pageLinkIds` 包含在索引的 `linkIds` 和 `link` 里；
   - 全部功能里的「设置」卡指向已有的 spot。
3. **使用说明和索引对得上**（`guide_nav_test.dart`）。逐行读 `docs/guide/{zh,en}/*.md` 里的 `<!-- nav: … -->`，凡是以 `commonSettings` 开头的链，按 ARB 换成文字后，必须等于某个 spot 的面包屑。这样使用说明不会落后于界面。`guide_sync.py` 现有的 ARB 检查照旧。

**搜索本身的测试**（`settings_search_test.dart`）：
- 「深色」「dark」都找到明暗；
- 「保活」找到后台运行；
- 「别问我」「自动执行命令」都找到权限；
- 「api key」找到账号和联网搜索；
- 「宠物」排第一的是宠物页；
- 不可用的项显示条件；
- 网页模式下没有「问 AI」。

另外有 golden：输入前、有结果、无结果三种状态，浅色和深色各一张，再加 320dp 宽、2.0 倍字号各一张。

### 4.7 低频、高级和开发者项

- **低频项放进所属页面，不上首页**。安全模式、重置、卸载在本机引擎页；检查更新在关于页；分享配置在隐私与分享页。
- **技术参数统一收进「引擎参数」**。子代理、Agent 循环、命令执行，以及插件的命名空间表单，都是改了才知道是什么的东西。首页上只有一行「引擎参数」，值是当前主机。
- **单页里的「更多」**：现在命令执行页已经有「更多」折叠（最长可申请超时等三个字段），这个做法保留。规则是：一页里如果有用户第一眼用不到的字段，就收进页尾的「更多」，不再拆出新页。
- **开发者选项要先解锁**：
  - 连点关于页的「版本」7 次解锁。解锁后，关于页出现「开发者选项」一行，状态存在 `developer.unlocked`。
  - 已经打开过任何一个开发者开关的人，不用解锁就能看到这一行，免得找不到关的地方。
  - 「关闭开发者选项」会把开关全部恢复成默认值，并隐藏这一行。
  - 诊断页只留诊断，给所有人用。

### 4.8 风险项与「问 AI」

**位置规则**：

| 类型 | 例子 | 放哪 | 怎么拦 |
|---|---|---|---|
| 放宽保护 | 完全权限、自动审查、始终免确认、应用名单放宽、访问手机文件 | 所属页里的正常位置（权限页、手机操控页），**首页上一项都不放** | 风险提醒（`confirmRisk`），高档或中档 |
| 会中断工作的动作 | 以安全模式启动、访问手机文件（会重启引擎） | 所属页 | 现有的确认或提示 |
| 删除 / 重置 | 重置运行环境、卸载运行环境、删除渠道、清除 API Key、退出登录、删除 SSH 主机、卸载插件 | 所属页**页底**，单独一张卡，红字 | 现有的居中确认框（「红底 + onDanger + 具体动词」） |

**「不懂？问 AI」放在哪**：和另一个代理的方案（§4.3）衔接，入口只在下面几处。
- **设置 › 帮助与关于 › 使用帮助**：带文字的一行。
- **权限、手机操控、插件、远程主机四页的顶栏 ✦**：44 的圆键，和返回键镜像。前提是使用说明已经写到这一页。另一个代理只列了后三页，权限页要等 `docs/guide/zh/10-settings.md` 补上权限一节后再加。
- **风险提醒弹层**：「不确定？问 AI」。
- **设置搜索没有结果时**：「问 AI：「…」」（§4.5）。

不在每一行上都放「?」，那样会让设置看起来像说明书，也违背「产品文案，不写教程」的原则。

## 6. 需要 owner 拍板

| # | 问题 | 我的建议 | 反对它最有力的理由 |
|---|---|---|---|
| D1 | 首页按 **AI / 能力 / 外观 / 通用 / 主机 / 帮助与关于** 六组 | 采用 | 「能力」这个词偏抽象；「AI」作组名在英文界面下很短，看着有点空。备选是「对话 / 工具 / 外观 / 通用 / 主机 / 帮助」，但「对话」组里放模型和权限，范围会显得过大 |
| D2 | 「自动执行命令」开关**离开首页**，并进权限页的「完全权限」 | 采用：一页看全四个档位，首页也没有放宽保护的开关 | 常用的人要多点 1 下；而且这是 owner 早先放在首页的开关，老用户最先注意到它不见了。旧名字可以搜到，可以缓解一部分 |
| D3 | 抽屉身份栏的「网页版」圆键改成「全部功能」 | 采用：抽屉里本来就有两个网页版入口（品牌行的切换键和圆键），全部功能却没有固定入口 | 习惯点圆键临时开一下网页版的人要多走一步。如果网页版的使用频率其实很高，可以改成三个圆键，但身份栏会变挤 |
| D4 | 全部功能末尾留一组「设置」快捷卡（4 张 + 全部设置） | 留：照顾按官方网页版习惯找功能的人，也照顾老用户 | 边界又模糊了一点。但这些卡打开的是同一页（规则 2），不是另一份 |
| D5 | 开发者选项靠连点版本号 7 次解锁 | 采用：「直接启动本机引擎」打开后可能起不来，不应该让所有人都看见 | 群里的测试者得先知道这个手势。可以在论坛的测试帖里写明；或者改成在诊断页底部长期显示 |
| D6 | 「后台保活」改名「后台运行」 | 改：更像产品用语，「保活」写进同义词 | 「保活」是国产机用户圈的通用说法，一搜就懂；改名后，使用说明和常见问题都要跟着改 |
| D7 | 模型页显式露出「新对话默认」 | 露出，标明「上次选择」：用户常问「怎么让新对话默认用 Pro」 | 引擎的语义是「上次选的就是默认」，用户在任何对话里换一次模型，这里的值就会悄悄变。设置页上的值自己变，看起来像出了 bug |
| D8 | 搜索要不要支持拼音（「quanxian」） | 先不做：中文用户本来就用输入法打汉字 | 有些人习惯打拼音首字母。以后要做，得带拼音表，体积大约 100 KB |

**需要先验证的技术点**（不用 owner 决定，但会影响 S4 和 S6）：
- `agent-default-model` 在远程主机和 DeepSeek 账号路由（`llm-deepseek-account`）下，能不能直接用 `settings/mutate` 写入；写入后，新对话是不是真的会用它。
- 远程主机（SSH、Relay）上，能不能不带对话读到权限的「新对话默认」。现在 `permissionStateProvider(null)` 读得到，但 Relay 还没测过。
- `/plan` 和 `/plan off` 作为开关时，在 Relay 主机上状态能否回读。计划状态现在来自 `session_detail_page.dart:1118` 的 `planActive`。
- 手机操控的 `confirmMode` 改动是否需要重启引擎。现在看不需要，但 ＋ 面板里改完要能立刻回显。

## 7. 不做

- **宽屏双栏设置**（左边列表、右边内容）：骨架现在是 720 列的二级页，双栏要另开一轮设计。
- **每一行都放「?」说明**：违背产品文案原则。「问 AI」只在 §4.8 列出的几处出现。
- **改存储键或引擎命名空间**：只动位置，不动数据。
- **「设置已改版」引导横幅、红点**：靠搜索同义词和更新说明解决。
- **把网页版自己的设置对话框原生化**：网页版的设置在网页版里改；原生侧只搬「通用设置」里已有的六个字段。
