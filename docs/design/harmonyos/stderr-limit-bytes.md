# 私有 Bash 的限额错误保留 stderr 字节

## 问题与修复范围

本项以 530f183 加已复核的 52 号 stdout 控制流补丁为前置。52 号的私有 just-bash 产物 index.js SHA256 为 `4a376233cb86e8cd3c0b1a0601c9a7a8dc816fc428636852aa7702925e18c854`。

当执行限额错误携带此前已经接受的二进制 stderr 时，两个错误出口只复制 stderr 字符串，遗漏其 `stderrKind`。下游因此按普通文本重新编码原字节。原复现先向 stdout 写入 `00ffc3a9800a`，向 stderr 写入 `fef09f98800a`，在嵌套循环中 `continue 2`：总预算 24 字节时完整成功；预算 23 字节时应保留 stdout 的 12 字节和 stderr 的前 6 字节，再返回限额诊断与退出码 126。原实现把这个 stderr 前缀错误编码为 `c3bec3b0c29fc298c2800a`。

修复只在现有、严格计数为两处的 rewrite 规则中复制原 `stderrKind`，并更新固定生成后像 SHA。原错误清理函数 `kt`、执行限额、退出码与已计费字节都保留。`kt` 是诊断清理函数，不是 UTF-8 编解码器。输入类型为 undefined 或 text 时仍保留原来的文本处理规则，不能无条件改成 bytes。

产物通过既有 `build-just-bash.py` 从固定 npm 输入重新构建，未手改生成 JavaScript。新 index.js SHA256 为 `f66202f3ad8a37d18e949be37317d3330538325f5ed7e1e51e54fdf3bcde8fa4`；其余三个受改写模块的 SHA 与前像相同。生成目录不进入补丁。

## 回归与证据边界

`runtime/tests/ohos/process-stderr-limit.test.mjs` 加入原 process/test.sh 完整矩阵。66 项包括十种输出场景的三个执行入口和两个精确预算边界，以及三个迭代限额、三个外层源码大小限额控制。三个入口分别为直接 Bash.exec、字面 bash -c，以及带实际 statement-output 回调的字面 bash -c。

场景覆盖已有非空输出先行交付、首块拒绝、原 23/24 字节复现、函数、子 shell、eval、source、有效中文 UTF-8、跨命令截断 UTF-8 和 0–255 全字节。先行交付场景明确要求存在非空回调，并将回调与最终返回合并检查，防止丢失或重复。测试保留原命令、预算和退出语义；每个新用例阈值为 15 秒，既有测试阈值及断言不变。

在未经修复的同一生产前像上，最终这 66 项普通模式与严格模式均为 40 通过、26 失败、0 取消；修复后两种模式均为 66 通过。严格模式使用固定 Node 24.22.1、jitless、openharmony 模拟平台且无 WebAssembly。10 个脚本另外与真实 `/bin/bash --noprofile --norc` 的完整输出逐字节对照，全部相同；原生 Bash 没有本解释器的预算机制，该对照不证明超限语义。

最初执行的新测试曾把直接 cat 的首块拒绝诊断误写成总输出诊断，得到每模式 39 通过、27 失败。固定 cat 源码在这一路先触发其单命令 5 字节限制，原诊断为 `bash: cat: output size limit exceeded (5 bytes)`。只将这一个控制改为精确原诊断，保留旧测试源与两份原 TAP，再在未改生产前像重新执行，得到上述 26 个真实失败。没有把这项测试预期错误计作产品缺陷，也没有调整任何预算或超时。

完整模块回归、独立复核的最终状态以本项交付报告为准。这里的 66 项不是全模块通过的替代证据，也不是 OHOS 真机验证。

## 与其他在制项组合

该增量不修复 54/55 号独立 open/重定向问题，也不包含 E1 while 条件控制流修复。它不以这些被阻断的补丁为前置。

独立 open v3 改写了相同私有解释器，并可能通过端点收集机制改变限额错误的传递路径。两项的 `changedAfter.index.js` 不同，不能把两个生成后像 SHA 顺序覆盖来组合。最终集成应核对两份精确源变更，重新构建并锁定组合后的 SHA，再运行对应完整矩阵和真实产物门；不能将本项 52 前置上的结果归给未经测量的组合。

Android 路径、上游 npm 包、runtime/ohos/node 和原生构建约定均不在本项改动范围。
