# Workshop Worker: submission, review and public downloads

This implements workshop1 item 7110. `/market/workshop.json` is a new authority and `/market/companions.json` is a filtered projection. Existing pet/adapter catalogs and their upstream cron keep their existing routes and publication objects. Writing user submissions into those old objects would let the next upstream sync overwrite them.

The exact request/response and error contract is in [workshop-api.md](../../services/share-worker/docs/workshop-api.md); the public shape is [workshop.schema.json](../../market/schema/workshop.schema.json). Entries carry a kind. A future wallpaper, launch, theme or card capability adds a kind and its validator without rewriting old rows; old clients must ignore unknown kinds.

## Authority and immutable history

The private BUCKET object `workshop/state-v1.json` atomically holds submissions, current rows, permanent version/owner bindings, withdrawals, reports and audit events. R2 If-Match updates the exact prior ETag; If-None-Match `*` creates it. A loser returns409. A storage failure may have an unknown remote outcome, so the client retries the same creation requestId and reads the known submissionId instead of assuming nothing committed.

Validated ZIPs are create-once private objects under `workshop/blobs/<sha>.zip`, with native R2 SHA verification. Even approved bytes stay private. A blob is not publication evidence. Approval reads/checks its actual size/SHA and revalidates the package with current code before the authority CAS. Draft/orphan/rejected objects have no direct public bucket URL.

The state machine is draft → pending → approved/rejected, with withdrawal from these states and no revival. First approval binds kind/id to the fixed forum origin and numeric user id. Drafts do not reserve names. The kind/id/version SHA+size binding survives upgrades, absent current rows and withdrawal. Reusing identical bytes for an unwithdrawn old version is possible; byte replacement, ownership transfer and revival of withdrawn versions fail. Withdrawing an old version preserves a newer current row while permanently adding blockedVersions. Reports require moderator action rather than automatically removing content.

Every public GET, HEAD, Range and conditional request reads current authority. The path must exactly match a current row; native SHA metadata is also checked on the actual R2 GET/HEAD. Existing serveObject provides streaming/Range and validators; this route additionally handles If-Range. No bare-bucket redirect or public edge-cache bypass exists. Client byte responses are private/no-store, catalogs no-cache/must-revalidate. Companion projection/downloads share the same switch and authority, including old ETags. The main catalog retains all withdrawal records while hiding disabled companion rows.

7113 makes the If-Range date match Last-Modified exactly, as required by [RFC9110 section13.1.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.5), retaining HTTP-second precision for R2 uploaded timestamps. The strong-validator premise remains the immutable content object and actual checksum check. Earlier or later dates ignore Range and send full200 bytes; the less-than-or-equal comparison of If-Unmodified-Since does not apply. An exact strong ETag can yield206, a weak ETag cannot match, and If-Range is ignored without Range. Small regression fixtures cover these branches without changing authority, publication, withdrawal or object verification.

## Identity and operational controls

ADDENDUM-02 requires upload and companion enabled by default. Both are shipped as1 and are enabled if absent. Setting WORKSHOP_UPLOAD_ENABLED or WORKSHOP_COMPANION_ENABLED to0 (or any explicit value other than1) returns the documented stable503 code. Pausing uploads still permits viewing one's records, withdrawal, reports and administrative rejection/withdrawal. Old pet-market routes are unaffected.

User-Api-Key is sent only to the configured HTTPS forum `/session/current.json`, default `https://forum.dshtui.com`, with manual redirects and rejection of every non200 response. Local workerd rejects redirect:error, so that browser/Node option cannot be used. No caller-selected origin, Cookie, Authorization or User-Api-Client-Id is forwarded. Discourse can change a key's associated client id using the latter header. Only a positive numeric id plus bounded username from the current-user response is accepted. Keys are neither persisted nor fingerprinted/logged. The current App's read/session_info scopes can support this check, but do not silently authorize credential transfer to another service: the outer UI must explain and confirm that transfer to the trusted Worker. A future forum-issued audience/operation/SHA/nonce/expiry ticket needs an actual signing/verification service; none is invented here.

Admin routes reuse X-Admin-Key. Audit actor `admin` is a shared credential role, not proof of an individual moderator's identity. Existing rate bindings and KV meters give per-IP burst limits plus approximate per-user hourly limits: five new submissions and twenty archive attempts/reports/withdrawals. Invalid archive attempts count. Existing KV failure behavior is fail-open and cross-colo counting is approximate; this is not a global hard quota.

Required provenance is localized title, author, one of the fixed license choices, HTTPS source and rightsConfirmed=true. Server createdAt records confirmation time. Actions, actor and reason are included in the same CAS. Audit is retained at least186 days; only older events are pruned on later writes. Version, owner, withdrawal and submission metadata are never automatically discarded. No seven/thirty-day bucket lifecycle may target the workshop prefix.

The authority cap is8MiB, with hard maxima of1000 current rows,10000 bindings/submissions/reports,4000 withdrawals and20000 audit events. These are upper bounds, not promised capacity. Each unwithdrawn submission additionally reserves24KiB and each unwithdrawn release12KiB for worst-case UTF-8 withdrawal/audit growth and slots. Ordinary admissions therefore fail earlier with workshop_capacity instead of exhausting the ability to withdraw admitted work. An administrator can withdraw abandoned drafts/pending/rejected submissions to release reserved capacity while retaining their records. Scaling requires a verified archival/sharding migration, not deletion of history or unexpired audit.

## Validation boundary

Pet validation consumes the App's exact rules JSON and pinned Unicode15 tables. Generated code is built, not edited by hand; the validator fingerprint covers code, generator, lock file, rules and Unicode data. ZIP checks cover all central/local headers, paths, NFC+full casefold aliases, intervals, nonregular entries, encryption/compression and bounded actual inflate EOF/CRC/length. JSON rejects BOM, invalid UTF-8, duplicate decoded keys, lone surrogates, nonfinite numbers and excessive nesting. Schema/frame/scale integers, Float32 geometry, animation references and atlas bounds preserve the current App import gate.

PNG validation checks the whole stream: CRC, chunk ordering, color/depth, palette/transparency, contiguous IDAT, exact zlib EOF/Adler32, compressed metadata budgets, Adam7/ordinary scanline lengths and filters, and reconstructs every RGBA sample. IDAT uses a second bounded pass instead of retaining a view per chunk. The full authority envelope is released before ZIP/PNG validation, and current authority is reloaded before CAS.

Intentional stricter upload subsets are compressed ZIP≤20MiB, ZIP32, empty validated directories and a single root/one-folder pack.json plus only referenced PNGs, and provenance matching the submission. The App may import larger or extra-member archives locally; its workshop export must produce this clean subset. The Worker does not repair authored geometry.

Companion accepts character/ data only, with the App's extension allow-list. Runtime code is rejected; index.json is rebuilt by the installer. All members have bounded actual expansion/CRC and strict JSON, and model3 Moc/Textures plus expression/motion/physics/pose/userdata/display references must resolve to existing data inside character/. character.json carries required matching provenance and name/model. Explicitly selected persona/name is the exporter's choice; the Worker reads no preferences. The limits are1000 entries,16MiB per member and64MiB expanded, with the same complete PNG limits.

7112 validates companion JSON one member at a time. The ZIP directory is complete before the loop, so character/model references can be checked against it before the referenced member is read. A helper fully parses and checks one JSON, then returns without adding its object graph to a cross-member Map. Only a validated-character flag, model count and the existing moc-version set survive. Unreferenced data JSON is still fully parsed, every model3 is checked including unselected models, and later members still pass CRC, PNG and moc validation. No file, byte, depth or reference acceptance rule changes; the generated validator fingerprint changes with the revised source. If an invalid archive has multiple independent defects, sequential semantic checks may report a different existing400 validation code first; it remains rejected.

Removing accumulated JSON graphs is not streaming JSON parsing or a whole-isolate memory guarantee. A single JSON still forms a full object graph. Its node complexity and temporary strings, PNG scanlines, zlib concatenation temporaries and buffers held by other requests still require runtime measurement. Losing a live reference does not force immediate collection. [Workers memory limits](https://developers.cloudflare.com/workers/platform/limits/#memory) apply128MB per isolate, and an isolate can handle multiple concurrent requests; the64MiB archive expansion cap is not a heap budget.

MOC3 format enums1..6 are accepted; unknown/future enums fail. The ceiling comes from the baseline's 2026-11-07 historical official Core6.0.1 measurement in `tooling/companion/fixtures/live2d-core-sources-v1.json`, SHA8741…ef47. It was not remeasured here and does not establish the installed App runtime identity. Header/version validation is not Core consistency, full model loading, texture/audio decoding, renderer support or device verification. A moderator must perform those permitted local checks and verify licensing/content before approval. No Core, runtime, model or texture is redistributed.

## Evidence and remaining local verification

The new Node tests replay the App's shared synthetic JSON/ZIP/PNG/parser corpus and exercise identity, idempotency, private review, rejection, permanent bindings/owners, withdrawal, reports, switches, Range/If-Range, checksum failures and CAS races. Local workerd executes the actual bundled validator against the44 existing PNG vectors, a valid pet, exact deflate EOF and output limits. An additional local native R2 API test exercises review/withdrawal, SHA/CAS and Range against synthetic forum responses; its result is reported in the delivery log. A legal2048×2048 RGBA16 PNG at the decoded-pixel ceiling (33,556,480 scanline bytes) succeeds in local workerd. No process peak or combined/concurrent maximum is measured. These are not deployed Cloudflare/R2/Discourse tests.

The supplied snapshot lacks the existing site/share/apple-touch-icon.png, so its ordinary site build fails. A separate temporary SITE_BUILD fixture supplies one synthetic pixel only for test setup; no site asset was fabricated in source. Existing full-suite failures related to missing home assets, executable bits and local tools are reported separately in the delivery README and raw log. Do not claim a fully passing repository suite.

7112 adds small valid multi-JSON fixtures with stored/deflated archives in different member orders, every reference category in an unselected model3, and rejection of late invalid JSON, CRC, PNG and moc data. They check the content contract of sequential validation, not maximum JSON heap use, process peaks or concurrent workloads.

Before deployment, restore baseline assets/modes and run normal npm ci/build/typecheck/test and Wrangler dry-run. Measure complete-route peaks and concurrent workloads against the paid Worker CPU budget and per-isolate128MB memory limit; a pixel-buffer cap is not whole-process memory proof. Check private bucket/no public domain/lifecycle retention, provision ADMIN_KEY outside source, verify test-forum scopes/revocation and explicit credential consent, exercise R2 CAS/SHA/Range/unknown outcomes/switches/withdrawals, and perform App device import, runtime retention, export round-trip and error UI tests. This patch neither deploys nor sends requests to a real forum.
