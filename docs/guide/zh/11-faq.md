# 常见问题

## 发不出消息，或一直没有回复

先看对话列表底部的主机状态。

- **本机**：打开引擎页查看状态和**日志**。没装运行环境、引擎已停止、启动失败是不同情况，按页面提示处理。启动失败时，失败卡片里可以查看日志、导出诊断包。
- **远程主机**：远程主机页会按原因给出修复按钮，如**重新连接**、**重新登录**、**重新信任**。
- 模型没配好时，**选择模型**里会提示填写 API Key 或添加渠道。

重置和卸载会删除本机数据，排查时不必先用它们。

<!-- nav: commonSettings,phoneEngineDiagnostics -->
`设置 › 诊断` · [打开](dshgo://open/diagnostics)

反馈问题时，在这里导出诊断包，包含版本、设备、有限的引擎日志和已捕获的错误；不是全部系统日志或完整崩溃历史。App 会尝试移除 Key 和令牌，但分享前仍需自己检查。

想让 AI 直接帮你查：点 **让 AI 看诊断**，App 会把一份有限快照写给本机引擎，然后问 AI「看下诊断」——内置的 `dsh-go-support` 技能会按症状排查并给出可以直接粘贴的 issue 草稿。

### 闪退与自动故障分析

App 会在本机有界保存错误类别、有限的自有源码位置和语音阶段，不保存错误正文、录音或聊天内容。Android 11 及以上还会尝试读取本应用的历史进程退出原因；系统未提供或记录为空，不代表没有故障，也不是完整崩溃堆栈。

普通本机对话中，可以直接说“查一下刚才的闪退”。支持的版本提供 AI 可调用的诊断工具，能刷新并按段读取，不需要手动导包、开启手机操控或授予无障碍权限。安全模式或旧运行时不支持时，仍可读取已发布快照；缺少证据时再按提示导出。

**自动故障分析**默认关闭。开启前会明确告知：故障发生后，仅在 App 前台、本机引擎正常连接时，将白名单内的版本、设备系统信息、错误类别、源码位置、语音阶段和退出原因发送给本机引擎配置的模型服务商，可能产生模型费用；不发送聊天正文、录音、凭据或原始日志，不采集系统输入法证据。App 闪退时要等下次打开并连接成功后才能分析。

分析使用独立的无工具对话，不切换当前聊天、不执行修复、不公开提交 GitHub。相同故障会合并，失败或结果不明时不会自动重试。这里能看到状态，点报告入口读取分析结果。关闭、切远程主机或进入后台会阻止新请求并尝试停止已有分析；已经发送的信息和生成的对话无法撤回。

本地分析记录无法读取或保存时，会暂停自动分析，并显示恢复入口。恢复只在本机进行；会跳过当前已留存故障，不重发旧请求，成功后再处理未来的新故障。恢复失败仍保持暂停，不循环重试。

### 输入法或键盘异常

复现后，在 **系统输入法诊断** 点 **采集本次日志**，阅读原生弹窗并亲自确认。它只复用已经选定并连接的 Shizuku、Sui、无线调试或 Root 通道，不自动申请权限、启动后台屏或操作输入框；没有通道时，可以自行选择 **手机操控权限设置（可选）**。

采集会短暂限读固定标签的现存系统日志，只保留最近2分钟、最多64条由本 App 进程输出的显示/隐藏请求或输入连接关闭事件，不导出输入正文、候选词或原始日志。Android 12 或部分系统可能没有匹配记录；0条和失败都不能证明输入法正常。采集是一次性的，不会持续监听。将 App 置于后台、离开诊断页或点清除会取消；多窗口下诊断页仍可见时，仅切换焦点不会撤销已经同意的这一次短读取。

结果仅留在 App 内存；点 **让 AI 看诊断** 或手动导出诊断包时才加入，自动快照不会加入。手动 AI 报告与自动环境快照分别原子保存到固定文件，互不覆盖。可以清除内存证据，重启 App 后也会消失，但不能撤回已经生成或分享的文件。

## 切到后台后引擎被关掉，或收不到通知

<!-- nav: commonSettings,phoneEngineKeepAlive -->
`设置 › 后台运行` · [打开](dshgo://open/background)

按指南关闭电池优化、保留「引擎运行中」通知、在最近任务里锁定 App。各品牌限制不同，做完这些仍可能被系统结束。

通知还要在 App 的**通知**里开启对应提醒，并在系统设置里允许 DSH Go 通知。远程主机的提醒需要 App 在运行、连接在线。

## 引擎反复启动失败

本机引擎页的**自动进入安全模式**默认开启：连续两次启动失败后，自动不加载插件启动。也可以在同一页点**以安全模式启动**。安全模式下对话都在，修好配置后点**恢复正常模式**；安全模式期间在网页版改的设置不会保留。

直接启动本机引擎默认关闭，在开发者选项里手动打开。打开后，某台手机上直接启动起不来（例如 Android 16 会拦截）时，会自动改用兼容启动，不算一次启动失败，也不进安全模式；之后一直用兼容启动，直到 App 带来新的运行环境。**诊断**页会显示**直接启动未成功**。想再试，先停止本机引擎，再在诊断页的**开发者选项**里打开**直接启动本机引擎**。

从旧版本升级后，第一次直接启动前会把插件文件整理一次，引擎显示**正在整理插件文件**，只做这一次。手机空间不够或整理没做完时，这次先用兼容启动，**诊断**页的**兼容启动原因**会写明，下次启动接着整理，文件不会丢。

**tawcroot 加速启动**也在**开发者选项**里，默认关闭，和直接启动二选一。打开后本机引擎改由 tawcroot 运行：启动快约三倍，装包和 apt 也更快。起不来时自动改用兼容启动，同样不算启动失败，**诊断**页显示 **tawcroot 未启动成功**；想再试，停止本机引擎后重新打开。关掉之后的第一次启动，会先把它留下的硬链接整理成普通文件，引擎显示**正在整理插件文件**；手机空间不够时这次启动会报错并写明还差多少，腾出空间或重新打开 tawcroot 即可，文件不会丢。

## App 能对话，headless 命令却报 MISSING_CREDENTIAL

`dsh --profile headless` 启动独立的一次性任务。默认配置不启用交互式凭据存储、授权和 DeepSeek 账号服务，因此不会自动使用 App 里保存的 API Key 或账号登录。App 能对话，不代表这条命令已经配好凭据。

默认的 DeepSeek 官方 API 路线需要 `DEEPSEEK_API_KEY`。在启动命令的进程环境中提供它，或在启动目录的 `.env`、`$DSH_HOME/.env` 中按 `DEEPSEEK_API_KEY=...` 的格式配置自己的 API Key。读取优先级依次为进程环境、启动目录的 `.env`、`$DSH_HOME/.env`；导出的空变量也会挡住 `.env` 回退，改用文件配置时先取消该空变量。不要把真实 Key 放进对话、问题反馈或提交到代码仓库。

如果 App 用的是 DeepSeek 账号登录，它和官方 API Key 是不同的凭据；账号登录令牌不能填进 `DEEPSEEK_API_KEY`。可以继续在 App 中使用账号，或为 headless 单独配置 API Key。

只叠加 App 的登录补丁不会启用 headless 默认关闭的服务。自定义 profile 或远程主机采用不同配置时，以那台主机的实际配置为准。

## 手机操控用不了

手机操控页顶部会写明还差什么：

- 开关没打开，或引擎还没启动。
- 当前连的是远程主机：切回**本机**。
- 没有本机运行环境：先安装。
- 在安全模式下：恢复正常模式。
- 无障碍没打开：点**去开启**；侧载的 App 先「允许受限制的设置」。

任务中途停了：熄屏、锁屏，或 DSH 连续 3 分钟没有新的操作，都会结束任务。见 [手机操控](04-phone-control.md)。

## 悬浮条挡住了屏幕

按住悬浮条拖到不碍事的地方（左边、中间或右边，任意高度），或拖出屏幕边收成小球；也可以点它左端的圆点（或卡片里的**收成小球**）。**闲置时自动收起**默认打开，胶囊闲置几秒就会自己收成小球；小球闲置时变淡并缩进屏幕边，调低**闲置时不透明度**让它更淡。

## 宠物不见了

- 对话里看不到：宠物页选了**不显示**时，重新选一只；还在「藏起来 1 小时」里时，点**立即显示**。
- App 外看不到：检查**App 外显示**是否打开、是否已允许悬浮显示。**显示时机**默认是**有事时显示**，5 分钟没有动静就会隐藏；被「今天不再显示」时，在宠物页点**恢复**。App 在前台、手机操控进行中时也会隐藏。

见 [宠物](06-pets.md)。

## 插件装好了，界面里看不到

先确认插件已启用，需要时重启引擎。插件的原生界面需要主机带有 dsh-go 桥接：本机引擎自带，远程主机一般没有。插件详情里也可能关掉了某个显示位置。没有原生界面的插件面板会出现在「全部功能」的插件分组里，在 App 内打开或以「网页版」入口打开。见 [插件](08-plugins.md)。

## App 会发送哪些数据

<!-- nav: commonSettings,hubPrivacy,usageStatsTitle -->
`设置 › 隐私与分享 › 发送匿名使用统计` · [打开](dshgo://open/usage-stats)

dsh-go 自身的匿名使用统计默认开启，第一次打开 App 时的欢迎页上就有这个开关；从旧版本升级的，第一次回到首页时会在底部提示一次，可以当场关闭。开启时，每天最多发送一次前几天的匿名统计，只有这些：App 和 Android 版本、CPU 架构、手机品牌和型号（如 `V2405A`，1.0.15 起）、厂商系统及版本（如 OriginOS 5.0，1.0.15 起）、界面语言、本机引擎的启动方式，以及当天发了几条消息、用了几次语音输入（把说的话转成文字填进输入框，不含语音通话）、手机操控和生成、分享了几次、装了几个插件。1.0.17 起还有：在酒馆里发了几条消息、打开了几次伙伴小屋、接通了几次语音通话，以及当天模型回复里报告的输入和输出 token 总数（只用服务商在回复里给出的数，没给的渠道不计，也不估算）。设备之间用一个随机编号区分，每 90 天换一个。

这项统计不含账号、API Key、对话、角色卡、文件、提示词、主机地址、用的是哪个模型，也不含手机号、IMEI 这类设备标识。关闭这个开关后不再发送这项 dsh-go 统计，随机编号和本机记下的次数立即删除。

## 本机文字识别与 Google ML Kit

<!-- nav: commonSettings,hubSettingsPhoneControl -->
`设置 › 手机操控`

手机操控使用内置的 Google ML Kit 中文文字识别（`com.google.mlkit:text-recognition-chinese:16.0.1`），默认开启，可以展开这一页的 **更多设置**，在 **文字识别** 里单独关闭。识别在本机进行，截图和文字不会发给 Google；Google 的 SDK 会收集机型、应用版本、耗时等使用统计。上面的匿名统计开关不控制这个 SDK。

手机操控可能将截图和识别文字发给你配置的模型。关闭时，识别请求不会触发 SDK 加载或初始化。关闭本机识别后不再开始新的识别，已经开始的工作可能仍在收尾。关闭不会卸载 SDK、清除此前积累的 SDK 统计，也不保证历史 SDK 统计停止发送。从未初始化过 SDK 的设备，与此前开启并使用过识别的设备，历史状态不同。

Remote 的「扫码配对电脑」也使用 ML Kit，在打开扫码界面时独立按需初始化；相机扫码和相册识码不要求先使用手机操控或开启文字识别，也不会改变本机文字识别开关。不想为配对使用 ML Kit 时，可改用 Remote 账号登录方式连接主机。

参见 [Google ML Kit 条款](https://developers.google.com/ml-kit/terms)和 [Android SDK 数据披露](https://developers.google.com/ml-kit/android-data-disclosure)。SDK 条款与文档示例代码的 Apache 2.0 许可证不同。
