# Web 插件面板入口

注册 `sidebar.panellist` + `main` 的 Web 插件仍可从「全部功能 › 插件」进入。

对话详情页也提供入口：如果当前主机没有可见的对话专属插件页签（`sidebar.right.pane.tab`），「插件」页签会显示 `main` 面板。一项直接打开，多项先列出面板。已有对话专属页签时仍以它们为准，全局面板留在「全部功能」中。

全局面板保持根作用域，不传当前 `sessionId`。同一槽内仍按原规则选择原生面板、Web 岛屿或「在网页版打开」；原生面板不会因为这个入口而多出 invoke 权限。没有可显示内容时不出现空页签。

面板名称优先取 `main` 条目的名字，再找同插件、同 cell 的 `sidebar.panellist` 名字，最后使用插件名。请为侧栏条目提供简短、明确、和别的面板不重名的名字：App 按名字在网页版侧栏里找它，同名时不猜，直接换成「在网页版打开」。插件设置分区（`settings.section`）同理。

## 对话视图

在 DSH Web 里给对话注册了 View（`conversation.view`，和 Chat、Trajectory 并列的另一种看法）的插件，在 App 里出现在这个对话的对话详情 › 「插件」页签，和对话专属页签排在一起：先页签，后视图。一项直接打开，多项先列出。

- 名字取注册时的 `label`。App 按名字在网页版的 View 标签行（或「更多会话视图」菜单）里找到它，再按 View 的 id 确认打开的就是它，所以请给它一个简短、独一无二的名字：和别的 View 同名时，App 不猜，直接换成「在网页版打开」。
- 整页岛，只在这台手机自己的引擎上、主机有桥接占用表、路由守卫生效、资源预算够时打开；打开时先显示加载骨架，12 秒内没显示出来就换成「在网页版打开」，打开的是这个对话。
- App 只在岛里点选这个 View，不改用户在网页版里选的 View：岛显示后和离开时把原来的选择写回。
- 官方的 Chat、Trajectory 不出现在这里。

## 聊天页「插件」弹层

聊天页输入框上方胶囊行的最后一枚胶囊「插件」（拼图图标）打开这个对话的插件弹层。它只在弹层有内容时出现，不占胶囊 8 个的名额，生成回复时和整行一起让位。

若要隐藏这个 App 绘制的入口，在 `$DSH_HOME/dsh-go/ui.json` 的现有 `hide` 数组中加上 `pluginCapsule`，例如 `{"version":1,"hide":["pluginCapsule"]}`。删除这一项或在界面配置页恢复默认即可重新显示。它不停用插件，不隐藏插件自己的快捷胶囊，也不移除「全部功能」或「对话详情」中的面板。`plugins.seats` 控制插件槽位；`chat.panel` 和 `dsh-go.panel` 都不是这枚 App 胶囊的名字。

弹层里先是原生面板（`placement: "chat.panel"`，按插件名排），再是网页插件放在聊天页的部件：这 7 个 slot 的第三方条目——`conversation.session.header.actions`、`conversation.session.header.utilities`、`conversation.input.dock`、`conversation.input.left`、`conversation.input.right`、`conversation.input.overlay`、`conversation.composer.dock`。它们装在**一个**面板岛里，按网页上的顺序竖排，官方条目已遮掉；岛上方一行写着是哪些插件的。

- 岛在打开弹层时才建，关掉 30 秒后回收，不拖慢聊天页。
- 只有每一项都能单独做成岛（本机引擎、桥接占用表、路由守卫）、没有被 `ui.json` 改成 `web` 或隐藏、预算够时才建；否则、或 8 秒内没显示出来、或网页说找不到，都换成一行「在网页版打开」。
- 岛里的条目没有逐条标记，所以 App 不能只隐藏其中一个插件的；`ui.json` 改了其中一项，整块就走网页版。

## 插件详情「网页版界面」

插件详情的「App 内界面」提供网页接缝的控制与入口；浮层开关名为「聊天页浮层」：

| 网页 slot | 详情页行为 |
|---|---|
| `shell.overlay` | 逐包显式启用 / 关闭 App 内浮层，默认不显示 |
| `sidebar.footer.action` | 打开本插件所选条目的整页岛，显示侧栏底部按钮 / 入口 |
| `settings.plugins.tab` | 打开本插件所选插件设置页签的整页岛 |
| `plugins.detail.section` | 打开本插件详情分区的整页岛 |

后三类每次只显示所选包、所选 cell，不把所有第三方插件混在一起，也不把网页按钮搬进原生抽屉。设置页签需要能核对选中状态，插件详情分区需要能定位所属包；找不到、同名歧义或打不开时，不假装成功，仍给「在网页版打开」。请注册稳定且唯一的 `id` 和简短、明确的 `label`。

其他尚无座位的位置（如消息级部件）仍逐行列出并打开网页版。上面的对话视图和聊天页部件另有入口。没有占用表的主机只显示一行，说明插件有网页部分。

## App 内网页浮层（`shell.overlay`）

在插件详情启用后，App 只允许该包被启用的 `shell.overlay` cell 显示；官方、未启用包及无法确认归属的条目不会一起放出来。开关是**本机、按主机保存的偏好**，切换主机分别生效，不改写主机配置。`ui.json` 的 `plugins.seats` 里对该 slot / 包显式配置的值优先于本机开关；被配置控制时，应先修改那份配置。

例如，主机配置 `{"version":1,"plugins":{"seats":{"shell.overlay":{"dsh-go-example-overlay":"island"}}}}` 显式启用该示例；把 `island` 改为 `hidden` 则关闭。合并到现有配置，不覆盖其他键。

- 浮层挂在 `HomeShell.chat` 内的 `ChatScreen`，视口由 `ClipRect` 严格裁在原生顶栏与输入框之间的聊天内容区，不覆盖原生 chrome、抽屉、右侧详情或原生模态。有未决审批或未答问题时停止浮层；离开聊天页也不显示。它不是 Android 跨 App 悬浮窗。
- 空白区向下穿透，命中的是网页上报的**矩形区域**，不是按图片 alpha 或像素透明度抠图。透明图片的矩形内部仍可能接走触摸；快速运动时触点 / 命中区会有采样和桥接滞后，不保证紧贴动画。
- 插件应让根容器不接触摸（`pointer-events: none`），只给真实可交互元素设置 `pointer-events: auto`，不要用透明的全屏元素挡住聊天页。保持交互区域小而稳定。
- 键盘出现时，可用聊天内容区随原生布局收缩，浮层视口也跟着缩小。CSS `--dsh-go-island-top` / `--dsh-go-island-bottom`（像素 inset，网页里用 `0px` 回退）仍可读取；在已保留原生 chrome 的内容区内可以为 `0`，不要再扣一次顶栏 / 输入框高度。这不是插件可控制的原生布局。
- 仍需本机引擎、可核对的桥接占用表、路由守卫和资源预算；启用偏好不绕过这些条件。失败时保留网页版入口。
- 音频仍遵守现有 WebView 用户手势要求，不自动开启免手势播放。本轮不是新增原生 `pets` / `bubbles` / `actions` 协议。

参见无额外依赖、无构建链的[网页浮层与三槽示例](../../examples/plugins/dsh-go-example-overlay/README.md)。本轮没有安装或运行该插件，也未做真机验证。

## 完整网页版的触控尺寸

在 App 的完整 DSH Web 页面里，开启「网页版手机布局」且浏览器报告粗指针（`pointer: coarse`）时，`[data-slot="main"]` 内的 `button`、`[role="button"]`、`select` 和 `input` 使用 **44 × 44 CSS px** 的最小尺寸。`main` 也包含官方对话，因此该规则不只影响插件页。细指针不增加这层尺寸规则；关闭手机布局时不注入它。独立 Web 岛屿和 Flutter 原生面板不走这份样式。

`role="switch"`、`role="slider"`、`input[type="range"]` 和隐藏元素不改变显示方式；开关和滑轨保留原尺寸。普通 HTML checkbox / radio 也受最小尺寸约束。默认行内的 `a[role="button"]` / `span[role="button"]` 提供 `inline-block` 默认值，使最小尺寸能生效；整段默认 layer 样式放在页面已有样式之前，让作者自己的 `display` 规则仍优先。显式行内布局和固定尺寸包装容器应由插件自行核验，不应假定宿主会改写其内部布局。

在任意祖先或控件上设置 `data-dsh-adapt="off"`，即可让该子树保留自己的控件尺寸和显示方式，放在 `html` 或 `main` 上同样有效：

```html
<section data-dsh-adapt="off">
  <!-- 此处由插件提供足够的命中区域，并为邻居保留空间。 -->
</section>
```

该属性只退出这层触控尺寸，不关闭手机布局的安全区、抽屉等规则。尺寸下限会占用实际布局空间；使用可容纳或换行的行容器，别把增大的控件裁在紧凑包装盒里。若插件自己管理点击区域，应使用上述 opt-out，而不是依赖宿主插入 DOM 或修改事件处理。

## 主机与降级

- 岛屿仍要求主机可提供 Web 页面，并通过现有路由门控和资源预算。
- 岛屿无法打开时使用已有的 DSH Web 入口；它会打开侧栏，让用户选择面板。现有 Web 打开桥没有第三方面板的深链 id，因此不承诺直接定位任意插件 cell。
- 没有 Web 页面的中转主机不显示仅 Web 面板。

## 资源与兼容边界

旧普查中约 19% 的包使用过 `shell.overlay`，只是静态 slot 用量，不代表这些插件都能免改可用。宿主内部状态、全屏事件捕获、自定义弹层或浏览器 API 仍需逐个核验。

首岛约 200 MB（含渲染进程与 App 增量）、冷开约 1–3 秒仅是 Android 15 x86_64 debug 模拟器上的估测；真机未验证，不代表 release、其他 ABI 或每个插件的成本。

## 尚未开放

此入口没有增加 `ui.json` 的 `plugin:` 页面引用、跨插件 `open` 别名或 `dsh-go://panel/…` 深链。原生 `open` 效果仍只能打开 App 支持的页面或本插件的 `panel:<id>`。这些能力需要另行定义可校验的目标、生命周期和权限边界。
