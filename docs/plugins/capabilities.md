# 能力边界

一页回答「插件能做什么、不能做什么」。细节在各篇文档里，这里只给总表和边界。

## 能做

| 能力 | 要写的 | 读 |
|---|---|---|
| 工具结果显示成原生卡片 | 工具 `presentationMeta` 里加视图（任何主机） | [快速开始](quickstart.md) |
| 原生位置：胶囊、消息菜单、状态条、面板、加号工具、对话操作、回合尾注 | `package.json` 的 `dshGo` 清单 + `ctx.dshGo` | [插槽参考](slots.md) |
| 命令、技能、设置表单、dsh-ui 卡直接原生显示 | 不写 App 代码 | [不写代码就原生显示](native-for-free.md) |
| 网页界面、聊天内容区网页岛（`shell.overlay`） | 客户端入口 + slot 注册 | [网页面板](web-panels.md) |
| 选择文件/图片（NA v1.3，可选） | `capabilities: ["files"]` + `pickFile`/`pickImage` | [选择文件](files.md) |
| 朗读、开口即停、字幕（v1.2，可选） | `media`/`micro`/`overlays` + `caps` | [声音与字幕](voice.md) |
| 受限视图：v1/v2 组件、双向绑定、有界公式 | JSON 视图 | [组件目录](components.md)、[输入与表单](inputs.md) |
| 点按后的 8 种效果 | `effect` 声明 | [动作与效果](actions.md) |

## 不能做

| 不能 | 说明 |
|---|---|
| 控制宠物或伙伴小屋 | 协议没有 pets/bubbles 位置；内部设计稿里的 `pets` 字段**未实现**，不要当文档 |
| 跨 App 悬浮窗 | `shell.overlay` 只是聊天内容区里的网页岛，不是系统悬浮窗 |
| 发系统通知 | 没有通知 API |
| 弹审批卡、改权限 | 审批属于引擎，插件不能代答或跳过 |
| 装卸插件、切换主机、改会话语义 | 没有这些 API |
| 后台常驻或自动触发 | 由用户点按、宿主事件调用；代码在一次调用里启动的定时器或流，调用返回后可以继续跑（朗读示例就是边读边计时），但没有后台服务，也没有让插件自己醒来的接口 |
| 换 App 主题、图标或整体界面 | 只有受限样式和插件座位声明 |
| 在 App 进程里执行插件代码 | App 只画声明和 JSON 视图；插件代码在引擎里跑 |

## 两种 overlay 别混

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| `capabilities` 里的 `overlay` | App 画的一行字幕/浮动文字（v1.2） | 不是网页、不是系统悬浮窗、不是宠物 |
| `shell.overlay` 网页岛 | 聊天内容区里的一个网页，受容器约束 | 不是跨 App 悬浮，不能盖住其他应用 |

## 能力依赖与降级

- 原生插槽只在带 dsh-go 桥接的主机上出现：本机引擎自带，远程主机一般没有（SSH/中转只有工具卡）。
- 较新的位置与能力取决于 App 和桥的版本；用 `caps` 判断能力，不要假设存在。
- 旧 App 会忽略不认识的键；只放在新位置的面板退回 `session.tab`，不会消失。

## 未来项（未实现，不要依赖）

`pets`/`bubbles`/`actions` 清单字段、插件控制宠物、系统通知、后台常驻、跨 App 悬浮。
