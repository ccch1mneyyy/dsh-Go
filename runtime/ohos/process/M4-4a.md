# M4-4a：明确的工作区根与临时根收尾

本项处理 M4-4 中能够独立闭合的三个要求：宿主必须显式配置工作区根；无票据的直接调用不能取得宿主的所有工作区；正常 dispose 清理后端自己创建的临时根。另给真实 DSH grep / glob 补上会话根票据，使安全收窄不妨碍合法的会话父目录搜索。

**符号链接越界诊断仍未完成。** 原文件系统和 Worker 保持已审字节，未混入此前的 `cat` 包装或解释器重定向尝试。完整 M4-4 的旧七项断言仍单独运行并保留诊断失败；不能以本分项的通过替代整个 M4-4 完成。

## 宿主与 profile 的启动契约

宿主或明确的 profile 必须向 `OhSubprocessRuntime` 的第二个构造参数传入 `workspaceRoots`。这是后端配置字段，不是环境变量，也不是由运行时自己从当前目录推导的默认值。例如：

```js
await ctx.plugin(OhSubprocessRuntime, {
  workspaceRoots: [authorizedWorkspacePath],
  // 可省略：省略时后端创建并拥有自己的私有临时根。
  temporaryRoot: explicitlyProvidedTemporaryPath,
});
```

`authorizedWorkspacePath` 必须来自宿主实际授予的工作区。不能为了通过新检查而机械填写继承的 `process.cwd()`、用户 home 或 `/`。`runtime.mjs` 构造函数已经移除 `workspaceRoots = [process.cwd()]`：未传、空数组、相对路径、整个文件系统根、文件或不存在的目录都拒绝。每个根经 realpath 转为实际目录，再去除重复与被更大授权根包含的项。配置验证发生在 mkdtemp 前，配置失败不能产生新的临时目录。

显式 `temporaryRoot` 也必须是存在的绝对实际目录，不能是 `/`。它由调用者拥有，dispose 保留它及其内容。没有提供时，后端通过 mkdtemp 创建目录，保存精确路径及 BigInt `dev` / `ino`，只对该目录承担清理责任。

本项修改的是后端要求；目标 OHOS 宿主实际如何获得用户授权路径、HAP 目录权限与设备行为尚待对应宿主集成和真机验证。旧的实验 profile 不因本文自动成为产品入口。

## 一次调用拿到哪些根

| 调用 | 工作区范围 |
| --- | --- |
| 无 `prepare` 的直接 `spawn` | 本次规范化 cwd；不从多个宿主根中猜测会话身份，也不自动授予其父目录 |
| `prepare(argv, { mode, workspaceRoot }, signal)` 后的调用 | 明确的会话 workspaceRoot；必须处于宿主授权范围 |
| 真实 DSH grep / glob，存在 agent | 使用 `agent.session.header.cwd` 建立 `read-only` 票据 |
| 真实 DSH grep / glob，没有 agent | 使用本次 cwd 建立只读票据，仍须通过宿主授权检查 |

所有调用继续使用后端既有的 `temporaryRoot`，本项没有把它改成逐任务目录。无上下文的直接调用只能保守限制到 cwd；这不等于获得或认证了某个 Session 的完整根。

启动时还检查实际 cwd 必须落在这张票据允许的范围内。宿主同时授权 A、B，不表示 A 的票据能够在 B 启动。真实 `WorkingDirectoryService.set()` 可以改变会话的当前目录，但不改变创建时的 Session header；新搜索接缝据此阻止通过改 cwd 扩大工作区授权。

`zzzzzzzzz-ohos-search-confinement.diff` 只在 OHOS 集合中。已有 agent 却没有合法绝对 `header.cwd` 时明确失败，不用当前 cwd 补造授权。后端没有 `prepare` 时也明确失败，不悄悄退回普通 spawn。保留原 `--no-config`、固定 argv、输出上限、超时/取消信号及 `SEARCH_*` 错误分类；底层 EACCES 或缺失契约保留为 cause。

Android 集合没有该后置补丁。普通 Android 运行时也不会因为旧 `DSH_GO_OHOS_SIM=1` 环境变量进入本分支；门控仍只有真实平台或显式进程内标记。

## dispose 的顺序与边界

dispose 先关闭入口并清除未用票据，终止两条队列中的活跃任务，取消未启动任务，再等待每个 Worker 的真实退出。原 OutputCollector 在完成事件中同步 seal；这些步骤完成后，才检查自有临时根的文件身份并删除。

重复 dispose 复用同一次收尾。目录已不存在视为已完成；若同一路径已被不同 inode、普通文件或符号链接替换，则返回 `ERR_OHOS_TEMP_ROOT_REPLACED` 并保留替换物。没有按名称前缀、时间或空目录状态扫描其他路径，也不删除调用者提供的临时根。

测试验证了包含封闭 spill 文件和指向外部目录的符号链接的自有临时根：spill 随自有目录清理，外部目标保留。双 lane 测试使用测试专用预加载握手：搜索 Worker 在真实 FileHandle 读取完成后暂停；执行 Worker 已真实写入 ready 文件并进入长命令。两者都到达边界后才 dispose，同时提交的两个排队任务也必须不运行，返回时自有临时根和后续写入均不存在。

这些证据覆盖正常 dispose，不能外推为整个 App 被 SIGKILL 后的自动恢复。归属记录仍在内存中，不扫描回收前次进程的未知目录。身份检查和删除也不是可防御任意外部并发重命名者的内核事务；应用私有临时父目录不能交给未受信任的外部写入者。原文件系统仍是 JavaScript 受限适配层，不是内核级沙箱。

## 验证与剩余项

新增根/生命周期 12 项在旧 M4-2 runtime 上为 5 PASS / 7 FAIL，新版 JIT 与严格 O0 均 12/12。先失败确实读到了另一个会话文件，不能用错误码变化冒充权限修复。测试草稿曾断言 Promise 对象身份，最终改为验证重复调用的实际收尾结果；两次旧记录都保留，正式前后对照使用同一最终测试文件。

真实搜索 7 项使用固定 DSH 的 `Session`、`WorkingDirectoryService`、`LocalFileSystem`、`Context` 和公开的 `runRipgrep` / 模板 / 解析函数。新 runtime 配旧 provider 为 2 PASS / 5 FAIL；接入票据后 JIT 与严格 O0 均 7/7。它既验证 A/sub 仍可搜索 A 的父目录，也验证 cwd 改到 B、缺少原始会话根和缺少 prepare 时明确失败。

原集成测试中的十个空 `agent: {}` 夹具改为带真实不可变 Session header 的值，原语义断言没有删除或放宽。既有 Android 条件对照 3/3、JIT 49/49、严格 49/49；原 M4-2 双队列 5 项在两种模式均通过。源码、日志、完整 DSH 树对照和独立复核状态均随本包记录，作者结果不代替审查结论。

工作区外符号链接仍可能被 just-bash 显示为 No such file；M4-4b 原始失败断言、输入重定向/cd 的反例以及未改上游的 Unicode stderr 最小复现保持 BLOCKED。此处没有更改错误处理、shell 的 `||` 恢复或重定向行为。
