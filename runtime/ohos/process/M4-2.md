# M4-2：将直接搜索和命令执行分开排队

本项只改变虚拟进程调度，不增加命令、权限、运行时依赖或全局改写。输入为17号O4a v3及23号O4仿真标记迁移；后者对应 runtime.mjs SHA256 `19a8989ad5f54ab1f9c73fcd617fbb57d143e638fe34c47e423fcdc070bfa311`。未在鸿蒙设备核实。

## 选择与代价

每个 VirtualSubprocessRuntime 固定两个 FIFO 队列，各自最多一个活跃 Worker：直接 `rg` 属于搜索队列，其它命令属于执行队列。分类发生在受限票据解封之后，并使用现有 commandName 白名单，所以允许的绝对路径别名和 prepare 后的 rg 同样可用，伪造路径不获得搜索槽。

相比把所有任务放进2到4个通用槽，分开排队能保留现有写操作的串行关系，以及后继Git元数据收尾的必要前提，同时解除长bash对grep的排队阻塞。bash/sh脚本内部即使只调用rg，也留在执行队列：同一脚本还可能包含重定向和后续写入，调度器不猜测脚本的副作用。未来node/git命令若按现有入口启用，也会先落到执行队列；本包没有提前启用它们。

总上限是**每个服务两个Worker**，不是应用任意创建多个服务时的全局上限。每个Worker沿用256MiB old-generation限制；这不等于RSS上限，也不保证两者合计RSS小于512MiB。多一个解释器线程会增加内存和CPU负担，固定2是解除已复现阻塞所需的最小槽数，未把上限提高到4。

搜索现在可能与一个写任务或外部编辑器同时读写同一文件。它是实时文件搜索，不提供快照一致性；既有路径校验与后续文件操作之间也仍存在已记录的宿主文件系统竞态。取消不回滚已经产生的副作用。M4-4的会话根/链接错误/临时根清理问题、M4-3的大行内存问题、Git硬终止残留均由独立子项处理，本包没有宣称消除这些问题。

## 生命周期

每个任务保留原done、terminate、waitForExit和OutputCollector契约。只有对应Worker的exit事件完成后才释放本槽；排队取消不创建Worker。失败只释放本任务所属队列，不阻塞另一队列。dispose先关闭服务入口，终止所有live任务，清空两个尚未启动的队列，然后等待所有Worker退出；这里没有新增定时轮询或自行延长生产执行预算。

## 真实先失败与修复验证

测试先让实际bash写出ready文件再sleep 30秒，确认它已进入用户脚本；提交两个写任务和一次直接rg。旧版在8秒搜索验收预算内始终未完成，严格O0得到0PASS/1FAIL，错误为“直接搜索仍在等待长 shell”。没有仅根据源码中queue字段推断阻塞。

同一断言在修复上通过：搜索完成时长shell仍未退出，两个写任务尚未写order；终止长shell后，两个写任务按first、second顺序落盘。一次严格样本搜索335.989347ms，JIT样本321.064494ms。它们是单次当前宿主观察，不是设备延迟承诺或严格调度上界。RSS打印值只是该时点整个进程的样本，不是峰值或修复前后差值。

新增5项测试还实际覆盖：prepare票据与三个合法rg绝对别名；脚本内rg仍留执行队列；搜索提交顺序、排队取消；两个队列各自错误后的恢复；dispose等待已经创建的两类Worker退出、排队任务不运行。最后一项在Worker创建之后立即dispose，证明创建/退出收尾，不声称两个用户脚本都已进入主体。

作者结果：新增JIT5/5、严格5/5，均0skip/TODO；原完整O4套件Android3/3、JIT43/43、严格43/43。独立裁决必须另见绑定最终补丁SHA的只审不做报告，作者结果不能代替它。完整App同O0b回归由主代理单独记录。

## 复跑

沿O4原安装步骤，用固定Node24.22.1与私有、已装配的DSH prefix。无需新增npm依赖。先保留原套件：

```sh
export NODE=/path/to/node-v24.22.1/bin/node

OHOS_TEST_PROCESS_PREFIX=/path/to/ohos-patched-prefix \
OHOS_TEST_BASE_PREFIX=/path/to/original-prefix \
OHOS_SIM_PRELOAD="$PWD/runtime/ohos/sim/preload.mjs" \
bash runtime/ohos/process/test.sh

env -u DSH_GO_OHOS_SIM "$NODE" --import ./runtime/ohos/sim/marker.mjs \
  --test --test-isolation=none runtime/tests/ohos/process-concurrency.test.mjs

env -u DSH_GO_OHOS_SIM "$NODE" --jitless --import ./runtime/ohos/sim/preload.mjs \
  --test --test-isolation=none runtime/tests/ohos/process-concurrency.test.mjs
```

全部日志与实际完整命令在交付evidence中保留。新增测试无需child_process，严格O0仍禁止spawn、默认禁止dlopen、删除WebAssembly并让link报EACCES；没有用桩模拟worker或把失败断言删去。

依据为锁定DSH的subprocess handle契约、Node24.22.1的Worker/exit语义及本包真实测量。读写实时性与内存代价是由两个独立解释器同时运行推得的限制，不是已完成真机压力测试的结论。
