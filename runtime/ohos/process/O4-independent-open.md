## 为什么旧修复不够

最初的反例是两个独立目标依次写入同一路径：

```sh
{ printf ABCDEFGHI; printf 123 >&2; } > result.bin 2> result.bin
```

真实 Bash 得到 `123DEFGHI`。两个目标都在打开时截断文件，各有从零开始的位置；第二次写入只覆盖头部。精确 52 的结果交付阶段再次整文件截断，错误地得到 `123`。旧 54 去掉了这次多余截断，但仍等整个复合命令完成后再写两路缓冲。因此独审发现的新反例会把已经删除的尾部写回来：

```sh
{ printf ABCDEFGHI; : > result.bin; printf 123 >&2; } > result.bin 2> result.bin
```

此时真实 Bash 与精确 52 都得到 `123`，旧 54 却得到 `123DEFGHI`。把中间命令改为 `printf X > result.bin` 也有相同回归。源代码中的 `rt → body → mn` 顺序与实际 Worker/直接入口的普通、严格反例共同确定原因，不能仅用文件大小或 mtime 猜测发生了哪次截断。

## 本修订保持的状态

准备作用域重定向时，将其输出目标实际装入当前描述符表。每个子命令完成后立即经该目标交付输出，后续命令因而能观察或截断真实的当前文件。已有快照机制负责在作用域结束或抛出时恢复原有绑定、别名、输入标记和关闭状态。

每次独立打开建立不同的私有输出对象，保存路径、append 标记和当前位置。dup 与描述符表的浅复制共享同一个打开对象；两个相同路径的独立打开不合并。普通、持久、数值描述符均使用该对象。非 append 写入在其当前位置覆盖，成功后推进相应字节数；append 每次仍走原 append 路径。外部截断不会重置旧打开的位置，因此后续写入需要空洞时由真实定位写产生 NUL 空洞，而不是恢复缓存的旧内容。

定位写继续使用原来的根授权、变更队列、规范化路径、no-follow、特殊文件拒绝和 COW 路径。对多链接 inode 先通过原有有界机制隔离；若隔离后又被外部建立硬链接，写入前拒绝。单链接写不读取整文件来拼接尾部。定位值须为非负安全整数，位置与数据长度相加也须安全；验证在写文件前进行。真实写句柄为只写，分次 `write` 有进度检查。内存后端保留原分配上限并实现相同的定位与补零语义。

## 标准输出的目标身份

v2 独审的原样反例：

```sh
{ printf C; printf E >&2; } 2>&1 > result.bin
```

`2>&1` 保存当时的标准输出目标，随后文件重定向只更换 FD 1。真实 Bash 输出 `E`、文件为 `C`；v2 输出为空、文件为 `CE`。命令替换和管道中也有真实反例。不能通过一律跳过外层 `mn` 修复：普通函数、原始诊断和部分重定向失败仍需执行该入口。

每次顶层执行现在建立两个稳定输出对象，缓冲保存在私有 WeakMap。dup 保存对象身份；后来更换绑定不改变已保存的对象。命令、复合体、函数与异常仍走原路由入口；字节送入文件或输出对象后返回已消费的空结果，外层不会再次按当前 FD 解释它们。嵌套 shell 继承同一输出所有者及描述符对象，绑定表本身浅复制。

捕获建立独立输出对象，并在结束或异常时恢复原绑定；已有 dup 仍指向捕获之前的目标。一个已完成的外层语句或顶层执行结束时才取出标准输出对象中的字节，因此外部流式边界保持原约定。文件输出在子命令完成时交付，以让后续截断观察到正确状态。

合法 UTF-8 使用既有解码器并要求精确往返后返回文本；其它字节明确保留 bytes 类型。普通输出不经过诊断路径清理器。

v3 的最终 `logResult` 只排除 bytes，仍把已标为 text 的结果传给兼容解码器 `jf`。因此原文 `Ã©`（UTF-8 `c383c2a9`）先被正确解码为 JavaScript 文本，再被按两个 Latin-1 字节 `c3a9` 解成 `é`；`Â¢` 同样被折叠。真实文件系统的三个 stderr 程序在直接入口出现回归，Worker 正控制保持正确。stdout 对应情形在精确 52、v2 已存在，不能算 v3 新引入。

v4 只给这两条最终解码条件各补一个“未显式标为 text”的判定。显式 text 和 bytes 均保留其值；原未标类型的兼容形状继续走 jf。没有删除 UTF-8 分类、把所有输出标为 bytes，或改变预算。生成 JavaScript 与 v3 逐字节比较，仅同一位置新增两个判定，共 46 字节。


## 捕获与预算

继承文件目标不等于所有嵌套输出都应写入外层文件。普通命令替换、管道非末项和输入进程替换明确捕获 stdout，暂时遮蔽外层绑定并在 `finally` 恢复。输出进程替换仍继承外层输出。`|&` 的隐式 `2>&1` 在该命令显式重定向之后生效，按同一描述符别名路径执行，不在事后把两路字符串随意拼接。

文件目标在实际输出交付前进入共享预算。已接受的字节不会因为后来作用域返回空结果而被重复计费；独立目标和 dup 都仍受原输出大小上限约束。真实 6 字节预算接受 `ABC` 与 `DEF`，拒绝后来的 `GHI`，落盘仅为 `ABCDEF`。这里没有放宽任何生产预算或测试超时。

## 明确限制

定位对象仍按授权路径执行文件操作，不等同操作系统保持的内核打开 inode；未证明 unlink/rename 后仍写旧 inode 的语义。`readwrite` 描述符的既有缓存实现没有被本修订替换。单个外部命令内部 stdout/stderr 的真实实时交错仍不作普遍保证；这里核实的是已列脚本的命令完成顺序及对应描述符结果。任意自定义文件系统对私有写入选项的行为、任意 shell 语法和完整 POSIX 等价也不在承诺内。

实际 DSH 回合使用固定开发依赖前缀与本次源码。旧 42 的真实归档、安装树、Host/HAP 都不包含本修订；源补丁普通适用不等于产品载荷已更新。最终需重建私有 ESM、重算归档清单和内容版本、实际增量安装后再走 Host 与严格回合。没有新增 Dart/ArkTS/App 编译或设备验收声明。
