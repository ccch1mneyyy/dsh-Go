# M4-4b：权限诊断与合并输出的字节保持

## 范围与接入次序

本补丁在 `c0949d6` 的已收组合（34、36）及 M4-4a v2 之后应用。M4-4a v2 完整补丁为 `85cf1559e65139ecabad3e592ab4390fc0da16986a72e7aff4dd2c75519d024c`；本项不替代其根授权、会话 grep 和临时目录归属修复。Worker 的唯一直接修改是把 `Bash/defineCommand` 的 import 指向本目录的私有构建。运行时、受限 FS、两条队列、命令注册、票据、预算数值、DSH 厂商补丁和 pins 均不改变。

交付的是固定 npm 发布物的精确变换和本地构建脚本。没有新 npm 依赖、没有修改共享 `node_modules`、没有将生成的第三方 JS 或归档装进源码补丁。`test.sh` 和安装步骤增加显式构建；未生成私有目录时启动失败，不静默切回错误诊断的原入口。

既有 `filesystem.mjs` 仍使用原包的 `MountableFs/ReadWriteFs`。本项只修改解释器如何报告它实际拒绝的错误。工作区内指向域外的 symlink 保持 EACCES；词法域外 `exists()` 的既有 false 语义不扩大成新的权限承诺。没有通过允许外部 PATH、修改 Node 全局或伪造中止异常解决诊断。

## 固定版本中的原因与改动

固定 `just-bash 3.6.0` 的 `cd`、`cat` 及三处输入重定向 catch 将拒绝读取的错误改写成 “No such file or directory”。私有变换只在错误 `code === 'EACCES'` 或既有受限 FS 以 `EACCES:` 开头的错误消息时，返回明确的 `EACCES: Permission denied`。其他错误保留原分支；真实 ENOENT 仍是缺失文件。错误仍通过原执行结果返回，因此 `||` 恢复、`2>/dev/null`、先设置的 stderr 文件重定向均沿原语义工作。

第二个问题是输出表示混用。该版本的 stdout 可以是保存原始字节的 Latin1 字符串，stderr 则是 Unicode 文本。`2>&1` 直接相加后，又按 UTF-8 文本计量/解码，会造成中文输出被误计为超限，或把 `0xff` 再编码一次。修复在通道合并和文件/descriptor 写入处按目标表示转换；原始字节按字节长度计量。脚本与语句累加器接收原 result 的类型标记，内部保留字节；仅在 UTF-8 解码再编码完全等于原字节时返回 text，否则保留 bytes 标记。已有 Unicode `for`、`if`、管道、函数正常返回、`exit/return` 路径有单独回归。

这些变换对应的上游阅读位置如下。完整 URL、commit、SHA256 在 `bash-src/upstream-review-sources.json`；固定 commit 来自 npm provenance 元数据，本轮没有独立验签，不将它写成签名已验证。实际构建身份以锁定 npm 发布物字节为准。

| 原源文件 | 核对位置 | 私有构建的处理 |
| --- | --- | --- |
| `interpreter/builtins/cd.ts` | stat catch | 保留 EACCES 分类 |
| `commands/cat/cat.ts` | 读取 catch | 保留 EACCES 分类 |
| `interpreter/redirections.ts` | 普通、数字 descriptor、读写 descriptor 输入错误及通道合并 | 保留分类，按原重定向顺序送入 stderr；统一跨通道字节转换和计量 |
| `interpreter/interpreter.ts` | script / statement 的 appendResult | 传递原结果的 stdout 类型 |
| `execution-output.ts` | 累加与 build | 字节累加、精确 UTF-8 往返判断 |
| `Bash.ts` | logResult | 对明确 bytes 的 stdout 保留原字节 |

## 可复现构建与许可

`build-just-bash.py` 不联网。它先核包名、版本、Apache-2.0 元数据、package.json、完整 LICENSE、`dist/bundle` 的 202 个普通文件及各自 SHA256/长度；额外文件、symlink 或任何漂移均拒绝。三个被改模块另有 before/after SHA256，替换锚点必须各出现一次。已经核过的字节保存在内存中，实际执行的本仓库变换字节也与 provenance 中记录一致。

只输出原发布物的 200 个 ESM 模块（排除未使用的 CJS/browser 入口），加私有 package.json、LICENSE 和 PROVENANCE.json，共 203 文件、2,052,667 字节。未改模块逐字复制；三个改动模块带显著修改声明。固定原 LICENSE 的 SHA256 为 `014bb31e83d5c2e76aea1cc6e82217346ab41362f32cb355ad0f5c10aa0aeaff`，全文随产物 `build/just-bash/LICENSE` 保留；原模块中的捆绑许可注释仍保留。修改声明不把原 Apache 许可证改为 MIT。安装闭包其余许可由 M4-6 另行盘点。

构建在所有前置检查完成后建立本次独有的旁侧 staging 目录，校核写出字节后提交。相同已有输出幂等；漂移或外来已有目录保留并拒绝。失败清理只删本次 staging。构建输出由一个构建者独占，不把普通目录 rename 宣称为任意并发构建者的 no-clobber 原语。

```bash
npm ci --prefix runtime/ohos/process --ignore-scripts --omit=optional
# 按既有步骤 link-dsh，并生成固定 RE2 私有产物后：
python3 runtime/ohos/process/build-just-bash.py
```

已有只读依赖可以明确传入 `--package /固定npm树/node_modules/just-bash`；输出用 `--out` 选择独立目录。输入与输出重叠被拒绝。本项不是完整 TypeScript 上游重编：采用的是精确 npm 发布 JavaScript 的本地变换，不能把其证据写成任意上游版本兼容。

## 测量与保留的失败

最终新矩阵由真实 `VirtualSubprocessRuntime` 创建 Worker，使用原始 stdout/stderr pipe 收集 Buffer；不是在字符串 `.text` 上猜测非法 UTF-8。JIT 和严格 O0 各 24/24，0 skip、0 TODO。严格命令同时显式使用 Node 24.22.1、`--jitless`、O0 preload、openharmony 平台、空 addon 白名单；父与 Worker 的前置断言检查平台、WASM 缺失和进程内标记。相同最终矩阵对原发布入口为 13 PASS / 11 FAIL。原三项诊断失败及先前 21 PASS / 1 FAIL 原日志仍保留；早期文件名含 strict 的实验实际只有 jitless，说明中不再将它算完整 O0，后来已按真实 O0 重跑。

矩阵包括 8 个读权限拒绝/恢复场景、3 个错误抑制场景、先建立 stderr 文件再输入拒绝、3 个 ENOENT、3 个字节/重定向目标组合、5 个既有 Unicode 组合和 1 个只读写入拒绝。已有 `cat < denied || recovery` 不会因新诊断中止整批。`2>&1 >file` 与 `>file 2>&1` 的目标身份分别验证。

只读写入测试的最初新增断言错误地要求 `||` 在写策略错误后恢复。真实原版与候选都返回 1、空 stdout、明确 `OHOS_SANDBOX_DENIED`、目标不存在。保留原先 23/1 和原版 12/12 日志，最终只将这条额外断言纠正为保持既有写策略行为；产品没有为它改变。读拒绝的恢复断言没有放宽。

构建器 14/14：新构建、幂等不重写、未改模块漂移、包元数据/许可/文件集合/symlink/变换输出漂移、已有输出与外来目录保留、输入输出重叠、第三次 staging 写入失败清理、最后输入及输出保持。其中 ENOSPC 是明确注入的写故障，不能说成本机磁盘满的实测。

根提供的真实 100001 命令案例在最终构建 JIT/严格 O0 各 1/1：返回 126、之前已完成的文件写入保留、之后的写入没有发生、worker 退出且下一任务可运行。生产 `maxCommandCount=100000` 没有调整，也不提供事务回滚承诺。原行为/审批 49 项在最终构建 JIT/严格 O0 各 49/49；真实 Session 夹具使用已审 M4-4a v2 的版本。

## 未解决边界

以下是 M4-4b 当时保留的边界。二进制 stdout 控制流问题由独立后继 [O4-stdout-control-flow.md](O4-stdout-control-flow.md) 修复，并保留原失败；这不改变本文件所记录旧补丁的测量与哈希。

原生 Bash 的额外 14 项字节组合对照不是本项全通过证据。最终候选有 12 项等价；`cat binary; exit 7` 与函数里 `cat binary; return 7` 的任意二进制 stdout 仍经过原未携带类型的控制流错误路径而再次编码。这两个例子在原发布物中同样失败，单列保留，不能把本项写成所有 shell 二进制控制流均已修好。已有合法 Unicode 的对应 exit/return 正对照仍通过。

受限 FS 检查与真实宿主 IO 之间的既有路径替换竞态、完整 OS 沙箱、实时输出、Node 脚本、O4b Git 硬取消等仍由各自条目处理。所有测量是在 Linux 仿真；OpenHarmony ABI、真机执行时间与峰值内存没有因此得到验证。最终结论须由绑定精确补丁哈希的独立审查给出。
