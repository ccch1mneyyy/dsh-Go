# M4-1 v2：DSH grep 的 include 与 Unicode 常用正则

## 结论和适用前置

本包在 OHOS 虚拟进程的 **DSH JSON grep 路径**恢复正向 `include`，以及 `\w`、`\d`、`\s`、`\b` 和反类。作者已用 DSH 随包 ripgrep 15.0.0 做真实差分，另从实际 DSH 搜索函数验证参数、NDJSON 消费和错误分类。结论限于本文范围；没有真机结果，也不等于完整 ripgrep、O4 或全部 M4 已完成。独立审查结论另附，作者测试计数不能代替独审。

**v2 完整替代 v1；不要把完整包叠加到 v1 上。** 已应用 v1 时使用单独绑定 `5fdebda845ecd607ce2f3107cbebc796e1ae8e05c7aeeebc4a76526bbbd7331c` 的后继差分。两个装配路径的源码须逐字节相同。

后继完整差分的前像为 O4a v3（SHA256 `2f134c973c565b0b771acdff483537e85a844ee6d7faf5ad5cdea12d418c2581`）叠加 M3-3 O4a marker 迁移（`116b3f31b2523a3647de4016b20ba2096de1c73c04c866482843bbbaf8457c18`）。M3-3 主包提供测试 marker/preload。旧 O4a 原始补丁声明 afb5cdd；本差分只修改这些已存在的 O4 文件及根 `.gitignore`，不声称能单独应用到尚无 O4 文件的干净 c0949d6。整合时按 manifest 的前后像核对，不能用 README 的整体覆盖丢弃 M4-2 并发说明。

不修改 runtime.mjs、filesystem.mjs、厂商补丁、pins、Android 构建、依赖 manifest 或锁文件。Android 原 resolver/工具 schema/服务门控对照继续通过；本包不是 Android 的新搜索实现。

## 实现依据

### include 选择

DSH 的 `include` 被编成 rg 的正向 glob，旧虚拟入口直接返回 exit 2。JSON 路径新增 `rg-select.mjs`，只通过当前调用的受限 `ctx.fs` 枚举和读取，不借宿主 fs 绕过授权根。

| 情况 | 处理及真实对照 |
| --- | --- |
| `*.txt`、`dir/*.txt`、`**/*.txt`、`*.{txt,ts}`、字符类 | 根据路径或 basename 匹配；覆盖实际 DSH 常见 include。 |
| 多个正负 glob | 最后一个匹配的 override 决定当前条目，正向文件匹配可以越过该文件的 ignore/hidden。 |
| 被忽略/隐藏的父目录 | 先按目录规则剪枝；仅子文件匹配不会自动重新打开父目录。`-g ignored -g *.txt` 可显式允许该目录。 |
| 显式文件 | 越过 ignore、hidden 及不匹配的 include，仍受 FS 根和只读策略约束；保留 O4a v3 修复。 |
| 显式目录 | 以它为遍历根，内部条目继续按规则选择；不重新套用祖先已剪枝目录这一事实。 |
| 本地 ignore | `.rgignore` 优先于 `.ignore`，再到仓库 `.gitignore` / `.git/info/exclude`；同类更深/更晚规则优先。 |
| 祖先规则 | 仅在当前授权文件系统可见时读取；词法域外 `exists` 为 false，不扩大根来追求宿主全局配置。 |
| 无输入文件 | 未显式给路径的遍历若过滤掉所有文件返回 2；显式目录没有匹配文件返回 1，错误路径返回 2。 |

固定 rg 的 glob 与文本正则使用不同的计量单位：`?`/字符类按字节匹配，`???` 能完整匹配三字节汉字，`????` 能匹配四字节 emoji。v1 按 Unicode 标量执行 glob，在独审中出现了成功但遗漏或额外纳入文件的问题。

v2 只在 selector 内把模式和路径的 UTF-8 bytes 映射成 Latin1 标量，一字节对应一 regex 标量；真实 FS 路径保持原字符串。这样字面多字节、star、单字节通配和字符类的组合可在同一引擎中按字节处理。类内反斜杠按原生 glob 的字面成员编码，避免 `\d` / `\w` 被错误解释成文本正则 shorthand。这个局部映射没有改文本正则的 Unicode 规则或私有构建产物。

范围与原生覆盖以固定新版 oracle 为准。遍历和结果数分别受解释器 `maxGlobOperations`、`maxArrayElements` 限制。递归遍历不跟随 symlink；显式路径是否可读仍由受限 FS 决定。`.git` 文件式 gitdir 目前明确返回 2，外部全局 gitignore / `core.excludesFile` 不读取；没有声明全部 Git ignore 语法和任意目录布局都等价。原始非法 UTF-8 文件名无法由这里的 Node 字符串路径无损表示，没有计入等价范围。

### Unicode 字符类和零宽断言

不能把 RE2JS 原有 ASCII shorthand 直接放行，也不能在候选匹配后检查 `\b`：后者会改变选择分支、贪婪/懒惰重复及内部零宽位置的决策。本实现只为 OHOS rg 构建私有 RE2JS 模块，在匹配引擎的同一个零宽上下文中使用 Unicode word 分类。

锁定 re2js 1.3.3 已带 Unicode 16 表。`\d` 使用 Nd；`\s` 使用 White_Space；word 使用 Alphabetic、Mark、Nd、Pc、Join_Control 的并集。word 补充范围与分类表组合通过固定 rg 的完整标量对照核实。不是用当前宿主 Node 的 Unicode 属性重新生成：本轮 Node 24.22.1 的 Unicode 为 17.0，而锁定表为 16.0。

源差分只涉及原始 `Utils.js`、`Parser.js`、`MachineInput.js`、`Machine.js`，另加手写 `UnicodeGroups.js`。原生成的 `UnicodeTables.js` / `CharGroup.js` 不修改。UTF-8 continuation 字节不能成为 Unicode 消费字符或 `\b/\B` 的位置，但普通空表达式仍保留 rg 在每个字节位置的行为；为此修改输入上下文与 NFA 的有效标量判断，没有通过过滤最终匹配列表近似实现。

BOM 检查曾发现真实新缺陷：`matcher.group()` 的解码器会丢弃每个片段开头的 U+FEFF，即使 start/end 正确。现从原始 line Buffer 的 start/end 取文本，只移除文件最前的一枚 UTF-8 BOM。文件中后续 BOM、行首 BOM 和多字节邻接字符均保留；文件首 BOM 后的 JSON 坐标与原生解码后坐标一致。

## 保留的失败证据

1. 在 marker 迁移后的旧 O4a v3 上，修正 stdin 夹具后的首批 51 项为 6 PASS / 45 FAIL，包含原先明确拒绝的能力与既有 ignore 差异。该旧路径的事实独立保留。
2. 第一版原生夹具错误地给无 path 的 rg 接 pipe stdin，原生因此搜索空 stdin。已保留误夹具日志并用 `stdio[0]='ignore'` 重录；不把这一夹具错误记成实现缺陷。
3. 逐步实验 25/51、31/51、48/51、49/51 均保留，包含 continuation 字节的断言/ANY 问题及隐式无输入文件退出码问题。WIP `59abbd94…` 不是本正式源码包，也不计为通过。
4. 扩展完整标量检查先发现四个模式仅缺 U+FEFF；新 BOM argv 回归修改前 59 PASS / 5 FAIL。`unicode-scalar-bom-before.*`、`m4-1-bom-before.*` 和 `rg-before-bom.mjs` 保留。修复后 64 项全过，不能用早先 57 项通过掩盖这个额外失败。

5. v1 正式独审 `5fdebda8…` 为 BLOCKED，报告 SHA256 `79e6f2b7893caf847cc0b92ecf808e4b85e3c33d3743a76af5c70c8d160024ec`。原有 64 项和 3/45/45 虽全过，额外 35 项有 2 项差异，实际 DSH 严格 O0 的 `?` / `???` / `????` / `[!a]` 四项 0/4；v2 不能用旧通过数覆盖这个反例。
6. 字节桥修复期间新增 27 个 byte/literal/class 组合探针，先为 22 PASS / 5 FAIL，定位到类内反斜杠被当成 regex 转义。最小 class 编码修复后同一 27 项全过，独审额外 35 项的作者隔离重放也为 35/35；原记录均保存。

7. v2 的新文件名夹具同时含预组合 `é` 和 `e`+组合附标，首次 93 项回放为 91/2。两个差异的完整 match 记录多重集实际相同；旧 `localeCompare` 排序把等价拼写视为相等，原生与虚拟枚举顺序因此进入断言。改为 JSON bytes 的确定排序并重录 oracle，不删除路径、行文本、偏移或任何 submatch 比较；保留首跑日志与排序器前像。最终两模式各 93/93。

## 重现

在已经应用上文精确 O4a+marker 前置的源码树中应用本差分，然后复用固定的 process 依赖与 esbuild：

```bash
node runtime/ohos/process/build-rg-regex.mjs /含esbuild0.27.3的prefix
NODE=/Node24.22.1/bin/node \
OHOS_TEST_PROCESS_PREFIX=/已应用O4a和marker厂商补丁的独立prefix \
OHOS_TEST_BASE_PREFIX=/原始DSH-npm-ci-prefix \
OHOS_SIM_PRELOAD=/已复核M3-3/runtime/ohos/sim/preload.mjs \
OHOS_ESBUILD_PREFIX=/含esbuild0.27.3的prefix \
bash runtime/ohos/process/test.sh

node runtime/tests/ohos/process-rg-m4-differential.mjs
node --jitless --import /已复核M3-3/runtime/ohos/sim/preload.mjs \
  runtime/tests/ohos/process-rg-m4-differential.mjs

OHOS_NATIVE_RG=/DSH随包rg15绝对路径 \
node runtime/tests/ohos/process-rg-unicode-differential.mjs
```

93 项的固定原生 oracle 已交付。若重录，需在可执行原生进程的普通宿主上设置 `M4_RG_MODE=record OHOS_NATIVE_RG=...` 运行同一 differential 入口；严格 O0 仅回放，不能为录制 oracle 绕过禁进程前置。全标量脚本是宿主两引擎对照，不在 O0 下尝试 spawn 原生程序。

## 尚未解决的边界

非 JSON 的新增 shorthand/词边界及 include、复杂 `--files` 正向 glob、任意 Rust regex 特性、所有全局 ignore、文件式 gitdir、非 UTF-8 编码仍未完整支持。多十 MB 单行可因数组展开放大内存，显式二进制预检与正式搜索重复读文件，明确留给 M4-3；本包没有借文件大小上限宣称已处理它。M4-2 并发、M4-4 根/临时目录、Git 硬取消、node 脚本与实时输出均由后继独立处理。
