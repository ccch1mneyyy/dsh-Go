# M6-1：Git worktree／子模块中的 JSON 目录搜索

## 修复范围

`rg-select.mjs` 在发现 `.git` 时，原先只接受目录。真实 Git worktree 和子模块使用普通 `.git` 文件，所以目录搜索会在准备忽略规则时直接返回 exit 2，未带 include 的搜索也受影响。

现在把普通 `.git` 文件视为新的仓库边界：清空从外层仓库继承的 Git 忽略规则，再读取这个工作区内的 `.gitignore`。`.rgignore`、`.ignore`、隐藏文件、正向 include、嵌套目录及 `--no-ignore` 的原处理继续沿用。普通 `.git` 目录仍读取本目录的 `.git/info/exclude`。

本修复采用追加 10 明确允许的“跳过 gitdir 的 info/exclude”方案，不解析 `.git` 文件里的指针，不扩大授权目录。worktree 的 gitdir 可以在另一个仓库的数据目录内，子模块的 gitdir 通常在父仓库的数据目录内；它们都可能位于当前搜索工作区之外。仅为读取排除规则而开放这些路径会改变权限范围，因此本次保留原有受限文件系统边界。

这项选择有明确的结果范围：对于 `.git` 为文件的仓库，私有 gitdir 中的 `info/exclude` 不参与过滤，可能比桌面 rg 返回更多文件。项目内 `.gitignore` 等规则仍生效。它不代表完整实现 Git 配置、全局 gitignore 或所有 Git 仓库布局。

## 可复跑差分

新增脚本：

- `runtime/tests/ohos/process-rg-gitfile-cases.mjs`：23 项固定参数和测试文件。
- `runtime/tests/ohos/process-rg-gitfile-differential.mjs`：原生记录与虚拟后端回放。

记录阶段实际执行 `git init`、`git worktree add --detach`、本地 `git submodule add`。子模块通过显式 `protocol.file.allow=always` 只从本次夹具的本地源仓库添加，不访问网络，也不修改调用方仓库。普通仓库的 `.git` 确认为目录，worktree／子模块的 `.git` 确认为文件；原生 rg 必须是锁定的 15.0.0，记录二进制摘要及版本。

回放阶段只调用真实 `VirtualSubprocessRuntime`：先取得当前仓库的 read-only 票据，再通过实际 worker 执行 rg；另外覆盖 `bash -c 'rg …'` 接线。严格模式继承 O0 预加载，不执行原生 git／rg。所有搜索前后都核对夹具整树的文件内容、模式和符号链接清单，包含原 index、objects、refs 以及工作区文件。

比较保留退出码、stderr、行内容、行号、绝对字节偏移、每个子匹配的内容与起止字节；只规范化 JSON 路径的单个前导 `./`，并按记录字节排序。没有把原生 rg 的 begin/end/summary 计时记录作为 DSH match 记录比较。

23 项中，22 项要求规范化后与原生 rg 相同。另 1 项专门锁住允许的差异：本机夹具中的 worktree 原生 rg 读取私有 `info/exclude`，OH 路径跳过它，多返回 `external-only.txt`。该项单独断言唯一新增文件和内容，不计作原生等价。此夹具中的子模块原生 rg 没有应用那条私有排除规则，单列实测事实，不把它泛化为所有子模块的行为。

## 命令

先按已有 OH 运行层锁文件安装依赖，并按 M4-1 的固定构建入口生成 `build/re2js-unicode.mjs`；该第三方生成物不进入本补丁。设置 `NODE` 为固定 Node 24.22.1，`OHOS_NATIVE_RG` 为固定 rg 15.0.0。

```sh
M6_GITFILE_MODE=record \
M6_GITFILE_ORACLE="$PWD/m6-evidence/native.json" \
M6_GITFILE_FIXTURE_PARENT="$PWD/m6-fixtures" \
OHOS_NATIVE_RG="$OHOS_NATIVE_RG" \
"$NODE" runtime/tests/ohos/process-rg-gitfile-differential.mjs

M6_GITFILE_ORACLE="$PWD/m6-evidence/native.json" \
M6_GITFILE_REPORT="$PWD/m6-evidence/replay-jit.json" \
"$NODE" --import ./runtime/ohos/sim/marker.mjs \
  runtime/tests/ohos/process-rg-gitfile-differential.mjs

M6_GITFILE_ORACLE="$PWD/m6-evidence/native.json" \
M6_GITFILE_REPORT="$PWD/m6-evidence/replay-strict.json" \
DSH_GO_OHOS_SIM_PLATFORM=openharmony \
"$NODE" --jitless --import ./runtime/ohos/sim/preload.mjs \
  runtime/tests/ohos/process-rg-gitfile-differential.mjs
```

记录与回放要使用相同的测试脚本和 case 文件，脚本会核对两者摘要。夹具保留在记录文件指明的随机目录，便于独立复核；每次回放只删除本次自行创建的临时根。完成审查后可删除调用者自己指定的 `m6-fixtures` 和 `m6-evidence`。

## 证据边界

这是一处 OH 搜索选择器修改，没有改变 Android 构建输入、DSH vendor 补丁／pins、文件系统授权、运行队列或发布服务。新的测量以 34 号累计树为前置，未混入 M4-4a/v2 或 M4-4b 的诊断候选。OH arm64／真机结果仍须另行验证。
