# O4 后继：控制流传递的 stdout 字节与已计数长度

## 范围与前置

这是一项独立后继修复，基于 `530f183906be2a218b1b09000400e01c9a572dba`，实际验证树先应用 Worker v2（36，补丁 SHA256 `46b1b09b2b96ac774ada4d3b78b6e4accd450642b88287ea6a1bfe1424b44909`）与组成 v2（40，`b8420b4351fbae0f9fb3c6e395e8f7e061b6f8c8a2eaaf75245b7302721436b1`）。交付增量须核精确前像，不能当成覆盖旧包的完整补丁。旧 36、40 和归档产物保持原字节。

改动仍只作用于固定 `just-bash 3.6.0` 的 OH 私有 ESM 变换。原 npm 包、锁文件、Android 构建输入、全局 Node built-in、Worker 启动与取消/排空/归属清理实现均未改。构建器继续核全部 npm bundle 文件、许可、每个改动模块的前后 SHA 以及每处变换锚点的确定次数。

## 已复现的丢字节路径

旧路径将二进制 stdout 装进 `ExitError`、`ReturnError` 或循环累加器时，没有一起传递字节类型。六个原始字节 `00 ff c3 a9 80 0a` 随后被当成文本再次编码，变为十字节 `00 c3 bf c3 83 c2 a9 c2 80 0a`。命令仍正常返回 7，文件与管道中的字节却已改变。

实际原生 Bash 对照包含外层/嵌套 shell、函数、花括号、子 shell、循环、重定向与管道；每个脚本均分别经过公开 `VirtualSubprocessRuntime` 的真实 Worker 和私有解释器。16 个脚本形成 32 个观察，旧版本普通和完整严格模式均有 23 个差异。其中 19 个属于本项控制流问题；另 4 个是两种“同路径独立 open”在两种执行入口下的既有问题，留在下一项处理。外层流式交付已使单独的 `cat binary; exit 7` Worker 路径通过，不能据此推断其嵌套路径也已正确。

## 修改后的不变量

错误对象和复合命令在内部保留原始字节字符串，并显式携带 `stdoutKind`、`stderrKind` 与 `internalOutputAccounting`。每次 prepend、append、返回错误结果及多层 break/continue 转交都保留这些信息。循环累加器先按原结果类型归一成字节，再按字节长度计量；不再将任意原始字节的 JavaScript 字符串按 UTF-8 长度重复计数。

原公共累加器的 `build` 仍只在 UTF-8 解码再编码逐字节相等时返回 text；其余结果保持 bytes。控制流错误不再先解码。命令替换属于明确的文本消费者，在进入文本展开的位置按结果类型解码，这同时保住合法中文，避免新的重复编码。

计数也属于传递协议：已经纳入共享输出预算的字节，跨错误结果边界后仍标为已计数。实测 6 字节输出、6 字节预算的函数 `return 7` 原来错误返回 126；现在保留原六字节并返回 7。第二个输出越过预算时仍返回 126，之前已经接受的二进制前缀只保留一次。循环次数超限同样保留原前缀及原退出码，生产预算数值没有放宽。

完整回合用固定开发依赖前缀与本项真实源码运行；已有单归档安装产物没有包含此修复。后续组成必须重建私有 ESM、重算逐文件清单和内容版本，再走归档安装与宿主链门。本包不复用旧归档的验收结论。

## 保留边界

`> same 2> same` 与 `>> same 2> same` 的两个独立打开仍有既有截尾差异；它们与真正 dup 的 `2> same 1>&2` 不等价。原始探针保留这些失败，不能写成全部 32 个观察都与原生相等。

本项不新增 stdout/stderr 实时交错顺序承诺，不证明任意 shell 语法、二进制变量/命令替换或完整 OS 沙箱等价。命令替换在本项只验证合法 UTF-8 文本。原 Node Worker 的平台/native binding/child-process 边界见 [O4-Node-Worker.md](O4-Node-Worker.md)。最终结论仍须以绑定本次精确补丁 SHA 的独立审查为准。
