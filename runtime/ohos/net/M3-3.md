# M3-3：仿真由显式预加载启用

本小包以 **c0949d6** 为基底。固定 Node **24.22.1**、DSH **0.2.1-rc.4**、外部 Undici **8.11.2**。修复的是 Android 继承普通环境变量时误入 OHOS 网络分支的问题；没有引入依赖，也不改 Android 启动文件。

## 行为与边界

生产中的三个入口——`net/fetch.mjs`、`dsh-http-proxy`、`dsh-web-fetch-http`——统一判断真实 `openharmony` 平台，或明确预加载已设立的 `globalThis[Symbol.for('dsh.go.ohos.sim')] === true`。它们不再读取 `DSH_GO_OHOS_SIM`。

`sim/marker.mjs` 只写入当前 isolate 的测试标记，不关闭 JIT、不拦截 Node API。`sim/preload.mjs` 明确导入标记并施加既有 O0 限制，是否运行由 `--import` 决定。预加载中的平台覆写和插件白名单仍是测试配置。网络预加载在标记或完整 O0 预加载之后运行，避免初始化先后造成分支选择错误。

`net/test-integration.sh` 的 JIT 组明确加载 marker，严格组明确加载 O0；没有把原 JIT 对照换成严格仿真。Android 组故意设置旧变量为 `1` 且不加载 marker，并同时核对原包/已补丁包的真实 HTTP 请求轨迹。

Worker 不共享父线程的全局对象。真实测试检查了默认继承预加载后，Worker 具有自己的标记；完整组还实际调用被禁止的 `spawnSync`。继承环境变量不再启用生产 OHOS 分支。

## 修复前后实测

原始先失败矩阵固定在交付证据 `frozen-before/`。四个 M3-3 断言在 c0949d6 原实现上均失败：Android + 旧环境变量使 fetch 被替换、代理要求 OHOS preload、地址固定抓取也要求 OHOS preload；反过来，单独显式设置进程内标记却不能启用网络。相同四条断言在修复后 **4/4 PASS**，保存为 `m3-3-after.json`。

| 实际执行的验证 | 结果 |
| --- | --- |
| 仿真入口、旧变量负对照、JIT 标记、真实 Worker、完整限制 | 10/10 PASS，0 skip/TODO |
| Android + `DSH_GO_OHOS_SIM=1`，不加载 marker | 4/4 PASS，0 skip/TODO |
| DSH 网络集成，marker-only JIT | 13/13 PASS，0 skip/TODO |
| DSH 网络集成，完整 O0 + jitless | 13/13 PASS，0 skip/TODO |
| 原网络核心，普通 Node / 完整 O0 两轮 | 每轮 36 PASS、5 TODO、0 SKIP |

五个 TODO 是既有 FormData 307/308 与响应体 falsy abort reason 的失败断言，未被删除或放宽。日志中的 `todo` 不表示通过。TLS 使用临时自签名证书，所有服务器均为本地夹具，没有访问真实账户或远程业务服务。

## 补丁与复跑

`runtime/patches/ohos-network-transport.diff` 与 `pins.json` 同步更新；私有验证前缀由项目 `rtbuild.py patch-dsh` 按精确 before/after 哈希生成，未手改被补丁覆盖的产物。M3-3 的两个 after 为：

- `dsh-http-proxy/lib/index.js`：`f3d22a3ff90162b957c9ae91b87390384b87a2a802669c03caf6c5f2666c82cc`
- `dsh-web-fetch-http/lib/index.js`：`49e18b23e61eb1d5a2008006bf857c9fee724a60d119ccebeab777f6e3fef260`

在已按新 pins 生成的独立 DSH 前缀上运行：

```bash
node --test runtime/tests/ohos/sim.test.mjs
NODE=/Node-24.22.1/bin/node \
OHOS_SIM_PRELOAD="$PWD/runtime/ohos/sim/preload.mjs" \
DSH_GO_OHOS_SIM_PLATFORM=openharmony \
bash runtime/ohos/net/test.sh
NODE=/Node-24.22.1/bin/node \
OHOS_TEST_DSH_PREFIX=/private/patched-prefix \
OHOS_TEST_BASE_PREFIX=/private/original-prefix \
OHOS_SIM_PRELOAD="$PWD/runtime/ohos/sim/preload.mjs" \
DSH_GO_OHOS_SIM_PLATFORM=openharmony \
bash runtime/ohos/net/test-integration.sh
```

O4a v3 与 O4b Git WIP 不在 c0949d6 内。它们新增的服务、resolver、provider 门控必须通过随附的、绑定各自精确冻结哈希的迁移差分一起更新；不能把本主包误称为修改了不存在于基底的文件。Git 的硬终止临时索引残留仍是原有 BLOCKED，门控迁移不改变这一裁决。

本包冻结时已完成上表的桌面测试；同一 O0b 真实五工具剧本由主验证树在整合后单独记录。尚未在 OpenHarmony 真机核实。M3-4 默认代理与 M3-5 dispatcher 生命周期问题仍由各自后继小包处理，不属于本包通过范围。
