# M3-5：默认 dispatcher 恢复、关闭回调与请求头归一

本子项修复追加3所列三种可达行为。固定验证输入为官方 Node 24.22.1（内置 Undici 7.30.1）、DSH 0.2.1-rc.4、锁文件中的外部 Undici 8.11.2。测量使用真实本地 HTTP/HTTPS 与 Worker；尚未在鸿蒙设备核实。它不宣称整个 O5 已完成，核心测试中五个原生规范 TODO 原样保留。

## 1. 为什么需要明确的启动前置

原始先失败矩阵在全新 jitless 进程中安装、卸载 DSH 代理策略，然后用外部 `undici.fetch` 访问真实本地 HTTP；恢复到最初默认 Agent 后，以 `WebAssembly is not defined` 失败。已有显式 custom dispatcher 的恢复对照原先就通过，修复须保留这个行为。

锁定 Undici 的 `lib/global.js:14–16` 在模块首次求值、全局 dispatcher 不存在时创建 Agent；`57–59` 的 getter 只取当前对象。公开 `types/global-dispatcher.d.ts` 仅声明 get/set，没有“此对象是库默认创建还是用户显式设置”的历史查询。相同类型的 Agent 可来自用户，不能凭 constructor.name 或 instanceof 推断意图。这里审阅锁定包源码作为依据；产品实现不读写 Undici 私有 Symbol。

采用的接缝是 `net/dsh-preload.mjs`。**宿主必须把这个专用 preload 放在应用、插件及其它 dispatcher 配置之前。** 主线程调用 `bootstrapDshNetwork(process.argv[1])`，核实实际 bin 的 realpath、DSH 包名/版本/公开 bin 字段，以及由此入口解析出的 Undici 版本，然后通过公共 setGlobalDispatcher 设置本层明确持有的安全基底。

`require.cache` 检查已解析 Undici 的 CJS 载入记录及导出公开 get/set 的 CJS 模块。真实 ESM import CJS 的用例确认同样进入该缓存。若外部模块已载入且没有本层先前建立的启动记录，函数在安装 fetch 之前报错，并保留已有 dispatcher 与 fetch 的对象身份。它不是所有 Node 内部全局配置历史的完备检测器，例如内置 `http.setGlobalProxyFromEnv` 的调用不会作为外部 Undici 模块出现在 require.cache 中。因此必要的早期启动前置不能删去；不能把“未发现缓存记录”等同于证明此前无人配置过任何 Node 全局状态。

安全基底建立后，应用可正常通过公共 API 设置自定义 dispatcher。重复 bootstrap 不重设它。策略安装捕获当时实际的 prior，卸载恢复该原对象；没有代理配置时也不会恢复一个由我们猜测的默认 Agent。原生内置 7 的全局桥接由外部 8 的公共 setGlobalDispatcher 完成。

| 入口情况 | 行为 |
| --- | --- |
| 真正 DSH bin；专用 preload 先于应用/插件和 dispatcher 配置 | 安装安全基底；允许后续策略 install/dispose |
| 已完成本层 bootstrap，随后用户显式设置 custom | 再 bootstrap 不覆盖 custom；策略卸载原样恢复 custom |
| 外部 Undici 已载入，无本层启动记录 | `ERR_OHOS_NET_BOOTSTRAP_ORDER`；不改原 dispatcher/fetch |
| 非锁定 DSH bin，或锁定包/版本不匹配 | `ERR_OHOS_NET_DSH_ENTRY`；不安装 fetch、不载入 Undici |
| 只使用普通 fetch preload，却调用 DSH 全局代理安装 | `ERR_OHOS_NET_BOOTSTRAP_REQUIRED`；不偷偷载入 Undici |
| 独立 `createHttpDispatcher` / `createFetch` | 可正常使用；不要求 DSH bin，不自动设置外部全局 dispatcher |
| Worker 继承专用 preload | 仅安装本 isolate 的普通 fetch，不根据 worker 的 argv[1] 解析 DSH |
| Android，只有旧 `DSH_GO_OHOS_SIM=1` | 门控不启用；原 fetch、外部 Undici 加载状态不变 |

典型仿真启动参数如下。真实 OHOS 不加载 sim；普通 JIT 测试仅加载 sim/marker。没有新增生产环境变量：

```bash
node --jitless --import ./runtime/ohos/sim/preload.mjs \
  --import ./runtime/ohos/net/dsh-preload.mjs \
  /path/to/dsh-prefix/node_modules/@deepseek-ai/dsh/lib/bin.js
```

## 2. 策略关闭后的回调

真正需要修改的是 `ohos-network-transport.diff` 中的 DSH `createPolicyDispatcher` 外层；核心 dispatcher 原来已有关闭分支。本次先在实际 provider 的 legacy/v8 两种 handler 上保留同步抛错的失败断言，再修改该层。

关闭后的 `dispatch` 返回 false，通过 microtask 单次调用 v8 `onResponseError(null, error)` 或 legacy `onError(error)`，code 为 `UND_ERR_CLOSED`。不创建新的按代理分组的工厂或连接。v8 的 null controller 表示请求尚未开始，与锁定 Undici 的 pre-dispatch 错误契约一致；不伪造已经触发 onRequestStart。测试直接经过真实 DSH 代理安装入口，不能只测 core.close 后的行为来替代它。

## 3. 请求头复制与长度检查

此前对象形态的 headers 直接被复用，upgrade 分支给它写 connection/upgrade；可变对象被污染、冻结对象抛错。大小写不同的 Content-Length 也可能绕过实际上传字节数检查。这些都在真实 HTTP/upgrade 夹具中先失败。

现在对每次调用新建无原型记录，按小写归一键名，复制数组值；原普通对象、冻结对象与数组不被改写。普通对象 getter 读取一次。平坦数组必须有偶数个元素；Map、Headers 及具有安全 iterator 的对象采用键值对遍历，避免在修普通对象路径时丢掉原有入口。安全 iterator 的选择参照锁定 Undici `lib/core/request.js:246–265` 和 `lib/core/util.js` 的公开输入行为，不依赖其内部函数。普通响应头重复值与 rawHeaders 仍由既有回调契约保留。

Content-Length 在归一后检查：接受单个非空十进制数字值，以及可精确表示的非负整数；实际上传字节数必须一致。大小写归一后重复的长度、数组长度值、空串、十六进制、科学计数、正号和首尾空白报 `UND_ERR_INVALID_ARG`。已知长度与实际 body 不符报原有 `UND_ERR_REQ_CONTENT_LENGTH_MISMATCH`。新错误信息不包含调用方原头值。锁定原生 Undici `lib/core/request.js:31–43,530–537` 同样拒绝空串、非十进制形式与重复长度；本层额外把超出安全整数的长度明确拒绝，不作不精确字节比较。

此项没有声称覆盖任意恶意对象 getter/Proxy 的运行时副作用，也没有新增 HTTP/2 实现；主要范围是既有 dispatcher 输入与所列可达反例。

## 4. 实际验证与证据层级

原始 `evidence/frozen-before/m3-before.json` 与 `M3-PREP.md` 保存 c0949d6 的三类先失败和显式 custom 恢复正对照，未覆盖改写。新请求头矩阵在冻结 M3-4 上得到 5 PASS、20 FAIL；真实策略关闭矩阵在旧 provider 上 0 PASS、2 FAIL。它们分别保存在 `m3-5-headers-before.log`、`m3-5-closed-before.log`。

| 测量 | 本次结果 | 覆盖与限制 |
| --- | --- | --- |
| 请求头 25 项 + 实际 policy closed 2 项 | JIT 27/27；严格 O0 27/27；0 skip/TODO | frozen/mutable upgrade、混合大小写短/长 body、对象/数组/Map/Headers、getter、非法长度；两种 callback |
| 专用 DSH preload 启动矩阵 | 18/18；0 skip/TODO | JIT/严格各 9 项；真正 argv bin、default/custom 恢复并请求、late 三种载入、Worker、独立工厂、错误入口、Android 旧 env |
| 原有核心 | JIT 与严格各 36 PASS + 5 TODO；0 skip | TODO 仍真实不满足断言，不能算通过 |
| 原有 DSH 集成 | Android 4/4；JIT 13/13；严格 13/13 | DNS pin、双栈回退、代理、TLS、WebSocket、SSE、内置7/外部8、重试/取消 |
| M3-4 代理路由 | JIT 20/20；严格 20/20 | opt-in、loopback、NO_PROXY、显式工厂、连接池回收均无回归 |

启动矩阵的观察器是最后一个 preload，实际请求与 Worker 结束后退出，故它证明入口前置与网络恢复，不声称真实 App 已运行。真实 App 的自动三模式脚本由 M3-6 独立打包与记录；阶段样本已得到 JIT 和 strict sim 五工具、两审批成功，普通 jitless 仍保留 transport BLOCKED。阶段样本不能替代最终冻结哈希的主代理集成复跑，也不能称为鸿蒙目标 ABI/设备通过。

复跑命令中 prefix 必须分别指向原 npm-ci 对照与按 pins 应用该版本网络 diff 的私有验证树。不要修改仍在运行的引擎安装目录：

```bash
export NODE=/path/to/node-v24.22.1/bin/node
export OHOS_TEST_DSH_PREFIX=/path/to/patched-prefix
export OHOS_TEST_BASE_PREFIX=/path/to/original-prefix
export OHOS_SIM_PRELOAD="$PWD/runtime/ohos/sim/preload.mjs"
export DSH_GO_OHOS_SIM_PLATFORM=openharmony
bash runtime/ohos/net/test-dispatcher-errors.sh
"$NODE" --test runtime/tests/ohos/net-bootstrap.test.mjs
bash runtime/ohos/net/test.sh
bash runtime/ohos/net/test-integration.sh
bash runtime/ohos/net/test-proxy-env.sh
```

bootstrap 的父测试进程用普通 Node 派生每种独立场景，子场景才按矩阵选择 JIT 标记或严格 O0；不能对这个父测试进程先加载禁止 child_process 的 O0。普通网络测试使用 `--test-isolation=none` 避免运行器自己派生进程；测试没有因此放宽被测进程约束。
