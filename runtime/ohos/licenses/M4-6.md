# M4-6：固定依赖的通知登记与裁剪实验

## 当前结论

本补丁登记三个根的 91 包非可选闭包和实际使用的 esbuild 构建工具，保留 `re2js: 1.3.3` 的直接声明，收录 111 份许可、归属与原始元数据摘录。v2 补上首版遗漏的 Angular/Google 源内通知，并校准 clean-git-ref 的 Apache 标准条款登记。**发行闭合仍为 BLOCKED**：minimisted 的 MIT 声明已知，但精确对应的完整版权/许可通知证据未齐；just-bash 内嵌 CPython/Emscripten 的实际定制构建通知与来源资料未齐。

首版补丁 `25f200863f5c426fe693301ab401c35612595598e46035767680cb0ee12fb510` 及其独审 BLOCKED 报告保持原样。v2 不改变依赖版本、解析字节、裁剪脚本、实现源码或 Android 路径；只修订登记、校验与明确的回归。

独立 shadow 实验支持把 TypeScript、sql.js、随包 CPython 列为 O2 的裁剪候选：三种状态各 8 项严格仿真测试通过，原依赖的 3,803 个普通文件均在前后核对中保持不变。该实验没有修改产品的打包规则，没有运行最终 HAP，也没有解除 O4b 的硬取消阻断。

clean-git-ref 2.0.1 的 `package.json` 本就声明 Apache-2.0。v2 收录 [Apache 官方标准全文](https://www.apache.org/licenses/LICENSE-2.0.txt)，11,358 bytes、SHA `cfc7749b96f63bd31c3c42b5c471bf756814053e847c10f3eb003417bc523d30`，并原样保留实际 author/license 字段；未从 author 推定版权行或年份。实际发行物仅 README.md、lib/index.js、package.json 三文件，已逐个核摘要、检索并读取现有声明。标准条款与包自带声明在 manifest 中使用不同来源类型。

Apache §4(a) 要求提供许可副本，§4(c) 涉及适用的已有通知；§4(d) 以原作品发行物含有 NOTICE 为条件。不能仅因本包没有 NOTICE 就要求编造一个。因此 v2 解除首版的 clean-git-ref 登记缺项，保留原始没有独立 LICENSE/NOTICE 的事实；这不等于宣称最终制品或一般法律完备性已经通过。

minimisted 同样不应称为“许可未知”：package.json 与 README 的 MIT 声明已知，作者元数据原样保留。当前仍未取得该版本对应的完整版权/许可通知，登记不从作者字段制造一段带猜测年份的 MIT copyright。这里保留的是具体证据缺口，可由精确原文或主线明确的替代依据关闭。

## 独立 shadow 裁剪实验

本节是首版已经执行并保存的 AUTHOR_RUN，v2 复用其冻结证据，**没有重新执行裁剪实验**。本次逐项核对两个 process manifest、裁剪脚本、两个 probe 驱动的摘要均与首版一致；没有把旧测量冒称为新的执行。v2 的新验证限新增许可来源、完整登记字节、原 91 包闭包、六项登记回归及双路线应用。

实验基于已审 M4-1 v2 的 30 文件冻结源码，私有 RE2 产物为 `80eaea2a9e50a2851e332fa4fccffeb01550584ad3c448a2eadd88b43373d5f1`。实际 Node 是 24.22.1，三个工作阶段均使用 `--jitless --import <已审 M3-3 preload>`；报告保存完整 argv 与 preload SHA，不仅凭 WebAssembly 缺失就称为严格仿真。

91 包逐包常规复制，核对原件与副本没有共享普通文件 inode。DSH 服务 API 的 `@deepseek-ai` 名称空间只读指向固定 DSH prefix，明确记录此边界；被裁剪的三处全部位于独立 shadow 内。完成后源目录的全部 3,803 个普通文件重新计算摘要并与实验前比较，一项未变；只回收自己新建的 shadow。

| 状态 | 严格仿真实际测试 | 结果 |
|---|---|---|
| 完整 91 包闭包 | 管道、文件命令、循环、Unicode JSON rg 与正向 glob；python3/sqlite3/node 明确不可用；isomorphic-git 实际 init/currentBranch | 8/8 |
| 移除 TypeScript + sql.js 的 shadow | 同一脚本、同一断言；两个包实际解析为 MODULE_NOT_FOUND | 8/8 |
| 再移除 vendor CPython 的 shadow | 同一脚本、同一断言 | 8/8 |
| 普通 JIT 的原版 ESM just-bash sqlite3 | `sqlite3 :memory: 'select 1;'` | exit 0、stdout `1\n` |
| 同一 ESM 查询，使用已裁剪 shadow | SQLite 已启用的原始功能边界 | exit 1，明确缺 sql.js，作为预期功能损失保留 |

删除清单的普通文件总字节数分别为 TypeScript 23,625,066、sql.js 31,132,473、CPython 三文件 10,386,899，合计 **65,144,438 bytes**。这是未压缩文件体积，不是 HAP 压缩节省、RSS 或安装时延测量。

调查时曾把 CJS 产物里的 `require('sql.js')` 误当成立即执行，所写夹具的预期失败；后续真实对照显示原版与裁剪版 CJS **导入都成功**，引用是惰性执行。另一个 `node -e` / CJS SQLite 对照的原版先受 worker 路径元数据影响而失败，也没有算作正确的裁剪基线。最终表中的正/负对照来自文件形式的真实 ESM 入口，前述失败记录保留在 evidence，不作实现失败或通过计数。

因此可作出的结论是：当前 OHOS 已注册/已禁用功能组合存在裁剪可行性证据。不能由 8 项子集测试推断整个 just-bash、完整 DSH 回合或未来打开的 Python/SQLite/Node 功能都不需要这些包。O2 应另行固定允许的功能、打包排除清单和完整 App/制品测试，当前补丁不提前修改这些规则。

## 新增回归与范围

`runtime/tests/ohos/licenses-registration.py` 使用真实固定依赖检查：domino 的 BSD 与精确 Angular MIT 并存；两处发行通知的原始字节区间；Apache 标准条款及未补造的实际归属；minimisted 的已知声明与剩余缺项；默认验证成功与完整发行门退出 2；删除整个已知 Angular 条目后验证必须拒绝。首版六个用例全部失败（含 subTest 共八条断言失败）；首次失败诊断曾展开大清单，缩短诊断后保留相同断言重跑，两个日志都保存。最终同一脚本在 v2 的六项用例为 6/6，通过且没有 skip；完整发行门仍实际退出 2。

这些检查只修复并约束已证实的遗漏，不能自动发现 91 包中所有未知嵌入内容。最终 HAP、GPL/LGPL 适用发行要求与 CPython 构建来源仍按各自范围待核。没有因测试通过把整体发行状态改为 PASS。

## 重跑

```bash
python3 runtime/tests/ohos/licenses-registration.py \
  --registration-root /absolute/source-root \
  --process-prefix /absolute/process-prefix \
  --esbuild-prefix /absolute/esbuild-tools
```

安装仍按 process 的固定 lock 执行。以下路径参数指向本机实际的只读依赖与既有构建工具，不需要重复安装新版本：

```bash
python3 runtime/ohos/licenses/verify.py \
  --process-prefix /absolute/process-prefix \
  --esbuild-prefix /absolute/esbuild-tools
```
