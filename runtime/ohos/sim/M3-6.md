# M3-6：自动网络预加载与加载器测量记录

本文件描述测量工具，不是产品启动器，也不批准把模拟预加载放进 HAP。

`measure.sh` 在 sim 模式自动加入 `net/dsh-preload.mjs`，顺序为完整 O0
预加载、测量观察器、DSH 专用网络预加载、真实 DSH 入口。前者设置当前 isolate
的显式标记并施加原有限制；DSH 专用入口在主线程处理固定 Undici 的安全默认分发器，
Worker 则只安装通用 fetch，不把 Worker 脚本当成 DSH bin。
jit 与普通 jitless 对照不自动启用 OH 网络实现。

## 参数与复现

使用已准备的、精确打过补丁的 DSH prefix，并保持固定 Node 24.22.1：

```sh
NODE=/absolute/node24.22.1/bin/node \
DSH_OHOS_PREFIX=/absolute/dsh-prefix \
bash runtime/ohos/sim/measure.sh /absolute/new-output \
  --sim-patch /absolute/mobile-profile.patch.yml \
  --allow-addon /absolute/optional-package/prebuilt/require_builtin.node
```

输出目录必须不存在。`--patch` 继续适用于所有三种模式；`--sim-patch` 只对 sim
追加平台专用 profile，避免把仅能在 OH/SIM 启用的服务加入普通 JIT 对照。
两个参数均可重复。测试模型 overlay 最后叠加，五个工具、实际文件内容、审批、
真实 HTTP/WS 与 turn/end 的原验收条件保持不变。

`--allow-addon` 只为严格 sim 的 addon 白名单提供入口。每个参数必须是绝对路径，
解析后为存在的普通 `.node` 文件；在建立输出目录、模型服务或引擎之前核验。
白名单按规范路径去重，报告记录读取时的 SHA256。严格模式设置
`NARB_DISABLE_NATIVE_CACHE=1`，防止原 loader 将二进制复制到未获准的临时路径。
不传参数时继续默认拒绝全部 addon。JIT 两个对照仍按原平台加载；报告明确标记白名单
是否实际施加，不能把所给路径清单当成已经加载的证明。

Linux 测量中的 `openharmony-x64` optional package 只能是明确的测试 fixture。
其中使用的 Linux ELF 即使成功，也不是 OHOS ELF、ARM64 ABI 或 HAP 的验证。
不要把这个 fixture 放进目标安装包。

## 报告如何确定加载器

每个 `report.json` 的 `loader` 分别记录启动配置和实际观测。
测量专用 `observe-loader.mjs` 包装的是已存在的 `process.dlopen`，先调用它，只有原调用
成功返回后才记录真实路径和字节 SHA256。完整 O0 的拒绝包装仍在调用链内。
观察器不主动 require addon，不调用 requireBuiltin，不建立另一套加载器。
这个摘要对应成功加载后从磁盘路径读到的文件，不是进程内存映像的摘要；它不证明
能够抵御加载后另一写入者替换或改写文件。正式测量须固定输入，并核对前后文件哈希。

成功加载的实际 native exports 若提供 `getNativeBindingInfo`，观察器读取其 product、
backend、ABI 和 mode。固定上游提交的此函数只创建四字段对象；它不调用加载或探测逻辑。
数据只用于测量，不能据此证明目标平台符号归属或 ABI。

- 实际观察到 require-builtin N-API 二进制且未传 expose 参数：`native-addon`。
- 观察到二进制但同时传了 expose 参数：`native-addon-with-exposed-internals`。
- 只传 expose 参数而未观察到该二进制：
  `expose-internals-configured-native-not-observed`；这只是配置事实，不能伪称观察到 fallback 的执行。
- 没有实际记录：`not-observed`，包括白名单拒绝、提前启动失败等情况。

`observer-ready` 记录子进程当时的平台与 WebAssembly 是否存在；父进程真实平台和架构
单列在 `loader.host`。Worker 不重复安装该观察器。它只在测量器显式设置的 opt-in 下工作，
不能作为抵御不受信任代码伪造日志的安全机制。观察器读取文件并计算 hash 有开销，
新旧不同仪器配置的耗时不能直接归因于性能改进。

普通 jitless 对照仍可能在上游原网络/Wasm 路径失败；sim 自动预加载修复不把这个失败改成
PASS。`measure.sh` 只要任何一组失败就保持非零退出，并保留每组自己的完整报告。

## 回归要求

```sh
DSH_TEST_PREFIX=/absolute/locked-prefix "$NODE" --test --test-isolation=none \
  runtime/tests/ohos/measurement-loader.test.mjs
```

四项测试覆盖无 opt-in 时不改写 dlopen、真正允许的 native 字节与原 O0 spawn 限制、
真正拒绝的 `.node` 加载与原错误码、以及四种非法路径在启动前失败。
完整 App 和自动三模式测量还须保留真实正反报告；单元测试不能代替它们。
每次改变测量入口后都要使用新输出目录，不修改原始失败记录。
