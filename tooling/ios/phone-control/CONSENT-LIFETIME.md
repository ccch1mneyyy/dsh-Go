# 手机任务资格与闲置连接的生命周期

此变更对应 ios5 `ADDENDUM-07` §3.10 的“30 分钟资格过期或被拒后，拆掉闲置的 CoreDevice 会话”。它只修改原生资格和调用者的清理时序；资格仍绑定准确的 `(runID, sessionID)`，每个实际调用仍需单独确认。

## 过期时主动清理

`IOSPhoneTaskConsent` 在用户真正批准任务资格后启动一个检查任务。任务每次等待约一秒，再检查既有 `IOSPhoneContinuousTime.now` 的连续时间样本；同一检查也由 `remainingSeconds`、`isGranted` 和调用准入同步执行。达到原始截止时间、无法读取时钟、非有限值、负值或时间相对上次已接受样本倒退，都会永久结束这一次资格；之后恢复的时钟样本不能复活它。

结束资格会先取消检查任务、轮换资格代次并清除持有者，然后同步通知 `IOSPhoneRunner`。Runner 只有在当前任务仍为同一个 run/session 时才清除观察、路由和连接。取消的旧检查任务还要通过自己的 UUID 门，不能在新资格建立后关闭新连接。显式结束任务直接取消检查任务，不另外发送“过期”事件。

这里没有精确的后台定时保证。连续时间来源包含设备睡眠，但等待任务只有在 App 和 MainActor 得到调度时才运行；App 被挂起或主线程阻塞时，清理可能延后。重新调度后的检查及每次实际准入仍核对截止时间，不因定时器迟到而延长资格。检查任务不为整个 30 分钟保留某次请求、参数或 UI presenter 闭包。

新发起的明确请求可以在旧资格清除后重新展示两层确认。反过来，如果某个已经开始的请求在资格复用检查中触发过期，它会先重新核对自己的代次并退出，不能继续替已失效的调用弹出新的任务授权。已经显示的旧逐次确认即使收到迟到的“允许”，也不能取得执行资格。

## 单次拒绝只清理本次连接

以下失败出口关闭当前调用拥有的连接，并作废其 CoreDevice/XCTest 屏幕观察：前台或遗留剪贴板恢复未通过、逐次确认未通过、桥接 begin 授权未通过，以及进入有效非 ASCII 输入流程后的第二次剪贴板确认未通过。错误回复、用户确认层级和已派发动作的结果语义沿用现有实现。

尚未过期的 30 分钟资格保留原截止时间；拒绝一次动作不等于撤销整个任务，也不会重新计时。再次操作需要新的逐次确认；旧屏幕已作废，需要屏幕观察的后续动作须先重新 `screen`。过期、明确停止、暂停或原有其他撤销路径仍按其各自规则撤销任务资格。

Runner 每次调用生成独立 invocation UUID。拒绝清理必须同时匹配捕获的 native owner ID 和 invocation UUID；先轮换本地身份，再向后端发送准确 owner 的 stop。旧请求的迟到拒绝不能关闭同一会话里后来的调用，也不能关闭另一个 run/session。设置页预检使用不同 owner；这里没有使用无 owner 限定的 stop。

非 ASCII 第二次确认在首次有效准入后、任何 UI 等待前，快照当时的清理闭包。即使后来的调用替换了已安装的闭包，旧确认也只能调用原闭包。初始已失效、其他 owner 或非文本请求不会取得当前调用的清理钩子。这个钩子不持有请求正文、不撤销任务资格，也不触碰剪贴板。第二次确认前已派发的焦点点击不能撤回；原有剪贴板准备流程只有确认返回 true 后才进入写入阶段。

## 资源和可证明范围

清理请求使用原有 `IOSPhoneCoreDevice.stop(ownerID:)` 和 `IOSPhoneSelfRunner.stop(ownerID:)`。后端自己的停止确认、超时 faulted 屏障和资源终态仍有效；本变更没有把 stop 请求当成已经退出，也没有允许在未知终态后切换或重放。

外部 Mac 启动的 XCTest helper 不属于本地 native owner。清理会丢弃其 endpoint 和观察，不能据此声称已终止外部进程。已经到达设备或 XCTest 的同步动作也不能保证被撤回；仍可能需要用户核对实际结果。

## 验证

`IOSPhoneTaskConsentTests` 的资格和确认用例直接使用生产 `Runner.IOSPhoneTaskConsent`、真实确认控制器和测试宿主窗口；原有目标切换等待用例直接调用生产 `IOSPhoneTargetWait`。合成部分是时钟、按钮点击和记录返回值的调用者，不执行真实手机动作。现有测试类已经在 `ios-compile.yml` 的 `-only-testing:RunnerTests/IOSPhoneTaskConsentTests` 中，无新增项目或 CI 接线。

该类由 23 项扩为 35 项：保留既有目标切换等待及剪贴板确认测试，更新旧时钟测试以检查“过期不可复活”，新增 12 项涵盖无后续请求时的过期通知、取消和换代、可见确认的迟到答案、拒绝不续期，以及二次确认清理闭包的捕获边界。其中一项在真实准入路径中推进合成时钟，检查发现过期后没有第三次弹窗。

本次 Linux 环境没有 Swift 编译器、Apple SDK、Xcode 或模拟器，以上 35 项全部为 **authored / UNRUN**。Linux 的补丁应用、源文件身份、保护方法逐字一致及项目选择器检查不替代 Swift 编译和 UIKit 执行。测试记录的闭包不是 native owner 替身；准确 owner/nonce 到后端 stop 的接线目前依据生产源码审计，仍需要 Apple 运行验证。

Apple 后续需要验证：资格自然到期时闲置连接进入停止流程；一次拒绝后新 screen 仍只要求逐次确认且不续期；非 ASCII 二次拒绝不会写剪贴板；旧调用迟到时不会停止新调用或设置页预检；App 睡眠后恢复不会沿用过期资格。真实设备停止时长、后台调度和 30 分钟运行均未在本环境测量。
