# 鸿蒙本机模式验收摘要

本文记录 2026-11-01 已实际完成的限定验收，不表示安卓版所有功能一致。设备范围为 MatePad、HarmonyOS API 26；构建编号用于区分测试版本，不是公开发行号。隔离模型夹具使用全新测试目录、固定非私密文字和空凭据。用户另行授权后，正常包 127 通过原凭据服务使用已保存 API Key 完成一次真实 DeepSeek 请求；诊断工具未读取、显示或导出 Key。

## 已完成的真实验证

| 范围 | 实际结果 | 边界 |
| --- | --- | --- |
| Node 与网络 | 同源 Node 24.2.0 以 `--jitless --wasm-jitless` 执行固定 Wasm 返回 42；原 `globalThis.fetch` 回环请求、基础文件/加密/随机数/HTTP/进程标题及正常退出通过 | 未用替代 fetch；不据回环结果推定外部供应商或所有 HTTPS 场景通过 |
| 原版页面与本机服务 | 认证、会话列表、事件通道、创建/改名、停止再启及冷启动读回通过 | 这些操作没有提交真实模型聊天请求 |
| 隔离一次性 PTC | 独立 UID、父私有路径拒绝、只读固定脚本 FD、原双向协议、并发、提前 EOF、取消与退出回收通过 | 实际 cwd 为 `/`；不授予父工作区原路径访问，不支持持久 PTC |
| 生产任务 broker | 两并发任务各自 70000 字节 stdout、20000 字节 stderr、工具绑定返回 42，以及取消、exit 7、未捕获异常和拒绝的退出行为通过 | 输出流按额度读取；官方退出回调、四流 EOF、释放分别确认，不把子进程状态内容当不可伪造凭据 |
| 原标准文件工具（118） | 原 `ctx.agents.create` 挂载标准预设，原 `ctx.tools.execute`/`run_code` 经绑定完成两工作区写读；只读、越界、跨工作区及运行中撤权检查通过，句柄释放、模型尝试为 0 | 文件权限由宿主原工具策略执行，不把隐藏不可用工具等同功能实现 |
| 无 Key 对话（119） | 标准能力枚举、真实工具检查后，独立 fixture 模型经一次回环 HTTP 请求、3 个流式帧进入原 agent loop；用户/助理事件与持久化通过 | 注册了明确测试适配器，未伪造最终 UI 消息，但未覆盖原 UI/RPC 模型对话全链路 |
| 对话冷读（119b） | 完全停止后启动新进程，使用同一 fresh 测试目录，确认进程不同并读回同一用户与助理消息 | 真实重启，不以同进程缓存或旧终态报告代替读回 |

会话与文件的新目标发布使用已真机验证的 `renameat2(RENAME_NOREPLACE)`：新建成功，已有目标冲突不覆盖、源状态正确，并发仅一个赢家。没有扩大原 EACCES 降级条件，也没有使用先检查存在再普通 rename。

## 重放材料与正常包边界

[设备验收夹具](../tests/runtime-lifecycle/device-fixtures/README.md)保留上述工具、能力枚举、对话及冷读脚本和独立测试 ZIP 注入步骤。生产包不包含这些脚本，不注册 fixture 模型，不接受测试环境分支；临时导出 Ability 和 Runner 已移入测试夹具。测试包仅覆盖安装，之后恢复正常包，不卸载或清除用户数据。

[清洁资产导出](../tooling/prepare-dsh-assets/README.md)已从固定官方 APK 实际重放 14576 个原普通文件和 12 个命令目标映射，逐文件核对来源。映射不执行命令；原 Linux 原生文件不等于可加载的鸿蒙库。[原生库构建](../tooling/NATIVE-RUNTIME-BUILD.md)与[Node 来源重放](../tooling/node-runtime/drumbrake-compressed/README.md)分别记录来源、ABI、摘要和许可证；本轮没有重新完整运行干净 Node 长编译。

清洁资产构建 120 的 ZIP 共 14587 个文件，SHA-256 为 `431e92e59844adc3cbfe9e003762afd949d2c7c79848671ff885a478ba86cc31`。使用该资产的正常构建 121 首次启动已实际通过认证、4 个会话的列表检查、ready、标题持久化和固定文本附件上传。正常 HAP 不包含测试 Ability，17 个诊断库已移除；这些结果独立于 119 测试包。

正常停止时曾发现白屏：122 仅处理 `onNewWant` 后仍失败，未记为通过。123 结合窗口就绪状态与 `onForeground` 回跳后，在原引擎页停止确认旧进程已退出、页面显示“已停止”；再启动时页面可见、新进程与旧进程不同，认证、列表和标题检查通过。

123 与 127 均已执行 force-stop 并确认应用全部进程为 0，随后冷启动的认证、会话列表、事件通道与固定标题读回通过。正常包还完成固定文本附件上传。

## 正常包真实供应商验收（127）

恢复原 `settings-controller` 后，Flutter 可经其注册的原 `credentials/set` 同步已保存 Key；诊断仅检查 configured/writable 状态，不读取 Key。原 `session/modelCatalog` 返回 `deepseek-official` 组与 `deepseek-flash`。

全新固定测试会话通过原 `session/create/selectModel/prompt/page` 和 mux `session/follow` 完成一次真实请求，要求只回复 `HARMONY_LOCAL_ENGINE_OK`、不调用工具。实际收到 15 个助理流帧，用户/助理事件、连续序号、turn/end、回复文本及历史均通过，测试后恢复原模型选择。再次完全停止并冷启动后从磁盘读回两条消息，原 Flutter 页面也实际显示固定用户提示及助理回复；冷读没有再次调用模型。此结果仅覆盖 API Key 路由，不证明账号路由。

独立无 Key 网络验收已通过 DNS lookup/resolve4、严格 TLS 的 HTTPS HEAD 和原 global fetch HEAD（官方入口返回 401）。另已修正 fs.watch 覆盖后的 ESM 内建导出同步及异步迭代契约；先失败后通过的三项回归不构成原目录超时根因证明。

## 原账号登录验收（128–130）

仅恢复原 `account-controller`，沿用 Flutter 账号页、系统浏览器、Host PKCE/state 和原 loopback 回调，没有新建密码输入框或令牌 RPC。89 项 Flutter 账号与身份隔离测试，以及真实 Gateway/Controller 的无凭据 mock 回归通过。

首轮出现 `failed/protocol`，浏览器前台时本机 RPC 也曾超时，回前台后恢复；未将其归因为已确认的服务端或后台策略缺陷。随后原页面重新登录、用户在官方浏览器操作并返回应用，Host 实际报告 `succeeded` 与 `credential-stored`，原页面出现退出登录入口，个人资料与余额查询均 ready，`deepseek-account` 模型目录非空。浏览器曾显示失败页的原因未单独证实，以 Host 成功提交及平台查询为实际结果。

移除临时诊断后，正常包 130 覆盖安装，完全停止并确认旧应用进程为 0，冷启动仍为 `credential-stored`（attempt 已清空），资料、余额及账号模型目录再次通过。仅检查状态和接口可用性，不读取或导出身份、密码、验证码或账号 token，也没有主动注销。API Key 测试会话的用户和助理消息仍可读回。没有发送账号模型生成请求，不把 API Key 的回复记为账号推理成功；后台常驻及超长网页登录仍未覆盖。

正常包 130 的资产 ZIP SHA-256：`30b6b68af566716936a98e2616820c6fb4827351888fee0b3b8679d86075ab1f`；临时账号诊断 hook 不存在。

## 明确未覆盖或不支持

- 真实供应商验收仅覆盖上述 DeepSeek API Key 单次短回复；账号登录及状态保持已按上文独立通过，账号模型生成仍未验证。
- 不支持一般 shell、终端、任意外部命令、任意缓存 `.node` 扩展、持久 PTC，或隔离任务直接切换到宿主工作区路径。
- 重置（reset）、安全/自动安全模式和 LKG 恢复未支持；相关变更操作明确返回不支持，不伪报清理或恢复成功，不删除用户数据。
- 未完成后台常驻/系统回收行为与安卓版一致性，以及其他设备或更低 API 的验证。
- 语音、手机操控及所有网页能力仍有独立验收缺口；附件选择回传通过不表示已向模型发送附件。
- 空凭据夹具与用户授权的真实 API 请求分别记录；文档与报告不包含凭据、认证地址、设备标识或本机绝对路径。
